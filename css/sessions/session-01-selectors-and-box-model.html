box-sizing — CRITICAL! By default, padding and border are added ON TOP of the width. border-box fixes this so the size you set is the total size.
/* Default (content-box): width 200px + padding 20px + border 5px = 250px actual */

That's why every CSS file starts with * { box-sizing: border-box; } — it fixes this globally for every element.

4 Display Property

display: block — each element takes up the full width of its container and starts on a new line, even if the content is tiny.
div { display: block; } /* default for div, p, h1, h2, header, section... */
3 divs — each gets its own full-width row
Block One — full width
Block Two — full width
Block Three — full width
display: inline — elements sit side by side on the same line like words in a sentence. Width and height are ignored. (span, a, strong are inline by default)
span { display: inline; } /* default */
span { width: 200px; }    /* IGNORED! inline elements ignore width/height */
span { margin-top: 50px;} /* IGNORED! top/bottom margin ignored too */

★ Bonus: Debug 5 CSS Bugs

Each example below is broken. Can you spot the bug before revealing the fix?

🐛 Bug 1 — Link won't accept padding-top

This button link is supposed to have equal padding on all sides but the top and bottom padding do nothing:

a.nav-btn {
  padding: 12px 20px;  /* top/bottom seems ignored! */
  background: #1d4ed8;
  color: white;
}
BROKEN — flat button:
Nav Button
→
FIXED — proper padding:
Nav Button
Root cause: <a> is inline by default. Inline elements ignore top/bottom padding (visually) and ignore height entirely.

Fix:
a.nav-btn { display: inline-block; }

Now it behaves like a block for sizing but stays inline-like for flow.
🐛 Bug 2 — Box is wider than expected

This sidebar should be exactly 250px wide, but it keeps overflowing its container:

.sidebar {
  width: 250px;
  padding: 20px;
  border: 3px solid #334155;
  /* actual width = 250 + 40 + 6 = 296px — oops! */
}
BROKEN — actually 296px wide:
Sidebar content here
← this div is actually 296px
Root cause: Without box-sizing: border-box, CSS adds padding and border ON TOP of the width you set.

Fix:
.sidebar { box-sizing: border-box; }

Now the 250px includes everything — content area shrinks to fit padding and border inside. Better still, put * { box-sizing: border-box } at the top of every CSS file.
🐛 Bug 3 — Class style being overridden unexpectedly

The .price class says green, but the text keeps showing red:

#product-section .price { color: #f85149; }  /* score: 100+10 = 110 */
.price                  { color: #10b981; }  /* score: 10 — LOSES */
$49.99
← should be green, but ID wins!
Root cause: The ID selector (#product-section) gives the rule a score of 100+10 = 110, which crushes the plain class score of 10.

Fix options:
1. Make the class rule more specific: #product-section .price { color: #10b981; }
2. Remove the ID from the conflicting rule
3. (Last resort) Use !important — but avoid this if possible

Golden rule: Avoid styling with IDs in CSS — use classes instead to keep specificity manageable.
🐛 Bug 4 — Unexpected gap between stacked elements

The gap between these two sections is 40px, but the designer set 20px on each. Why?

.section-a { margin-bottom: 20px; }
.section-b { margin-top:    20px; }
/* expected gap: 40px — actual gap: 20px! */
Section A — margin-bottom: 20px
Section B — margin-top: 20px
↑ gap = 20px (not 40px) — margins collapsed!
Root cause: Margin collapse — when two vertical margins meet, they merge into the larger value (not added together). 20px + 20px = 20px, not 40px.

Fix options:
1. Use only one of the two margins (e.g., only margin-bottom)
2. Add padding-top: 1px to the second element (breaks collapse)
3. Wrap in a flex/grid container (collapse doesn't happen there)

Best practice: Only set margin in one direction (e.g., always margin-bottom, never both) to avoid surprises.
🐛 Bug 5 — Block element won't center horizontally

This modal box should be centered on the page but it's stuck to the left:

.modal {
  margin: 0 auto;     /* centering attempt — doesn't work! */
  background: #1e2d4a;
  padding: 30px;
  border-radius: 12px;
}
I want to be centered! 😢
← stuck to left — margin:auto needs a width!
Root cause: margin: 0 auto only centers a block element when it has a fixed width. Without a width, a block element already takes the full width — there's nothing to center.

Fix:
.modal { width: 400px; margin: 0 auto; }
— or for responsive layouts —
.modal { max-width: 400px; width: 100%; margin: 0 auto; }

Now the browser knows: "total width is 400px, put the remaining space equally on both sides."
Now I'm centered! ✦

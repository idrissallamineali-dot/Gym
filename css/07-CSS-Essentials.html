CSS Essentials: How CSS Really Works

Go slow. This is the foundation everything else is built on. If you understand this tutorial, everything else becomes easy. We're not rushing anymore — every concept gets the full explanation it deserves.

0 What is CSS? (The Big Picture)

Before we write a single line of CSS, let's understand what CSS actually is and why it exists.

HTML is the Skeleton. CSS is the Clothing.

Think about a mannequin in a store window. The mannequin itself is HTML — it provides the structure, the shape, the bones. But nobody wants to look at a bare mannequin. CSS is the clothing, makeup, accessories, and styling that makes that mannequin look good.

Without CSS: With CSS: ┌──────────────────┐ ┌──────────────────────────────┐ │ My Website │ │ 🎨 My Website │ │ │ │ ════════════════════ │ │ Welcome │ │ Welcome │ │ │ │ │ │ Some text here │ │ Some beautifully styled │ │ │ │ text with colors, fonts, │ │ Click here │ │ spacing, and layouts. │ │ │ │ │ │ │ │ [ Click Here → ] │ └──────────────────┘ └──────────────────────────────┘ Plain. Boring. Ugly. Colorful. Styled. Professional!

Without CSS, every website in the world looks the same — black text on a white background, in Times New Roman, with links in blue. That's it. CSS is what transforms that into the beautiful, colorful, well-organized pages you see everywhere.

CSS is a Set of Rules

CSS works by writing rules. Each rule says: "Find THIS element on the page → make it LOOK like THIS."

A CSS rule has exactly 3 parts:

selector ─── property ── value │ │ │ ▼ ▼ ▼ h1 { color : red ; } ▲ ▲ │ │ opening semicolon brace (end of line)

Let's break this down in plain English:

  • 🎯 Selector (h1) = WHO are we styling? → "Find all h1 elements"
  • 🔧 Property (color) = WHAT about it are we changing? → "I want to change the text color"
  • 🎨 Value (red) = HOW should it look? → "Make it red"

You can have multiple properties inside one rule:

h1 {
    color: red;         /* text color */
    font-size: 32px;   /* how big */
    text-align: center; /* centered */
}
🧠 Think of it like giving instructions to a house painter:

"Go to the living room (selector) → paint the walls (property) → sky blue (value)."
"Go to the kitchen (selector) → change the floor (property) → to tile (value)."

Each CSS rule is one instruction. You can give as many as you want!

3 Ways to Write CSS (and Which One is Best)

Method 1: Inline Styles (❌ Avoid)

Write CSS directly on the HTML element using the style attribute:

<h1 style="color: red; font-size: 32px;">Hello</h1>
▶ Live Result — Inline Style

Hello

❌ Why inline is BAD: Imagine styling 50 paragraphs one by one. If you want to change the color later, you'd have to edit ALL 50. It's like writing the recipe on every single plate instead of in a cookbook.

Method 2: Internal <style> Tag (🟡 OK for Learning)

Write CSS inside a <style> tag in the <head> of your HTML:

<head>
    <style>
        h1 {
            color: red;
            font-size: 32px;
        }
    </style>
</head>
💡 This is what we're using in these tutorials! It's perfectly fine for learning and for single-page demos. The CSS applies to the whole page, so you write it once and it works everywhere.

Method 3: External CSS File (✅ The Best Way)

Write CSS in a separate .css file and link it to your HTML:

<!-- In your HTML file -->
<head>
    <link rel="stylesheet" href="styles.css">
</head>
/* In styles.css */
h1 {
    color: red;
    font-size: 32px;
}
✅ Why external is BEST:
• Separation of concerns — HTML handles structure, CSS handles looks. They stay in their own lanes.
• Reusability — One CSS file can be linked to 100 HTML pages. Change the file once → all 100 pages update.
• Caching — The browser downloads the CSS file once, then reuses it on every page. Faster loading!
• This is how real projects work. Your LUGX Gaming site uses Test1.css — that's an external file.

1 CSS Selectors — How CSS Finds Elements

The selector is the first part of every CSS rule. It tells the browser which elements to style. There are many types of selectors, and understanding them is the key to writing CSS that does exactly what you want.

1.1 Element Selector

The simplest selector — just type the name of the HTML tag. It targets ALL elements of that type on the page.

p {
    color: blue;
}

This says: "Find every <p> on the page → make its text blue."

▶ Live Result — Element Selector targets ALL paragraphs

First paragraph — I'm blue!

Second paragraph — I'm also blue!

Third paragraph — Me too! ALL paragraphs are blue.

💡 The problem: What if you only want the second paragraph to be blue, and the others to stay normal? The element selector can't do that — it's all or nothing. That's where class selectors come in.

1.2 Class Selector

A class selector targets elements that have a specific class attribute. You write it with a dot (.) followed by the class name.

<!-- HTML: add class="highlight" to the element you want -->
<p>Normal paragraph</p>
<p class="highlight">I'm special!</p>
<p>Normal paragraph</p>
/* CSS: dot + class name */
.highlight {
    color: red;
    font-weight: bold;
}
▶ Live Result — Only the element with class="highlight" changes

Normal paragraph

I'm special! (I have class="highlight")

Normal paragraph

Key facts about classes:

  • ✅ You can put the same class on MULTIPLE elements — that's the whole point. Reusability!
  • ✅ An element can have MULTIPLE classes separated by spaces: class="card large featured"
  • ✅ Classes are the #1 tool you'll use in CSS. About 90% of your selectors will be class selectors.
<!-- Multiple classes on one element -->
<div class="card large featured">
    This div has THREE classes: card, large, and featured.
</div>
🧠 Analogy: Think of classes like stickers you can put on anything. You can put a "VIP" sticker on any person, and every person with a "VIP" sticker gets special treatment. You can also put multiple stickers on the same person: "VIP" + "Gold Member" + "Early Access".

1.3 ID Selector

An ID selector targets the ONE element that has a specific id attribute. You write it with a hash (#) followed by the ID name.

<!-- HTML: only ONE element can have this ID -->
<h1 id="logo">LUGX Gaming</h1>
/* CSS: hash + id name */
#logo {
    font-size: 28px;
    color: gold;
}
▶ Live Result — ID targets one specific element
LUGX Gaming
❌ Why classes are usually better than IDs:
• IDs can only be used once per page — zero reusability.
• IDs have very high specificity (we'll learn about this in Section 2), which makes them hard to override later.
• Use IDs for JavaScript targeting or for page anchors (scroll-to links). Use classes for CSS styling.

1.4 Descendant Selector

A descendant selector targets elements that are inside another element. You write two selectors separated by a space.

.navbar a {
    color: white;
    text-decoration: none;
}

This says: "Find all <a> elements that are anywhere inside an element with class navbar."

🧠 This is exactly how you styled your nav links! When you wrote .nav-links a { color: white; }, you were using a descendant selector. Now you know why it works — it finds every <a> that lives inside .nav-links, at ANY depth.
▶ Live Result — Descendant selector: only links INSIDE .navbar are white

1.5 Direct Child Selector

The child selector uses > and targets only direct children, NOT grandchildren or deeper.

.navbar > a {
    color: white;
}

This says: "Find <a> elements that are direct children of .navbar — NOT ones nested deeper inside."

1.6 Grouping Selector

If you want to apply the same styles to multiple selectors, separate them with commas:

h1, h2, h3 {
    font-family: 'Inter', sans-serif;
    color: white;
}

This saves you from writing the same CSS three separate times. Without grouping, you'd write:

❌ Without grouping — repetitive and hard to maintain: 
h1 { font-family: 'Inter'; color: white; }
h2 { font-family: 'Inter'; color: white; }
h3 { font-family: 'Inter'; color: white; }
✅ With grouping — clean and DRY (Don't Repeat Yourself): 
h1, h2, h3 { font-family: 'Inter'; color: white; }

1.7 Combined / Chained Selectors

You can chain selectors together without any space to say "the element must match ALL of these":

/* Element that is an <a> AND has class .cta-btn */
a.cta-btn {
    background: gold;
}

/* A <div> with BOTH .card AND .featured classes */
div.card.featured {
    border: 2px solid gold;
}
🧠 Key rule to remember:
• No space between selectors = AND logic (must match both on the SAME element)
• Space between selectors = descendant (second one is INSIDE the first one)

div.card = "a div that has class card" (one element)
div .card = "an element with class card that's inside a div" (two elements)

2 Specificity — When Rules Fight, Who Wins?

What happens when two CSS rules target the same element but give it different styles? The browser needs a tiebreaker. That tiebreaker is called specificity.

/* Rule 1 */
a {
    color: blue;
}

/* Rule 2 */
.nav-links a {
    color: white;
}

/* CONFLICT! An <a> inside .nav-links matches BOTH rules. */
/* Which color wins? Blue or White? */

The Scoring System

Every selector gets a specificity score. Think of it like a points game:

Selector Type Points Example
Inline styles 1000 style="color:red"
ID (#) 100 #logo
Class (.), pseudo-class (:hover) 10 .highlight, :hover
Element (tag name) 1 p, h1, a, div

Now let's score some real selectors:

Selector Score Breakdown Total ───────────────────────── ───────────────── ───── a 1 element = 1 .nav-links a 1 class + 1 element = 11 #logo 1 ID = 100 .nav-links a:hover 1 class + 1 element = 21 + 1 pseudo-class div.card.featured 1 element + 2 classes = 21
✅ Back to our conflict:
a { color: blue; } → score = 1
.nav-links a { color: white; } → score = 11

11 > 1, so white wins! The link inside .nav-links will be white.
▶ Live Result — Specificity in action

A regular link (matched by a { color: blue } only):

I'm blue (specificity: 1)

Link inside .nav-links (matched by BOTH rules):

I'm white! (specificity: 11 wins over 1)
🧠 THIS is why your LUGX nav works! In your Test1.css, .nav-links a:hover (score: 21) overrides a plain a:hover (score: 11). The more specific selector always wins.

The Tiebreaker: The Cascade

When two selectors have equal specificity, the rule that comes LAST in the file wins:

p { color: blue; }    /* specificity: 1 */
p { color: red; }     /* specificity: 1 — SAME, but last wins */

/* Result: paragraphs are RED */
💡 This is the "Cascade" in "Cascading Style Sheets." Styles cascade down like a waterfall — later ones overwrite earlier ones (when specificity is the same).

!important — The Nuclear Option ☢️

p {
    color: red !important;  /* I WIN. ALWAYS. */
}
❌ Avoid !important like the plague. It breaks the specificity system entirely. It's like flipping the chess board because you're losing. It makes your CSS impossible to maintain because you can only override !important with another !important, and soon your whole codebase is a war of !importants. Only use it as a last resort (almost never).

3 Inheritance — Properties That Pass Down

Some CSS properties automatically pass from parent elements to their children. This is called inheritance.

Think of it like genetics: your eye color passes down from your parents. But your tattoo doesn't — that's yours only.

Properties That DO Inherit

These are typically text-related properties. If you set them on a parent, all children inside automatically get the same value:

body {
    color: white;          /* ✅ ALL text on page becomes white */
    font-family: 'Inter';  /* ✅ ALL text uses Inter font */
    font-size: 16px;       /* ✅ ALL text starts at 16px */
    line-height: 1.8;      /* ✅ ALL text gets 1.8 line spacing */
}

Full list of commonly inherited properties: color, font-family, font-size, font-weight, font-style, line-height, text-align, letter-spacing, word-spacing, cursor, visibility, list-style

Properties That DON'T Inherit

These are typically layout and box-related properties. Children do NOT get them automatically:

padding, margin, border, background, width, height, display, position, top/right/bottom/left, overflow

▶ Live Result — Inheritance: color inherits, border does NOT

Parent div: color=#10b981, border=3px solid red

Child paragraph: I inherited the green color! ✅

But I did NOT inherit the red border. ❌ (I have no border)

🧠 Why this makes sense: Imagine if border inherited. You set a border on <body> and suddenly EVERY element on the page — every paragraph, every heading, every span — has a border. That would be chaos! Text properties inherit because it's convenient (set the font once on body). Layout properties don't because it would be destructive.

The <input> and <button> Exception

Here's a gotcha: <input> and <button> elements have browser default styles that override inheritance. Even if you set font-family: 'Inter' on body, inputs and buttons will still use their ugly default font.

/* The fix: explicitly tell them to inherit */
input, button, textarea, select {
    font-family: inherit;  /* "Use whatever your parent has" */
}
💡 The inherit keyword forces any property to inherit from its parent, even properties that don't normally inherit. You can write border: inherit; to force a child to copy its parent's border.

4 The Box Model — Every Element is a Box

This is the MOST IMPORTANT concept in CSS. Once you understand this, 80% of CSS layout problems become obvious.

Here's the secret: every single HTML element is a rectangular box. Even if it looks round, even if it has rounded corners — underneath, it's a box. And every box has 4 layers:

4.1 The 4 Layers

┌───────────────────────── MARGIN (invisible space outside) ─────────────────────────┐ │ │ │ ┌─────────────────────── BORDER (the visible edge) ───────────────────────────┐ │ │ │ │ │ │ │ ┌───────────────── PADDING (space inside, around content) ─────────────┐ │ │ │ │ │ │ │ │ │ │ │ ┌─────────────────────┐ │ │ │ │ │ │ │ CONTENT │ │ │ │ │ │ │ │ (your text, img) │ │ │ │ │ │ │ └─────────────────────┘ │ │ │ │ │ │ │ │ │ │ │ └──────────────────────────────────────────────────────────────────────┘ │ │ │ │ │ │ │ └─────────────────────────────────────────────────────────────────────────────┘ │ │ │ └────────────────────────────────────────────────────────────────────────────────────┘

From inside to outside:

  1. Content — The actual text, image, or nested elements inside.
  2. Padding — Space INSIDE the box, between the content and the border. Like the foam inside a shipping box.
  3. Border — The visible edge of the box. The cardboard of the shipping box.
  4. Margin — Space OUTSIDE the box, between this box and other boxes. Like personal space between people.

4.2 Padding

Padding = space INSIDE the box, between the content and the border. It makes the box visually bigger.

🧠 Analogy: Imagine mailing a fragile vase. The vase is your content. The foam/bubble wrap you put AROUND it inside the box is the padding. More padding = more space between the vase and the edge of the box. 
/* All 4 sides the same */
padding: 20px;

/* Top/Bottom = 10px, Left/Right = 20px */
padding: 10px 20px;

/* Top Right Bottom Left (clockwise, like a clock!) */
padding: 10px 20px 30px 40px;

/* Individual sides */
padding-top: 10px;
padding-right: 20px;
padding-bottom: 30px;
padding-left: 40px;
💡 Memory trick for 4 values: Think of a clock — start at the Top (12 o'clock), go Right (3 o'clock), then Bottom (6 o'clock), then Left (9 o'clock). TRouBLe → Top Right Bottom Left.
▶ Live Result — No Padding vs. With Padding

❌ NO PADDING

Content is squished against the edge. Looks cramped and ugly!

✅ WITH padding: 20px

Content has breathing room. Looks clean and professional!

4.3 Margin

Margin = space OUTSIDE the box, between this element and neighboring elements. It does NOT change the visual size of the element.

🧠 Analogy: Margin is like personal space. When you stand in line, there's a gap between you and the next person. That gap is the margin. The person's body (the box) doesn't change size — there's just invisible space around them.

Margin uses the same shorthand as padding:

margin: 20px;              /* all 4 sides */
margin: 10px 20px;         /* top/bottom, left/right */
margin: 0 auto;            /* top/bottom 0, left/right auto = CENTERED! */
margin-bottom: 32px;      /* just the bottom */
✅ The magic of margin: 0 auto: When you set the left and right margins to auto, the browser splits the available space equally on both sides. This horizontally centers a block element! (Only works if the element has a set width.)

⚠️ Margin Collapse — The Weird Quirk

Here's a CSS quirk that trips up everyone: when two vertical margins touch, they don't add up. Instead, the bigger one wins.

.box-a { margin-bottom: 30px; }
.box-b { margin-top: 20px; }

/* You'd expect 30 + 20 = 50px gap. WRONG! */
/* The gap is only 30px — the bigger margin wins */
ℹ️ Margin collapse only happens VERTICALLY (top/bottom), never horizontally (left/right). It also doesn't happen inside flex containers or grid containers. So once you start using Flexbox, margin collapse won't bother you.

4.4 Border

Border = the visible edge of the box. It sits between padding and margin.

/* Shorthand: width style color */
border: 2px solid #333;

/* Just one side */
border-bottom: 2px solid red;

/* Rounded corners */
border-radius: 10px;     /* slightly rounded */
border-radius: 50%;      /* perfect circle (if width = height) */

4.5 box-sizing: border-box (THE FIX)

Here's one of the biggest "gotchas" in CSS. By default, width only refers to the content area. Padding and border get added on top.

❌ The problem (default behavior): 
.box {
    width: 300px;
    padding: 20px;        /* 20 left + 20 right = 40px added */
    border: 5px solid;   /* 5 left + 5 right = 10px added */
}
/* Total ACTUAL width = 300 + 40 + 10 = 350px !! */
/* You said 300, but you got 350. Surprise! 😱 */
✅ The fix — box-sizing: border-box: 
.box {
    box-sizing: border-box;  /* THE FIX */
    width: 300px;
    padding: 20px;
    border: 5px solid;
}
/* Total ACTUAL width = 300px. Padding and border fit INSIDE. */
/* Content area shrinks to make room. MUCH more intuitive! */
▶ Live Result — content-box (default) vs. border-box

❌ content-box (DEFAULT)

width: 250px
+ padding: 40px
+ border: 10px
= 300px actual!

✅ border-box (THE FIX)

width: 250px
padding + border
fit INSIDE
= 250px actual!

THIS is why every CSS file starts with:

* {
    box-sizing: border-box;
}

The * selector means "every element on the page." This one line saves you from countless layout headaches.

4.6 DevTools Box Model Viewer

Your browser has a built-in tool to see the box model of any element:

  1. Right-click any element on a webpage → "Inspect" (or press F12)
  2. Click on the element in the DevTools "Elements" panel
  3. Look at the Computed tab (or the box model diagram in the sidebar)
  4. You'll see a beautiful colored diagram showing the exact pixel values for content, padding, border, and margin
What you'll see in DevTools: ┌─────────── margin ──────────────┐ │ 20 20 20 │ │ ┌─────── border ────────────┐ │ │ │ 2 2 2 │ │ │ │ ┌───── padding ────────┐ │ │ │ │ │ 16 16 16 │ │ │ │ │ │ ┌── content ──────┐ │ │ │ │ │ │ │ 264 × 40 │ │ │ │ │ │ │ └─────────────────┘ │ │ │ │ │ └──────────────────────┘ │ │ │ └───────────────────────────┘ │ └─────────────────────────────────┘
💡 Pro tip: Whenever something looks wrong in CSS, the first thing to do is open DevTools and check the box model. 90% of the time, it's a padding or margin issue you didn't expect.

5 Display Property — Block vs Inline vs Inline-Block

The display property controls how an element behaves in the page flow. It's one of the most important CSS properties, and understanding it solves a LOT of beginner confusion.

5.1 display: block

A block element:

  • 📏 Takes the FULL WIDTH of its parent (even if the content is short)
  • ⬇️ Always starts on a NEW LINE
  • ✅ You CAN set width, height, margin, and padding on all sides

Default block elements: <div>, <p>, <h1>–<h6>, <section>, <header>, <nav>, <ul>, <li>, <form>

▶ Live Result — Block elements stack vertically, take full width
Block 1 — I take the FULL width ←───────────────────→
Block 2 — I'm on a NEW line
Block 3 — Even though my text is short, I still take full width

5.2 display: inline

An inline element:

  • 📦 Takes ONLY the width of its content
  • ➡️ Sits on the SAME LINE as other inline elements
  • ❌ You CANNOT set width or height — they're IGNORED
  • ❌ Top/bottom margin are IGNORED

Default inline elements: <span>, <a>, <strong>, <em>, <code>, <img> (technically "inline replaced")

▶ Live Result — Inline elements sit side by side, only as wide as content
Inline A Inline B Inline C

↑ All three sit on the SAME line, and each is only as wide as its text.

❌ Why you can't style an <a> tag like a box: 
a {
    width: 200px;      /* IGNORED — a is inline! */
    height: 50px;     /* IGNORED — a is inline! */
    margin-top: 20px; /* IGNORED — a is inline! */
}
This is why beginners get frustrated! They try to set width/height on a link and nothing happens. The fix? Change its display to inline-block or block.

5.3 display: inline-block

inline-block is the best of both worlds:

  • ➡️ Sits on the SAME LINE as other elements (like inline)
  • ✅ But you CAN set width, height, margin, padding (like block)
🧠 Think of it as: "Looks inline on the outside, behaves like a block on the inside." It flows with text but accepts all box model properties.
▶ Live Result — inline-block: side by side AND accepts width/height

↑ Side by side (inline behavior) but with set width and height (block behavior)!

5.4 display: none vs visibility: hidden

display: none makes an element completely disappear — it takes up zero space, as if it doesn't exist in the page.

visibility: hidden makes an element invisible — you can't see it, but it still takes up space.

▶ Live Result — display:none (removed) vs visibility:hidden (invisible)

5.5 display: flex (Connecting the Dots)

You already know Flexbox! But now you can see the bigger picture: flex is just another value for the display property.

.container {
    display: flex;     /* Block-level flex container */
}

.container {
    display: inline-flex; /* Inline-level flex container */
}
🧠 When you set display: flex, the element itself becomes a block-level flex container. Its children become flex items and follow flex rules (like justify-content, align-items, etc.) instead of normal block/inline flow. The container is still a block element to the outside world.

6 Width, Height & CSS Units

6.1 Width

width: auto;       /* DEFAULT — takes parent's full width minus margins */
width: 300px;      /* Exact pixel width */
width: 50%;        /* 50% of the PARENT's width */
width: 100%;       /* Full parent width */

max-width: 1200px; /* "Never wider than 1200px" — essential for responsive */
min-width: 200px;  /* "Never narrower than 200px" */
ℹ️ auto vs 100%: They look the same but behave differently. width: auto respects margins — if you have margin: 0 20px, the element shrinks to fit. width: 100% forces the element to be exactly its parent's width, and margins will make it overflow past the parent.
💡 max-width is your best friend for responsive design. A common pattern: width: 100%; max-width: 1200px; margin: 0 auto;. This makes the element full-width on small screens but capped at 1200px on large screens, centered horizontally.

6.2 Height

height: auto;       /* DEFAULT — grows to fit content */
height: 300px;      /* Exact pixel height */
height: 100vh;      /* 100% of viewport (browser window) height */

min-height: 100vh; /* "At least fill the screen, but grow if content is more" */
🧠 Why min-height: 100vh is better than height: 100vh:
With height: 100vh, if your content is longer than the screen, it overflows and gets cut off or creates a scroll inside the element. With min-height: 100vh, the element is AT LEAST screen-height, but it stretches if content needs more space. Always safer.

6.3 CSS Units — Which One When?

Unit What It Means Example Best For
px Pixels — absolute, never changes border: 2px solid Borders, shadows, tiny fixed sizes
% Percentage of the parent element width: 50% Widths, responsive layouts
em Relative to current element's font-size padding: 1.5em Spacing that scales with text
rem Relative to ROOT (html) font-size (usually 16px) font-size: 1.25rem = 20px Font sizes, consistent spacing
vh Viewport height (100vh = full screen) height: 100vh Full-screen hero sections
vw Viewport width (100vw = full screen) width: 100vw Full-bleed backgrounds
▶ Live Result — rem vs px: rem scales, px stays fixed

1rem = This text is 16px (1rem)

1.5rem = This text is 24px (1.5rem)

2rem = This text is 32px (2rem)

💡 Quick rule of thumb:
• px for small fixed things (borders, box-shadows, tiny spacers)
• rem for font sizes (consistent and accessible)
• % for widths (responsive to parent)

Exercise 1: Block vs Inline-Block

Create 3 <div> boxes with different background colors (#10b981, #388bfd, #d2a8ff). Give them each width: 150px, height: 100px, and padding: 16px.

First, observe them as block (default) — they stack vertically. Then change their display to inline-block and watch them sit side by side.

<style>
    .box {
        width: 150px;
        height: 100px;
        padding: 16px;
        color: white;
        font-weight: bold;
        border-radius: 8px;

        /* Try both: */
        /* display: block;        ← stacks vertically */
        display: inline-block;  /* ← sits side by side */
    }
    .box-a { background: #10b981; }
    .box-b { background: #388bfd; }
    .box-c { background: #d2a8ff; }
</style>

<div class="box box-a">Box A</div>
<div class="box box-b">Box B</div>
<div class="box box-c">Box C</div>

Exercise 2: Box Model Math

Create a box with: width: 300px, padding: 20px, border: 5px solid #388bfd.

Question: What is the TOTAL actual width without box-sizing: border-box?

Then add box-sizing: border-box and see how the total width changes. Open DevTools to verify!

Without border-box (default content-box):

Content width:       300px
+ Left padding:     + 20px
+ Right padding:    + 20px
+ Left border:      +  5px
+ Right border:     +  5px
─────────────────────────────
Total actual width:  350px  ← SURPRISE!

With box-sizing: border-box:

Total width:         300px  ← Exactly what you set!
Content area:        250px  (300 - 20 - 20 - 5 - 5)
Padding:             40px   (20 each side, fits INSIDE)
Border:              10px   (5 each side, fits INSIDE)

Exercise 3: Selector Specificity Battle

Create 3 paragraphs. Style them using:

  • 1st paragraph: element selector (p { color: blue; })
  • 2nd paragraph: class selector (.special { color: green; })
  • 3rd paragraph: ID selector (#unique { color: red; })

Then add this conflicting rule: p { color: purple !important; }

Question: What color does each paragraph become? Predict BEFORE you test.

p        { color: blue; }     /* specificity: 1 */
.special { color: green; }    /* specificity: 10 */
#unique  { color: red; }      /* specificity: 100 */

/* Without !important: */
/* Paragraph 1: blue (only p matches) */
/* Paragraph 2: green (.special beats p) */
/* Paragraph 3: red (#unique beats everything) */

/* With p { color: purple !important; }: */
/* ALL THREE become purple! */
/* !important overrides ALL specificity. */
/* This is why !important is dangerous. */

Exercise 4: Inheritance Detective

Create a parent <div> with these styles: color: blue, font-family: 'Georgia', serif, border: 3px solid red, padding: 20px.

Inside the div, add a <p>, an <h3>, and a <span>. Don't add any CSS to the children.

Question: Which children have blue text? Which have a red border? Which have padding?

/* All children INHERIT: */
/*   ✅ color: blue      — text properties inherit */
/*   ✅ font-family      — text properties inherit */

/* No children INHERIT: */
/*   ❌ border           — box properties do NOT inherit */
/*   ❌ padding          — box properties do NOT inherit */

/* So the <p>, <h3>, and <span> will all have: */
/*   - Blue text in Georgia font (inherited) */
/*   - NO border (not inherited) */
/*   - NO extra padding (not inherited) */

Exercise 5: Navigation Bar WITHOUT Flexbox

Build a horizontal nav bar with 4 links using display: inline-block (do NOT use Flexbox). Requirements:

  • Links should sit side by side
  • Each link has padding: 12px 24px
  • Background color: #1e2d4a, text color: white, no underline
  • On hover: background changes to #10b981
  • Nav bar has a dark background (#0d1117)
<style>
    .my-nav {
        background: #0d1117;
        padding: 8px;
        border-radius: 8px;
        /* Remove whitespace gaps between inline-block */
        font-size: 0;
    }
    .my-nav a {
        display: inline-block;
        padding: 12px 24px;
        background: #1e2d4a;
        color: white;
        text-decoration: none;
        font-family: 'Inter', sans-serif;
        font-size: 15px;  /* Reset from parent's font-size: 0 */
        border-radius: 6px;
        margin-right: 4px;
        transition: background 0.2s;
    }
    .my-nav a:hover {
        background: #10b981;
    }
</style>

<nav class="my-nav">
    <a href="#">Home</a>
    <a href="#">Games</a>
    <a href="#">About</a>
    <a href="#">Contact</a>
</nav>

Note: The font-size: 0 trick on the parent removes the tiny whitespace gaps that appear between inline-block elements (caused by spaces/newlines in HTML). This is a classic technique!

🎯 What You Learned Today

  • ✅ CSS Rules = Selector (who) + Property (what) + Value (how)
  • ✅ Selectors — element, class, ID, descendant, child, grouping, chained
  • ✅ Specificity — inline(1000) > ID(100) > class(10) > element(1). Higher score wins!
  • ✅ Inheritance — text properties pass down, box properties don't
  • ✅ Box Model — content → padding → border → margin (inside out)
  • ✅ box-sizing: border-box — always use it, padding/border go INSIDE width
  • ✅ Display — block (full width, new line), inline (no width/height), inline-block (best of both)
  • ✅ Units — px (fixed), rem (font), % (widths), vh/vw (viewport)

These are the fundamentals. Every single CSS technique you learn from here — Flexbox, Grid, animations, responsive design — builds on top of these concepts. You now have the foundation. 💪

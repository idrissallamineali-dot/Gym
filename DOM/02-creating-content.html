Lesson 02

Creating & Manipulating Content

This is where JavaScript becomes visual. You'll learn to create elements from nothing, insert them into the page, change their appearance, remove them, clone them, and build entire interfaces from pure JavaScript.

1. Creating Elements

The starting point: document.createElement(). This creates a brand new element in memory — it does NOT appear on the page yet.

// Step 1: CREATE the element (exists in memory only)
const div = document.createElement("div");

// At this point, div is a real DOM element object
// but it's floating in memory — NOT attached to the page
console.log(div);  // <div></div> — empty, invisible, detached
🧠 Mental Model
Think of createElement like building a LEGO piece in your hand. It exists, it's real, but it's not on the board yet. You have to place it somewhere on the page for it to appear.

Step 2: Configure the element

After creating, you give it content, classes, attributes — everything it needs before placing it on the page:

const card = document.createElement("div");

// Add classes
card.classList.add("card", "card-primary");

// Set text content
card.textContent = "Hello World";

// Set an attribute
card.setAttribute("data-id", "42");

// Set an ID
card.id = "main-card";

// Set inline styles
card.style.backgroundColor = "#1a1a2e";
card.style.padding = "20px";
card.style.borderRadius = "12px";

// At this point, card is fully configured but still NOT on the page

Step 3: Insert into the page

Now you attach the element to the DOM tree. It appears on screen the instant you do this:

// Append as the LAST child of body
document.body.appendChild(card);

// NOW the card is visible on the page ✅
The 3-Step Pattern (memorize this): 1. CREATE → document.createElement("tag") 2. CONFIGURE → set text, classes, attributes, styles 3. INSERT → parent.appendChild(element) This pattern is used every single time you build UI with JS.

2. All The Ways To Insert Elements

There are many methods to insert an element. Each one places the element in a different position relative to the parent:

Given this structure: <div id="parent"> <p>First</p> <p>Second</p> <p>Third</p> </div> Insertion positions: beforebegin ← before the parent itself <div id="parent"> afterbegin ← first child position <p>First</p> <p>Second</p> <p>Third</p> beforeend ← last child position </div> afterend ← after the parent itself

Modern Methods (use these)

const parent = document.querySelector("#parent");
const newEl = document.createElement("p");
newEl.textContent = "New paragraph";

// ── INSIDE the parent ──────────────────────────────────

parent.append(newEl);           // Insert as LAST child
parent.prepend(newEl);          // Insert as FIRST child

// ── OUTSIDE the parent ─────────────────────────────────

parent.before(newEl);           // Insert BEFORE parent (as sibling)
parent.after(newEl);            // Insert AFTER parent (as sibling)

// ── RELATIVE TO A SPECIFIC CHILD ───────────────────────

const second = parent.children[1];
second.before(newEl);           // Insert before the second child
second.after(newEl);            // Insert after the second child

append vs appendChild — What's the difference?

FeatureappendChild()append()
Insert element✅✅
Insert text string❌✅
Insert multiple things❌ (one at a time)✅
ReturnsThe inserted elementundefined
// appendChild — the old way (one element at a time)
parent.appendChild(newEl);

// append — the modern way (multiple items, text included)
parent.append(newEl, " some text", anotherEl);

// prepend — same as append but at the beginning
parent.prepend("Title: ", titleEl);
✅ Rule
Use append() / prepend() / before() / after() — the modern methods. They're cleaner, accept multiple arguments, and accept text strings. appendChild is the old way.

replaceWith() — Swap an element

const oldEl = document.querySelector(".old");
const newEl = document.createElement("div");
newEl.textContent = "I replaced the old element";

oldEl.replaceWith(newEl);  // oldEl is gone, newEl takes its place

3. Inserting HTML Strings

Sometimes you want to insert raw HTML strings instead of creating elements one by one. Two approaches:

innerHTML — Replace all content

const container = document.querySelector("#container");

// ⚠️ This REPLACES everything inside the container
container.innerHTML = `
    <h2>New Title</h2>
    <p>New paragraph</p>
    <button class="btn">Click me</button>
`;

// ADD to existing content (don't replace)
container.innerHTML += `<p>Added paragraph</p>`;
⚠️ innerHTML Problems
1. Security: Never use innerHTML with user input (XSS attack risk).
2. Performance: Using innerHTML += destroys ALL existing children and recreates them. Any event listeners on those children are lost.
3. Lost state: Input values, scroll positions, video playback — all reset.

insertAdjacentHTML — Insert at a specific position

This is the best of both worlds — you write HTML strings, but you insert at a specific position without destroying existing content:

const list = document.querySelector("ul");

// Insert as first child
list.insertAdjacentHTML("afterbegin", `<li>First item</li>`);

// Insert as last child
list.insertAdjacentHTML("beforeend", `<li>Last item</li>`);

// Insert before the element itself
list.insertAdjacentHTML("beforebegin", `<h3>My List</h3>`);

// Insert after the element itself
list.insertAdjacentHTML("afterend", `<p>End of list</p>`);
🧠 When to use what?
• createElement + append — when building complex interactive elements with event listeners.
• insertAdjacentHTML — when you need to insert quick static HTML at a specific position.
• innerHTML — only when you want to replace ALL content inside an element and don't care about losing listeners.

4. Removing Elements

const el = document.querySelector(".card");

// Modern way — simple and clean
el.remove();

// Old way — remove through the parent
el.parentElement.removeChild(el);

// Remove ALL children of an element
const container = document.querySelector("#container");
container.innerHTML = "";   // quick but destroys listeners

// Safer way to clear all children
while (container.firstChild) {
    container.firstChild.remove();
}

// Modern one-liner to clear
container.replaceChildren();  // removes all children — clean and safe

5. Cloning Elements

Sometimes you want to duplicate an existing element rather than building a new one from scratch:

const original = document.querySelector(".card");

// Shallow clone — copies the element but NOT its children
const shallow = original.cloneNode(false);

// Deep clone — copies the element AND all its children
const deep = original.cloneNode(true);

// The clone is detached — you still need to insert it
document.body.append(deep);
⚡ Important
cloneNode copies the HTML structure but does NOT copy event listeners. If the original card had a click handler, the clone won't have it. You'll need to add listeners again.

6. Modifying Styles

Inline styles — the style property

const box = document.querySelector(".box");

// Set individual styles (camelCase, not kebab-case!)
box.style.backgroundColor = "#1a1a2e";    // background-color → backgroundColor
box.style.fontSize = "18px";               // font-size → fontSize
box.style.borderRadius = "12px";           // border-radius → borderRadius
box.style.padding = "20px";
box.style.color = "white";

// Read a style
console.log(box.style.color);  // "white"

// Remove a style
box.style.color = "";  // set to empty string to remove

// Set multiple styles at once with cssText
box.style.cssText = `
    background: #1a1a2e;
    color: white;
    padding: 20px;
    border-radius: 12px;
`;
// ⚠️ cssText REPLACES all existing inline styles
⚠️ style only reads INLINE styles
element.style.color only returns a value if the style was set inline (via JS or the style attribute). It does NOT read styles from CSS stylesheets. To read the computed (final) style, use getComputedStyle(): 
// Read the ACTUAL computed style (from CSS + inline)
const computed = getComputedStyle(box);
console.log(computed.color);           // "rgb(255, 255, 255)"
console.log(computed.fontSize);        // "18px"
console.log(computed.backgroundColor);  // "rgb(26, 26, 46)"

classList — The Professional Way to Style

In real projects, you almost never set inline styles from JS. Instead, you define CSS classes in your stylesheet and toggle classes with JavaScript:

const btn = document.querySelector(".btn");

// ── ADD a class ───────────────────────────
btn.classList.add("active");
btn.classList.add("primary", "large");  // multiple at once

// ── REMOVE a class ────────────────────────
btn.classList.remove("active");
btn.classList.remove("primary", "large");

// ── TOGGLE — add if missing, remove if present ──
btn.classList.toggle("active");
// Returns true if class was added, false if removed

// ── Force toggle with second argument ─────
btn.classList.toggle("active", true);   // always ADD
btn.classList.toggle("active", false);  // always REMOVE

// ── CHECK if a class exists ──────────────
btn.classList.contains("active");  // true or false

// ── REPLACE one class with another ────────
btn.classList.replace("old-class", "new-class");
✅ The Professional Pattern
1. Define all your visual states in CSS (.active, .hidden, .error, .loading)
2. In JavaScript, just toggle classes: element.classList.toggle("active")
3. Never write element.style.display = "none" — use element.classList.add("hidden") instead.

Real Example: Dark Mode Toggle

/* CSS */
/*
body { background: white; color: black; transition: 0.3s; }
body.dark-mode { background: #0f111a; color: #c9d1d9; }
*/

// JavaScript — one line!
const toggleBtn = document.querySelector("#dark-toggle");

toggleBtn.addEventListener("click", () => {
    document.body.classList.toggle("dark-mode");
});

const img = document.querySelector("img");
const link = document.querySelector("a");

// ── Standard attributes — use properties directly ────
img.src = "new-image.jpg";
img.alt = "Description";
img.width = 300;

link.href = "https://example.com";
link.target = "_blank";

img.setAttribute("loading", "lazy");

input.disabled = true;    // adds the disabled attribute
input.disabled = false;   // removes it
input.required = true;

// ── data-* attributes — use dataset ──────────────────
const card = document.querySelector(".card");
card.dataset.userId = "42";         // creates data-user-id="42"
card.dataset.role = "admin";         // creates data-role="admin"
console.log(card.dataset.userId);    // "42"

8. Building Real UI — Complete Examples

Let's combine everything into real-world patterns you'll use every day.

Example 1: Build a Card Component

function createCard({ title, body, image }) {
    // 1. CREATE
    const card = document.createElement("div");
    const img = document.createElement("img");
    const h3 = document.createElement("h3");
    const p = document.createElement("p");

    // 2. CONFIGURE
    card.classList.add("card");
    img.src = image;
    img.alt = title;
    h3.textContent = title;
    p.textContent = body;

    // 3. ASSEMBLE (build the tree)
    card.append(img, h3, p);

    // 4. RETURN (let the caller decide where to insert)
    return card;
}

// Usage:
const myCard = createCard({
    title: "JavaScript",
    body: "The language of the web",
    image: "js-logo.png"
});

document.querySelector("#app").append(myCard);
🏗️ Factory Pattern
Notice how createCard is a factory function for DOM elements. It takes data, builds a complete element tree, and returns it. The caller decides where to put it. This is how professional code is structured.

Example 2: Render a List from Data

const users = [
    { name: "Alice", role: "Developer" },
    { name: "Bob", role: "Designer" },
    { name: "Charlie", role: "Manager" }
];

function renderUserList(users, container) {
    const ul = document.createElement("ul");
    ul.classList.add("user-list");

    users.forEach(user => {
        const li = document.createElement("li");
        li.textContent = `${user.name} — ${user.role}`;
        li.dataset.role = user.role;  // store metadata
        ul.append(li);
    });

    container.append(ul);
}

renderUserList(users, document.querySelector("#app"));

Example 3: Dynamic Table from Array of Objects

const products = [
    { name: "Laptop", price: 999, stock: 12 },
    { name: "Phone", price: 699, stock: 34 },
    { name: "Tablet", price: 499, stock: 0 }
];

function createTable(data) {
    const table = document.createElement("table");

    // Header row
    const thead = document.createElement("thead");
    const headerRow = document.createElement("tr");
    Object.keys(data[0]).forEach(key => {
        const th = document.createElement("th");
        th.textContent = key.toUpperCase();
        headerRow.append(th);
    });
    thead.append(headerRow);

    // Data rows
    const tbody = document.createElement("tbody");
    data.forEach(item => {
        const row = document.createElement("tr");
        Object.values(item).forEach(value => {
            const td = document.createElement("td");
            td.textContent = value;
            row.append(td);
        });
        // Highlight out-of-stock rows
        if (item.stock === 0) row.classList.add("out-of-stock");
        tbody.append(row);
    });

    table.append(thead, tbody);
    return table;
}

document.querySelector("#app").append(createTable(products));

9. DocumentFragment — Batch Insertions

Every time you append an element to the DOM, the browser recalculates layout and repaints. If you're adding 100 items in a loop, that's 100 reflows. Slow.

DocumentFragment is an invisible container — you build everything inside it, then insert it all at once (1 reflow instead of 100):

const fragment = document.createDocumentFragment();

// Build 1000 items in the fragment (no reflow yet)
for (let i = 0; i < 1000; i++) {
    const li = document.createElement("li");
    li.textContent = `Item ${i + 1}`;
    fragment.append(li);  // appending to fragment — NOT the DOM
}

// One single DOM insertion — one reflow
document.querySelector("ul").append(fragment);
Without Fragment (slow): append li → reflow append li → reflow append li → reflow ... × 1000 = 1000 reflows 🐌 With Fragment (fast): append li to fragment (no reflow) append li to fragment (no reflow) append li to fragment (no reflow) ... × 1000 append fragment to DOM → 1 reflow 🚀

10. Template Literals + createElement Patterns

In real projects, you'll see different patterns. Here are the 3 most common:

Pattern 1: Pure createElement (verbose but safe)

function createButton(text, onClick) {
    const btn = document.createElement("button");
    btn.textContent = text;
    btn.classList.add("btn");
    btn.addEventListener("click", onClick);
    return btn;
}

Pattern 2: insertAdjacentHTML (quick, no listeners)

function addCard(container, title, body) {
    container.insertAdjacentHTML("beforeend", `
        <div class="card">
            <h3>${title}</h3>
            <p>${body}</p>
        </div>
    `);
}

Pattern 3: Helper function (clean and reusable)

// A tiny helper that makes createElement less verbose
function el(tag, attrs = {}, ...children) {
    const element = document.createElement(tag);

    // Apply attributes
    for (const [key, value] of Object.entries(attrs)) {
        if (key === "class") element.className = value;
        else if (key === "dataset") Object.assign(element.dataset, value);
        else if (key.startsWith("on")) element.addEventListener(key.slice(2), value);
        else element[key] = value;
    }

    // Append children (elements or strings)
    element.append(...children);
    return element;
}

// Usage — reads like a component tree:
const card = el("div", { class: "card" },
    el("h3", {}, "Card Title"),
    el("p", {}, "Card description here"),
    el("button", { class: "btn", onclick: () => alert("clicked!") }, "Click Me")
);

document.querySelector("#app").append(card);
✅ Pro Tip
The el() helper above is essentially what React and other frameworks do behind the scenes. Understanding this pattern is the first step to understanding how UI frameworks work.

11. Working With Forms

// ── Reading values ────────────────────────────────────
const nameInput = document.querySelector("#name");
nameInput.value;            // the current text in the input
nameInput.value = "";       // clear the input

const checkbox = document.querySelector("#agree");
checkbox.checked;           // true or false

const select = document.querySelector("select");
select.value;               // the selected option's value

// ── Getting all form data at once ─────────────────────
const form = document.querySelector("form");
const formData = new FormData(form);

// Convert to a plain object
const data = Object.fromEntries(formData);
console.log(data);  // { name: "Idris", email: "a@b.com", ... }

// ── Form submission ──────────────────────────────────
form.addEventListener("submit", (e) => {
    e.preventDefault();  // STOP the page from reloading

    const data = Object.fromEntries(new FormData(form));
    console.log("Submitted:", data);

    form.reset();  // clear all fields
});
💡 preventDefault()
By default, a form submission reloads the page (it sends an HTTP request). In modern apps, we handle submissions with JavaScript instead — so we call e.preventDefault() to stop the reload, then process the data ourselves.

12. Real-World Pattern: Todo List

This combines everything — createElement, append, remove, classList, events, forms:

/* HTML needed:
   <form id="todo-form">
       <input id="todo-input" placeholder="Add a task...">
       <button type="submit">Add</button>
   </form>
   <ul id="todo-list"></ul>
*/

const form = document.querySelector("#todo-form");
const input = document.querySelector("#todo-input");
const list = document.querySelector("#todo-list");

function createTodo(text) {
    const li = document.createElement("li");
    li.classList.add("todo-item");

    const span = document.createElement("span");
    span.textContent = text;

    const doneBtn = document.createElement("button");
    doneBtn.textContent = "✓";
    doneBtn.classList.add("btn-done");
    doneBtn.addEventListener("click", () => {
        li.classList.toggle("completed");  // toggle strikethrough
    });

    const deleteBtn = document.createElement("button");
    deleteBtn.textContent = "✕";
    deleteBtn.classList.add("btn-delete");
    deleteBtn.addEventListener("click", () => {
        li.remove();  // remove from DOM
    });

    li.append(span, doneBtn, deleteBtn);
    return li;
}

form.addEventListener("submit", (e) => {
    e.preventDefault();

    const text = input.value.trim();
    if (!text) return;  // guard clause: don't add empty todos

    list.append(createTodo(text));
    input.value = "";       // clear input
    input.focus();           // refocus for next entry
});
What this code does: User types "Learn JS" → submits form 1. preventDefault() — stops page reload 2. input.value.trim() — get text, remove whitespace 3. createTodo("Learn JS") — builds: <li> <span> <button ✓> <button ✕> 4. list.append(li) — adds to page 5. input.value = "" — clears input 6. input.focus() — ready for next entry Click ✓ → toggles "completed" class (strikethrough) Click ✕ → li.remove() — element disappears

13. Performance Tips

❌ Slow✅ FastWhy
innerHTML += in a loopBuild in fragment, insert once+= destroys & rebuilds everything
Read layout → write → read layoutBatch reads, then batch writesAvoids forced reflows
Query the same element repeatedlyCache in a variablequerySelector is not free
One listener per elementOne listener on parent (delegation)Less memory, works with dynamic elements
element.style.x = "..." many timeselement.classList.add("x")One style recalculation instead of many
// ❌ DON'T — querying inside a loop
for (let i = 0; i < 100; i++) {
    document.querySelector("#list").append(...)  // queries 100 times!
}

// ✅ DO — cache the element
const list = document.querySelector("#list");  // query once
for (let i = 0; i < 100; i++) {
    list.append(...)  // reuse the cached reference
}

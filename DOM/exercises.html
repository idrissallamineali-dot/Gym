DOM — Tricky Questions & Exercises

30 questions that test your deep understanding of the DOM, events, the event loop, and performance. Predict the output before running the code. These WILL appear in interviews.

Part 1 — Predict The Output (Event Loop & Timing)

01Predict Output

setTimeout(0) vs sync

console.log("A");
setTimeout(() => console.log("B"), 0);
console.log("C");
setTimeout(() => console.log("D"), 0);
console.log("E");

Answer

A, C, E, B, D

All sync code runs first (call stack). setTimeout callbacks go to the macrotask queue and only run after the stack is empty. Even with 0ms delay, they wait.

02Predict Output

Promise vs setTimeout

setTimeout(() => console.log("1"), 0);
Promise.resolve().then(() => console.log("2"));
console.log("3");

Answer

3, 2, 1

3 = sync (stack). 2 = microtask (Promise.then — always runs before macrotasks). 1 = macrotask (setTimeout — runs last). Priority: Sync → Microtasks → Macrotasks.

03Predict Output

Chained Promises vs setTimeout

console.log("A");

setTimeout(() => console.log("B"), 0);

Promise.resolve()
    .then(() => console.log("C"))
    .then(() => console.log("D"))
    .then(() => console.log("E"));

console.log("F");

Answer

A, F, C, D, E, B

A, F = sync. Then ALL microtasks drain before the macrotask: C → D → E (each .then adds the next to the microtask queue). B = macrotask, runs last.

04Predict Output

setTimeout inside Promise

Promise.resolve().then(() => {
    console.log("A");
    setTimeout(() => console.log("B"), 0);
});

setTimeout(() => {
    console.log("C");
    Promise.resolve().then(() => console.log("D"));
}, 0);

Answer

A, C, D, B

A = microtask runs first. Inside it, setTimeout("B") is queued as macrotask. C = first macrotask runs (it was registered first, before the one from the microtask). Inside C, Promise("D") is queued as microtask → D drains immediately. B = second macrotask runs last.

05Predict Output

async/await execution order

async function foo() {
    console.log("1");
    await Promise.resolve();
    console.log("2");
}

console.log("3");
foo();
console.log("4");

Answer

3, 1, 4, 2

3 = sync. 1 = inside foo, before await (runs synchronously). await pauses foo — everything after it becomes a microtask. 4 = sync continues. 2 = microtask runs (the continuation after await).

06Predict Output

setTimeout ordering

setTimeout(() => console.log("A"), 100);
setTimeout(() => console.log("B"), 0);
setTimeout(() => console.log("C"), 50);
console.log("D");

Answer

D, B, C, A

D = sync. Then timeouts fire in order of their delay: B (0ms) → C (50ms) → A (100ms).

07Predict Output

The classic closure-in-loop trap

for (var i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 0);
}

Answer

3, 3, 3

NOT 0, 1, 2! var is function-scoped — there's only ONE i shared by all callbacks. By the time the callbacks run (after the loop), i is already 3. Fix: use let instead of var — let creates a new scope per iteration.

08Predict Output

The let fix

for (let i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 0);
}

Answer

0, 1, 2

let creates a new binding for each loop iteration. Each callback closes over its own copy of i.

Part 2 — Predict The Output (DOM & Events)

09Predict Output

Event bubbling order

// HTML: <div id="outer"><button id="inner">Click</button></div>

outer.addEventListener("click", () => console.log("outer"));
inner.addEventListener("click", () => console.log("inner"));
document.body.addEventListener("click", () => console.log("body"));

// User clicks the button. What's the output?

Answer

inner, outer, body

Events bubble UP from the target to ancestors: button (target) → div → body. Default listeners fire during the bubbling phase, from deepest to shallowest.

10Predict Output

Capturing + bubbling mix

// Same HTML structure
outer.addEventListener("click", () => console.log("outer-capture"), true);
inner.addEventListener("click", () => console.log("inner"));
outer.addEventListener("click", () => console.log("outer-bubble"));

// Click the button

Answer

outer-capture, inner, outer-bubble

Capturing goes DOWN first (outer-capture). Then target phase (inner). Then bubbling goes UP (outer-bubble). Capture listeners fire before bubble listeners.

11Predict Output

stopPropagation

inner.addEventListener("click", (e) => {
    console.log("inner");
    e.stopPropagation();
});
outer.addEventListener("click", () => console.log("outer"));

// Click the button

Answer

inner

"outer" never fires. stopPropagation() prevents the event from bubbling to parent elements.

12Predict Output

target vs currentTarget

// HTML: <div id="parent"><span id="child">Click me</span></div>

parent.addEventListener("click", (e) => {
    console.log("target:", e.target.id);
    console.log("currentTarget:", e.currentTarget.id);
});

// Click the span

Answer

target: child
currentTarget: parent

e.target = the element that was actually clicked (span). e.currentTarget = the element the listener is attached to (div). They differ when the click bubbles.

13Predict Output

removeEventListener with anonymous function

btn.addEventListener("click", () => console.log("click!"));
btn.removeEventListener("click", () => console.log("click!"));

// User clicks the button. What happens?

Answer

"click!" still fires

The remove does NOTHING. Each () => ... creates a new function object. They look identical but are different references. removeEventListener needs the exact same function reference.

14Predict Output

onclick vs addEventListener

btn.onclick = () => console.log("A");
btn.onclick = () => console.log("B");
btn.addEventListener("click", () => console.log("C"));

// Click the button

Answer

B, C

The second onclick = overwrites the first (A is gone). But addEventListener adds independently. Both B (from onclick) and C (from addEventListener) fire.

15Predict Output

textContent vs innerHTML

div.innerHTML = "<script>alert('hacked')</script>";
// Does the alert fire?

div.textContent = "<b>bold?</b>";
// What does the user see?

Answer

No alert. Scripts inserted via innerHTML don't execute.
User sees literal text: "<b>bold?</b>" — not bold text.

innerHTML parses HTML but blocks <script> tags (browser safety). textContent treats everything as plain text — no HTML parsing at all. Tags appear as visible characters.

Part 3 — Predict The Output (Performance Traps)

16Concept

What's wrong with this code?

const items = document.querySelectorAll(".item");
items.forEach(item => {
    const h = item.offsetHeight;    // READ
    item.style.height = h + 10 + "px"; // WRITE
});

Answer

Layout thrashing. Each iteration reads offsetHeight (forces layout) then writes style.height (invalidates layout). On the next iteration, the browser must recalculate layout AGAIN. With 100 items, that's 100 forced reflows. Fix: batch all reads first, then all writes.

const heights = [...items].map(i => i.offsetHeight); // all reads
items.forEach((item, i) => {
    item.style.height = heights[i] + 10 + "px";  // all writes
});
17Concept

Why is this slow?

for (let i = 0; i < 1000; i++) {
    list.innerHTML += `<li>Item ${i}</li>`;
}

Answer

innerHTML += on each iteration: serializes all existing HTML → concatenates the new string → destroys all DOM nodes → re-parses everything → creates all nodes again. On iteration 999, it parses 999 previous items + 1 new one. All event listeners on existing elements are lost. Fix: use DocumentFragment or build a string first.

18Concept

Which triggers reflow? Which doesn't?

el.style.color = "red";
el.style.width = "200px";
el.style.transform = "translateX(50px)";
el.style.opacity = "0.5";
el.style.margin = "20px";
el.style.backgroundColor = "blue";

Answer

Triggers reflow: width, margin (geometry changes)
Triggers repaint only: color, backgroundColor (visual only)
Composite only (cheapest): transform, opacity (GPU-accelerated)

Accordion (Collapsible Sections)

Create an accordion where clicking a header toggles its content panel. Only one panel should be open at a time.

Use event delegation on the parent container. Use closest() and classList.

Solution

// HTML:
// <div id="accordion">
//   <div class="section">
//     <button class="header">Section 1</button>
//     <div class="panel">Content 1</div>
//   </div>
//   ...
// </div>

const accordion = document.querySelector("#accordion");

accordion.addEventListener("click", (e) => {
    const header = e.target.closest(".header");
    if (!header) return;

    const section = header.closest(".section");
    const isOpen = section.classList.contains("active");

    // Close all sections
    accordion.querySelectorAll(".section")
        .forEach(s => s.classList.remove("active"));

    // If this one wasn't open, open it
    if (!isOpen) section.classList.add("active");
});
22Build

Delegated Todo List with Filters

Build a todo list with Add, Complete (✓), and Delete (✕) buttons. Add "All / Active / Completed" filter buttons.

Use ONE event listener via delegation on the list. Use data attributes to store state. Filter by toggling CSS classes.

Solution

const form = document.querySelector("#form");
const input = document.querySelector("#input");
const list = document.querySelector("#list");

form.addEventListener("submit", (e) => {
    e.preventDefault();
    const text = input.value.trim();
    if (!text) return;
    list.insertAdjacentHTML("beforeend", `
        <li class="todo" data-done="false">
            <span>${text}</span>
            <button class="btn-done">✓</button>
            <button class="btn-del">✕</button>
        </li>`);
    input.value = "";
});

// ONE listener for all interactions
list.addEventListener("click", (e) => {
    const todo = e.target.closest(".todo");
    if (!todo) return;

    if (e.target.closest(".btn-done")) {
        const isDone = todo.dataset.done === "true";
        todo.dataset.done = String(!isDone);
        todo.classList.toggle("completed");
    }
    if (e.target.closest(".btn-del")) {
        todo.remove();
    }
});

// Filter buttons
document.querySelector("#filters").addEventListener("click", (e) => {
    const filter = e.target.dataset.filter;
    if (!filter) return;
    list.querySelectorAll(".todo").forEach(t => {
        const done = t.dataset.done === "true";
        const show = filter === "all"
            || (filter === "active" && !done)
            || (filter === "done" && done);
        t.classList.toggle("hidden", !show);
    });
});
23Build

Modal with Escape & Overlay Close

Build a modal that opens on button click. It should close when: (1) clicking the close button, (2) clicking the overlay background, (3) pressing Escape.

Use AbortController to register all closing listeners at once and clean them up when the modal closes.

Solution

const openBtn = document.querySelector("#open");
const modal = document.querySelector("#modal");
const overlay = document.querySelector("#overlay");
const closeBtn = document.querySelector("#close");

let controller;

function openModal() {
    modal.classList.add("active");
    overlay.classList.add("active");

    controller = new AbortController();
    const opts = { signal: controller.signal };

    closeBtn.addEventListener("click", closeModal, opts);
    overlay.addEventListener("click", closeModal, opts);
    document.addEventListener("keydown", (e) => {
        if (e.key === "Escape") closeModal();
    }, opts);
}

function closeModal() {
    modal.classList.remove("active");
    overlay.classList.remove("active");
    controller.abort();  // removes ALL listeners at once
}

openBtn.addEventListener("click", openModal);
24Build

Debounced Live Search

Build a search input that filters a list. Debounce the input so it only filters after the user stops typing for 300ms.

Write your own debounce function using setTimeout/clearTimeout.

Solution

function debounce(fn, delay) {
    let timer;
    return (...args) => {
        clearTimeout(timer);
        timer = setTimeout(() => fn(...args), delay);
    };
}

const input = document.querySelector("#search");
const items = document.querySelectorAll(".item");

const filterList = debounce((query) => {
    items.forEach(item => {
        const match = item.textContent.toLowerCase()
            .includes(query.toLowerCase());
        item.classList.toggle("hidden", !match);
    });
}, 300);

input.addEventListener("input", (e) => {
    filterList(e.target.value);
});

Scroll Progress Bar

Show a progress bar at the top of the page that fills as the user scrolls down.

Use scroll event with passive: true. Calculate percentage from scrollY, innerHeight, and scrollHeight. Use transform: scaleX() for GPU performance.

Solution

// CSS: .progress { position: fixed; top: 0; left: 0;
//   height: 3px; background: #58a6ff; width: 100%;
//   transform-origin: left; transform: scaleX(0); }

const bar = document.querySelector(".progress");

    const progress = window.scrollY / total;
    bar.style.transform = `scaleX(${progress})`;

28Build

Image Lazy Loader

Images should only load when they scroll into view. Use data-src instead of src, then swap when visible.

Use IntersectionObserver. Do NOT use scroll event.

Solution

const images = document.querySelectorAll("img[data-src]");

const observer = new IntersectionObserver((entries) => {
    entries.forEach(entry => {
        if (entry.isIntersecting) {
            const img = entry.target;
            img.src = img.dataset.src;
            img.removeAttribute("data-src");
            observer.unobserve(img);
        }
    });
}, { rootMargin: "200px" }); // load 200px before visible

images.forEach(img => observer.observe(img));

30Build

requestAnimationFrame Counter

Animate a number counting from 0 to 1000 over exactly 2 seconds using requestAnimationFrame.

Use requestAnimationFrame. Calculate progress from elapsed time. No setTimeout/setInterval.

Solution

const el = document.querySelector("#counter");
const target = 1000;
const duration = 2000; // 2 seconds
let start = null;

function animate(timestamp) {
    if (!start) start = timestamp;
    const elapsed = timestamp - start;
    const progress = Math.min(elapsed / duration, 1);

    el.textContent = Math.floor(progress * target);

    if (progress < 1) {
        requestAnimationFrame(animate);
    }
}

requestAnimationFrame(animate);

Lesson 08

What Is The DOM?

The DOM is the bridge between your HTML file and JavaScript. Without understanding it, you cannot build anything for the web. This lesson explains what it is, how the browser builds it, and how JavaScript sees your page.

1. The Big Picture

When you write an HTML file, you are writing text. It's just a string of characters sitting in a .html file on your hard drive. The browser's job is to turn that text into a living, interactive structure that JavaScript can read, change, and respond to.

That structure is called the DOM — Document Object Model.

🧠 Mental Model
The DOM is NOT your HTML file. The DOM is what the browser builds from your HTML file. Think of HTML as the blueprint, and the DOM as the actual building.
The Journey: HTML file ──→ Browser Parser ──→ DOM (tree of objects in memory) ──→ Render on screen (text) (reads the text) (live JavaScript objects) (pixels you see)

Here's the critical insight: JavaScript never touches your HTML file. JavaScript works with the DOM — the live objects in the browser's memory. When you change something with JS, the HTML file on disk doesn't change. Only the in-memory DOM changes, and the browser re-renders the screen.

2. How The Browser Builds The DOM

When the browser loads your HTML file, it follows a very specific process:

Step 1: Fetch — Download the HTML text

The browser downloads the raw text of your .html file from the server (or reads it from disk).

Step 2: Parse — Read character by character

The HTML parser reads the text and identifies tags, attributes, and text content. It tokenizes them — breaking the string into meaningful pieces.

Step 3: Build — Create DOM nodes

For every tag, attribute, and piece of text, the browser creates a JavaScript object called a Node. Each node has properties and methods.

Step 4: Connect — Arrange into a tree

The nodes are connected in a parent-child-sibling hierarchy that mirrors the HTML structure. This tree IS the DOM.

Given this HTML: <html> <head> <title>My Page</title> </head> <body> <h1>Hello</h1> <p>World</p> </body> </html>
The browser builds this tree: document │ html ╱ ╲ head body │ ╱ ╲ title h1 p │ │ │ "My Page" "Hello" "World" Green = Element Nodes (tags) Yellow = Text Nodes (content inside tags) Blue = Document Node (the root of everything)

Every single thing in this tree is a JavaScript object with properties like .tagName, .textContent, .children, .parentNode, etc. That's what makes it "programmable."

⚠️ Common Misconception
Many beginners think JavaScript "reads" the HTML. It doesn't. JavaScript reads the DOM objects that the browser created FROM the HTML. The DOM can even differ from the HTML — if your HTML has errors, the browser will fix them in the DOM automatically.

3. Everything Is A Node

In the DOM, everything is a node. There are different types of nodes:

Node TypenodeTypeExampleDescription
Document9documentThe root of the tree. Entry point for everything.
Element1<div>, <p>, <h1>Any HTML tag. The most common node you'll work with.
Text3"Hello"The text content inside an element.
Comment8<!-- note -->HTML comments are also nodes.
Attribute2class="box"Attributes on elements (rarely accessed as nodes directly).
💡 Key Insight
The most important distinction: Element Nodes vs Text Nodes. When you have <p>Hello</p>, the <p> is an Element Node, and "Hello" is a separate Text Node that is a child of the <p> element.

Node vs Element — The Confusion Everyone Has

This is one of the trickiest parts of the DOM. There are two sets of navigation properties:

Node Properties (all node types)Element Properties (elements only)
.childNodes.children
.firstChild.firstElementChild
.lastChild.lastElementChild
.nextSibling.nextElementSibling
.previousSibling.previousElementSibling
.parentNode.parentElement

The difference? Node properties include everything — text nodes, comment nodes, whitespace. Element properties include only HTML elements (tags).

// Given: <ul> <li>A</li> <li>B</li> </ul>

const ul = document.querySelector("ul");

ul.childNodes;       // NodeList [text, li, text, li, text]
                     // ↑ The "text" nodes are the whitespace between tags!

ul.children;         // HTMLCollection [li, li]
                     // ↑ Only the element nodes — this is what you usually want

ul.firstChild;       // #text (whitespace)
ul.firstElementChild; // <li>A</li> — this is what you want
✅ Rule
In 99% of cases, use the Element versions: .children, .firstElementChild, .nextElementSibling, etc. The Node versions include invisible whitespace text nodes that will confuse you.

4. The window and document Objects

Two objects are your entry points to everything in the browser:

window — The Global Object

window represents the browser tab. It is the top-level object. Everything global lives here:

window ├── document ← the DOM (your page) ├── console ← console.log lives here ├── alert() ← window.alert() ├── setTimeout() ← window.setTimeout() ├── localStorage ← window.localStorage ├── location ← URL info ├── navigator ← browser info ├── innerWidth ← viewport width ├── innerHeight ← viewport height └── ... everything global
// These are the same thing:
console.log("hello");          // shorthand
window.console.log("hello");  // full version

alert("hi");                   // shorthand
window.alert("hi");            // full version

// When you declare a var (not let/const), it becomes a window property:
var x = 42;
console.log(window.x);  // 42 — this is why var is bad!

let y = 42;
console.log(window.y);  // undefined — let/const don't pollute window

document — The DOM Entry Point

document is a property of window. It represents your entire page and is the starting point for all DOM operations.

// document IS the DOM
console.log(document);              // the entire page
console.log(document.documentElement);  // the <html> element
console.log(document.head);             // the <head> element
console.log(document.body);             // the <body> element
console.log(document.title);            // the <title> text
The hierarchy: window (the browser tab — global scope) │ document (the DOM — your page) │ document.documentElement (the <html> tag) │ ├── document.head (the <head> tag) │ └── document.body (the <body> tag) │ ├── h1, p, div, etc. │ └── (all your visible content)

5. Selecting Elements

Before you can do anything with the DOM, you need to "grab" the element you want to work with. This is called selecting or querying.

The Modern Way (use these)

MethodReturnsCSS Selector
document.querySelector(sel)First matching element (or null)✅ Yes
document.querySelectorAll(sel)NodeList of all matches✅ Yes
// By tag name
document.querySelector("h1");

// By class
document.querySelector(".card");

// By ID
document.querySelector("#main");

// Complex CSS selector — just like in CSS!
document.querySelector("nav ul li:first-child a");

// ALL matching elements
const allCards = document.querySelectorAll(".card");
// Returns a NodeList — looks like an array but isn't quite one

// Loop through NodeList
allCards.forEach(card => console.log(card));

// Convert to real array (for map, filter, reduce)
const cardsArray = [...allCards];

The Old Way (you'll still see these)

MethodReturnsWhen to use
getElementById("id")Single elementSlightly faster for IDs. No # prefix.
getElementsByClassName("class")Live HTMLCollectionAvoid — use querySelectorAll instead
getElementsByTagName("tag")Live HTMLCollectionAvoid — use querySelectorAll instead
// Old way — still works, still fast
document.getElementById("main");   // Note: NO # prefix

// Modern equivalent
document.querySelector("#main");   // With # prefix
⚡ Live vs Static Collections
getElementsByClassName returns a live HTMLCollection — if you add/remove elements, the collection updates automatically. querySelectorAll returns a static NodeList — a snapshot at the time of the query. Static is safer and more predictable. Use querySelectorAll.

Scoped Queries — Searching Within an Element

You don't have to search the entire document. You can search within a specific element:

// HTML: <div id="sidebar"> <p class="item">A</p> <p class="item">B</p> </div>

const sidebar = document.querySelector("#sidebar");

// Only searches INSIDE sidebar, not the whole page
const items = sidebar.querySelectorAll(".item");
console.log(items.length);  // 2

6. DOM Tree Navigation

Once you have an element, you can walk the DOM tree — moving up, down, and sideways:

Navigation from any element: .parentElement ↑ .previousElementSibling ← [ELEMENT] → .nextElementSibling ↓ ┌───────────┼───────────┐ .firstElementChild .children[n] .lastElementChild
// Given: <ul id="menu">
//          <li>Home</li>
//          <li id="current">About</li>
//          <li>Contact</li>
//        </ul>

const current = document.querySelector("#current");

// Going UP
current.parentElement;           // <ul id="menu">

// Going SIDEWAYS
current.previousElementSibling;  // <li>Home</li>
current.nextElementSibling;      // <li>Contact</li>

// Going DOWN (from the <ul>)
const menu = current.parentElement;
menu.children;              // HTMLCollection [li, li, li]
menu.children.length;       // 3
menu.firstElementChild;     // <li>Home</li>
menu.lastElementChild;      // <li>Contact</li>
menu.children[1];           // <li id="current">About</li>

closest() — Walking Up To Find an Ancestor

One of the most useful methods. It walks up the DOM tree and returns the first ancestor that matches a CSS selector:

// HTML:
// <div class="card">
//   <div class="card-body">
//     <button class="btn">Click</button>
//   </div>
// </div>

const btn = document.querySelector(".btn");

btn.closest(".card-body");  // <div class="card-body">
btn.closest(".card");       // <div class="card">
btn.closest("section");     // null (no section ancestor)

7. Reading Element Properties

Every DOM element is a rich object with many properties you can read:

const el = document.querySelector("h1");

// Identity
el.tagName;        // "H1" (always uppercase)
el.id;             // "main-title" (the id attribute)
el.className;      // "title big" (all classes as one string)
el.classList;       // DOMTokenList ["title", "big"] — use this instead

// Content
el.textContent;    // "Hello World" — all text, including hidden text
el.innerText;      // "Hello World" — only visible text (respects CSS)
el.innerHTML;      // "Hello <em>World</em>" — the raw HTML inside

// Dimensions (in pixels)
el.offsetWidth;    // 500 — width including padding + border
el.offsetHeight;   // 60 — height including padding + border
el.clientWidth;    // 480 — width including padding, NOT border
el.clientHeight;   // 40

// Position
el.getBoundingClientRect();
// { top: 100, right: 500, bottom: 160, left: 0, width: 500, height: 60 }
// Position relative to the viewport

textContent vs innerText vs innerHTML

This is a classic interview question. Here's the difference:

// Given: <p>Hello <span style="display:none">hidden</span> <em>World</em></p>

el.textContent;  // "Hello hidden World" — gets ALL text, ignores CSS
el.innerText;    // "Hello World" — only VISIBLE text (respects display:none)
el.innerHTML;    // 'Hello <span style="display:none">hidden</span> <em>World</em>'
PropertyGets/SetsParses HTML?Performance
textContentRaw text (all)No — treats everything as text✅ Fast
innerTextVisible textNo❌ Slow (triggers reflow)
innerHTMLHTML stringYes — parses and renders HTML⚠️ Security risk (XSS)
🔒 Security Warning: innerHTML
Never insert user input into innerHTML. If a user types <script>alert('hacked')</script> and you put it in innerHTML, the browser will execute that script. This is called XSS (Cross-Site Scripting). Use textContent for user data.

8. Attributes vs Properties

This is one of the most confusing parts of the DOM. HTML attributes and DOM properties are related but not the same thing.

HTML (attribute): <input type="text" value="hello"> DOM (property): inputElement.type = "text" inputElement.value = "hello" Attributes = what's written in the HTML (the initial values) Properties = the live values on the JavaScript object (can change)
// HTML: <input id="name" type="text" value="hello">
const input = document.querySelector("#name");

// PROPERTY — the live current value
input.value;                      // "hello"
input.value = "world";            // changes the live value

// ATTRIBUTE — the original HTML value
input.getAttribute("value");     // "hello" — still the original!
input.setAttribute("value", "new"); // changes the HTML attribute

// For most attributes, properties auto-sync:
input.id;                          // "name"
input.type;                        // "text"

// But for value on inputs, they can diverge!

data-* Attributes (Custom Data)

HTML lets you add custom attributes that start with data-. JavaScript accesses them via the dataset property:

// HTML: <div data-user-id="42" data-role="admin">Idris</div>

const el = document.querySelector("div");

el.dataset.userId;    // "42"     (data-user-id → camelCase: userId)
el.dataset.role;      // "admin"

// Set a new data attribute
el.dataset.active = "true";
// Now the HTML has: data-active="true"

// Delete
delete el.dataset.role;
🧠 Mental Model
data-* attributes are like invisible sticky notes on HTML elements. JavaScript can read and write them. They're perfect for storing metadata that doesn't have a visual purpose — like IDs, states, or configuration.

9. The DOM Is Live

The DOM is not a snapshot — it's a live structure. Changes to JavaScript objects are immediately reflected on screen:

const h1 = document.querySelector("h1");

// Change the text — instantly updates on screen
h1.textContent = "New Title";

// Change the style — instantly updates on screen
h1.style.color = "red";

// Add a class — instantly updates on screen
h1.classList.add("highlight");

// Nothing here is "saved" or "committed".
// The change happens the INSTANT the line executes.
🔄 The Render Pipeline
When you modify the DOM, the browser goes through: DOM change → Style calculation → Layout (reflow) → Paint → Composite. The browser tries to batch these for performance, but some operations (like reading offsetHeight right after changing styles) force an immediate recalculation. This is called forced reflow and it's a performance killer.

10. Where Does <script> Go?

This causes bugs for every beginner. The browser reads HTML top to bottom. If your script runs before the body is parsed, the elements don't exist yet:

// ❌ THIS BREAKS — script runs before <h1> exists
<head>
    <script>
        const h1 = document.querySelector("h1");
        console.log(h1);  // null — the h1 doesn't exist yet!
    </script>
</head>
<body>
    <h1>Hello</h1>
</body>

There are 3 solutions:

Solution 1: Put script at the bottom (simple)

<body>
    <h1>Hello</h1>
    <script src="app.js"></script>  <!-- All elements exist by now -->
</body>

Solution 2: defer attribute (modern standard)

<head>
    <script src="app.js" defer></script>
    <!-- defer = download now, but EXECUTE after HTML is fully parsed -->
</head>

Solution 3: DOMContentLoaded event

<script>
    document.addEventListener("DOMContentLoaded", () => {
        // This code runs after the DOM is fully built
        const h1 = document.querySelector("h1");
        console.log(h1);  // <h1>Hello</h1> ✅
    });
</script>
✅ Best Practice
Use <script src="app.js" defer></script> in the <head>. This is the modern standard. It downloads the script in parallel with HTML parsing, then executes it after the DOM is ready. Fastest option.
Script Loading Comparison: Normal <script> HTML: ██████──────██████████████ JS: ██████ (HTML stops, downloads JS, executes JS, then continues HTML) async HTML: ████████████████████████ JS: ████████ (Downloads in parallel, executes ASAP — can interrupt HTML) defer HTML: ████████████████████████ JS: ████ ████ (Downloads in parallel, executes AFTER HTML is done) ↑ DOMContentLoaded fires here

11. Inspecting The DOM

The browser DevTools (F12) are your best friend for understanding the DOM:

Elements Tab

  • Right-click any element → Inspect — jumps directly to that element in the DOM tree
  • You can edit HTML, classes, styles live in the Elements tab
  • Hover over elements to see their box model (margin, border, padding, content)

Console Tab

// Type these in the console to explore:

document.body;                    // see the body element
document.body.children;           // all children of body
document.querySelector("h1");     // grab any element

// $0 is a special shortcut — it refers to the element
// you currently have selected in the Elements tab
$0;             // the selected element
$0.textContent; // its text
$0.classList;   // its classes

// console.dir shows the element as a JavaScript object
// instead of HTML — so you can see all its properties
console.dir($0);
🔍 Pro Tip: console.dir vs console.log
console.log(element) shows the HTML representation.
console.dir(element) shows the JavaScript object with ALL its properties and methods — this is how you discover what's available.

Key Takeaways

  1. The DOM is not HTML. The DOM is a tree of JavaScript objects the browser builds FROM your HTML.
  2. Everything is a node. Elements, text, comments — all nodes. Use .children (not .childNodes) to skip whitespace text nodes.
  3. document is your entry point. Use querySelector / querySelectorAll to grab elements.
  4. The DOM is live. Change a property → screen updates instantly.
  5. Use defer. Put <script src="app.js" defer> in the <head> so your JS runs after the DOM is ready.
  6. Attributes ≠ Properties. Attributes are the initial HTML values. Properties are the live JavaScript values.
  7. textContent over innerHTML. Use textContent for text. Only use innerHTML when you intentionally want to insert HTML. Never use innerHTML with user input.
  8. console.dir(element) to see an element as a JS object with all its properties.

Lesson 03

Browser Events

Events are how your page comes alive. Every click, keystroke, scroll, hover, form submission — they're all events. This lesson covers how they work, how the browser delivers them, and the patterns that professionals use.

1. What Is An Event?

An event is a signal that something happened. The browser fires events constantly — you just need to listen for the ones you care about.

Events happen all the time: User Actions Browser Events Form Events click DOMContentLoaded submit dblclick load change mouseenter resize input mouseleave scroll focus mousemove error blur keydown online / offline keyup contextmenu Touch Events Drag Events wheel touchstart dragstart touchmove drag touchend drop

Every event follows the same pattern: something happens → the browser creates an Event object → your listener function is called with that object.

2. Adding Event Listeners

The 3 ways (and which to use)

const btn = document.querySelector("#btn");

// ═══════════════════════════════════════════════════════
// WAY 1: addEventListener (✅ USE THIS — always)
// ═══════════════════════════════════════════════════════
btn.addEventListener("click", function(event) {
    console.log("clicked!");
});

// Can add MULTIPLE listeners for the same event
btn.addEventListener("click", handleClick);
btn.addEventListener("click", trackAnalytics);
// Both fire when button is clicked ✅


// ═══════════════════════════════════════════════════════
// WAY 2: onclick property (❌ avoid — overwrites)
// ═══════════════════════════════════════════════════════
btn.onclick = function() { console.log("first"); };
btn.onclick = function() { console.log("second"); };
// Only "second" fires — the first was overwritten! ❌


// ═══════════════════════════════════════════════════════
// WAY 3: HTML attribute (❌ never use — worst option)
// ═══════════════════════════════════════════════════════
// <button onclick="handleClick()"> — mixing HTML and JS
✅ Rule
Always use addEventListener(). It allows multiple listeners, can be removed cleanly, and supports options like capture and once.

Removing Event Listeners

// To remove a listener, you MUST pass the same function reference

function handleClick() {
    console.log("clicked");
}

btn.addEventListener("click", handleClick);
btn.removeEventListener("click", handleClick);  // ✅ same reference

// ❌ THIS DOES NOT WORK:
btn.addEventListener("click", () => console.log("hi"));
btn.removeEventListener("click", () => console.log("hi"));
// These are TWO DIFFERENT anonymous functions — different references!
⚠️ The Anonymous Function Trap
Anonymous arrow functions cannot be removed with removeEventListener. If you ever need to remove a listener, always use a named function.

The "once" Option

// Listener fires ONCE then automatically removes itself
btn.addEventListener("click", () => {
    console.log("This only runs once!");
}, { once: true });

3. The Event Object

When an event fires, the browser creates an Event object and passes it to your listener. This object contains everything about what happened:

btn.addEventListener("click", (event) => {
    console.log(event);  // the full event object — explore this!
});

Properties You'll Use Every Day

PropertyWhat it gives youExample
e.targetThe element that was actually clickedThe <span> inside a <button>
e.currentTargetThe element the listener is attached toThe <button> itself
e.typeThe event type"click", "keydown"
e.timeStampWhen it happened (ms since page load)3421.5
🧠 target vs currentTarget — This will be on the interview
e.target = the deepest element that triggered the event (where you actually clicked).
e.currentTarget = the element that has the listener attached (always this in regular functions).
They are the same ONLY when you click the exact element the listener is on, with no children. 
// HTML: <button id="btn"><span>Click <em>Me</em></span></button>

btn.addEventListener("click", (e) => {
    console.log("target:", e.target);          // <em>Me</em> (what you actually clicked)
    console.log("currentTarget:", e.currentTarget); // <button> (where the listener lives)
});

Mouse Event Properties

document.addEventListener("click", (e) => {
    // Position
    e.clientX;    // X relative to the viewport (visible area)
    e.clientY;    // Y relative to the viewport
    e.pageX;      // X relative to the full page (includes scroll)
    e.pageY;      // Y relative to the full page
    e.offsetX;    // X relative to the target element
    e.offsetY;    // Y relative to the target element

    // Which button
    e.button;     // 0 = left, 1 = middle, 2 = right

    // Modifier keys held down
    e.shiftKey;   // true if Shift was held
    e.ctrlKey;    // true if Ctrl was held
    e.altKey;     // true if Alt was held
    e.metaKey;    // true if Cmd (Mac) or Win key was held
});

Keyboard Event Properties

document.addEventListener("keydown", (e) => {
    e.key;        // "a", "Enter", "ArrowUp", "Escape", " " (space)
    e.code;       // "KeyA", "Enter", "ArrowUp" — physical key position
    e.repeat;     // true if key is being held down

    // Modifier keys
    e.shiftKey;
    e.ctrlKey;
    e.altKey;
    e.metaKey;

    // Common patterns:
    if (e.key === "Escape") closeModal();
    if (e.key === "Enter") submitForm();
    if (e.ctrlKey && e.key === "s") {
        e.preventDefault();  // stop browser's default save
        saveDocument();
    }
});
💡 key vs code
e.key = the character produced ("a", "A" with shift, "é" on French keyboard).
e.code = the physical key ("KeyA" — always the same regardless of keyboard layout).
Use e.key for text input. Use e.code for game controls / shortcuts.

Focus Events

const input = document.querySelector("input");

// focus — when element receives focus (clicked or tabbed into)
input.addEventListener("focus", () => {
    input.parentElement.classList.add("focused");
});

// blur — when element loses focus
input.addEventListener("blur", () => {
    input.parentElement.classList.remove("focused");
    validateField(input);  // validate when user leaves the field
});

// focusin / focusout — same but they BUBBLE (useful for delegation)

Input & Change Events

const input = document.querySelector("input");

// input — fires on EVERY keystroke / change
input.addEventListener("input", (e) => {
    console.log(e.target.value);  // live as you type
});

// change — fires when the value changes AND element loses focus
input.addEventListener("change", (e) => {
    console.log("Final value:", e.target.value);
});

// For checkboxes and selects, "change" fires immediately:
checkbox.addEventListener("change", (e) => {
    console.log("Checked:", e.target.checked);
});
input vs change: User types: h → e → l → l → o → [clicks away] input event fires: "h" "he" "hel" "hell" "hello" (every keystroke) change event fires: "hello" (once, on blur) Use "input" for live search, character counting, live preview. Use "change" for validation after user finishes typing.

Scroll & Resize Events

// scroll — fires VERY rapidly. Always throttle or debounce.
window.addEventListener("scroll", () => {
    const scrollY = window.scrollY;  // how far down you've scrolled
    console.log("Scrolled to:", scrollY);
});

// resize — fires when browser window is resized
window.addEventListener("resize", () => {
    console.log(window.innerWidth, window.innerHeight);
});

// DOMContentLoaded — DOM is ready (before images/CSS finish loading)
document.addEventListener("DOMContentLoaded", () => {
    console.log("DOM ready!");
});

// load — EVERYTHING is loaded (images, CSS, fonts, everything)
window.addEventListener("load", () => {
    console.log("All resources loaded!");
});

5. preventDefault — Stopping Default Behavior

Some elements have built-in behavior. preventDefault() stops that behavior:

ElementDefault behaviorWhy prevent it
<a href="...">Navigate to URLHandle navigation with JS (SPA)
<form> submitReload the pageHandle submission with JS
<input> keydownType the characterBlock certain characters
Right-clickShow context menuCustom context menu
Ctrl+SSave the pageCustom save behavior
// Stop a link from navigating
link.addEventListener("click", (e) => {
    e.preventDefault();
    console.log("Link clicked but didn't navigate");
});

// Stop form from reloading the page
form.addEventListener("submit", (e) => {
    e.preventDefault();
    const data = Object.fromEntries(new FormData(form));
    console.log(data);
});

// Block non-numeric characters in an input
input.addEventListener("keydown", (e) => {
    if (e.key.length === 1 && !/\d/.test(e.key)) {
        e.preventDefault();  // character won't appear
    }
});

// Custom right-click menu
element.addEventListener("contextmenu", (e) => {
    e.preventDefault();
    showCustomMenu(e.clientX, e.clientY);
});

6. Event Propagation — Bubbling & Capturing

This is the most important concept in DOM events. When you click an element, the event doesn't just fire on that element — it travels through the entire DOM tree.

The 3 Phases

You click the <button>. Here's what happens: PHASE 1: CAPTURING (top → down) The event travels DOWN from window to the target: window → document → html → body → div → button ↓ PHASE 2: TARGET The event arrives at the element you clicked: button ← event fires HERE ↓ PHASE 3: BUBBLING (bottom → up) The event travels BACK UP to the top: button → div → body → html → document → window

By default, your listeners fire during the bubbling phase (Phase 3). This means if you click a <button> inside a <div>, the button's listener fires first, THEN the div's listener fires.

// HTML: <div id="outer"> <button id="inner">Click</button> </div>

const outer = document.querySelector("#outer");
const inner = document.querySelector("#inner");

outer.addEventListener("click", () => console.log("outer"));
inner.addEventListener("click", () => console.log("inner"));

// Click the button → output:
// "inner"  ← target phase (the thing you clicked)
// "outer"  ← bubbling phase (the event bubbles UP to parent)
🧠 Mental Model: Bubbling
Imagine dropping a stone in water. The splash starts at the point of impact (the target), then the ripples expand outward (bubbling up through parent elements). Each parent "hears" the event as the ripple passes through it.

Capturing Phase

You can listen during the capturing phase instead (top → down) by passing { capture: true }:

outer.addEventListener("click", () => console.log("outer capture"), { capture: true });
outer.addEventListener("click", () => console.log("outer bubble"));
inner.addEventListener("click", () => console.log("inner"));

// Click button → output:
// "outer capture"  ← capturing phase (top → down)
// "inner"          ← target phase
// "outer bubble"   ← bubbling phase (bottom → up)

stopPropagation — Stop the event from traveling

inner.addEventListener("click", (e) => {
    e.stopPropagation();  // STOP — event will NOT bubble to outer
    console.log("inner only");
});

outer.addEventListener("click", () => {
    console.log("outer");  // This will NEVER fire when button is clicked
});
⚠️ Don't overuse stopPropagation
Stopping propagation breaks event delegation and can cause hard-to-find bugs. Only use it when you have a specific reason. In 95% of cases, you don't need it.

Events that DON'T bubble

Most events bubble, but some don't:

7. Event Delegation — The Most Important Pattern

This is the pattern that separates beginners from professionals. Instead of adding a listener to every child element, you add one listener on the parent and use e.target to figure out what was clicked.

The Problem

// ❌ BAD — one listener per item
const items = document.querySelectorAll(".item");
items.forEach(item => {
    item.addEventListener("click", handleClick);
});

// Problems:
// 1. 1000 items = 1000 listeners = wasted memory
// 2. Dynamically added items DON'T get the listener
// 3. You have to manually add/remove listeners when items change

The Solution: Event Delegation

// ✅ GOOD — one listener on the parent
const list = document.querySelector("#list");

list.addEventListener("click", (e) => {
    // Find the closest .item ancestor of whatever was clicked
    const item = e.target.closest(".item");

    // Guard: if click wasn't on an item, ignore
    if (!item) return;

    // Guard: make sure the item is actually inside our list
    if (!list.contains(item)) return;

    // Now handle the click
    console.log("Clicked item:", item.textContent);
    item.classList.toggle("selected");
});
How delegation works: <ul id="list"> ← ONE listener here <li class="item">Item 1</li> ← click bubbles up to ul <li class="item">Item 2</li> ← click bubbles up to ul <li class="item">Item 3</li> ← click bubbles up to ul <li class="item">NEW ITEM</li> ← added dynamically — STILL WORKS! </ul> Benefits: ✅ 1 listener instead of N ✅ Works with dynamically added items ✅ Less memory, better performance ✅ Cleaner code — one place to handle clicks

The closest() Method — The Key to Delegation

e.target.closest(selector) walks up the DOM from the clicked element and returns the first ancestor matching the selector. If the clicked element itself matches, it returns itself. If nothing matches, it returns null.

// HTML:
// <div class="card">
//   <h3>Title</h3>
//   <p>Text</p>
//   <button class="delete"><span>✕</span></button>
// </div>

// If the user clicks the <span> inside the button:
// e.target = <span>✕</span>
// e.target.closest(".delete") = <button class="delete">
// e.target.closest(".card") = <div class="card">

Real Example: Delegated Delete Buttons

const list = document.querySelector("#todo-list");

list.addEventListener("click", (e) => {
    // Was a delete button clicked?
    const deleteBtn = e.target.closest(".btn-delete");
    if (deleteBtn) {
        const item = deleteBtn.closest(".todo-item");
        item.remove();
        return;
    }

    // Was a done button clicked?
    const doneBtn = e.target.closest(".btn-done");
    if (doneBtn) {
        const item = doneBtn.closest(".todo-item");
        item.classList.toggle("completed");
        return;
    }
});
✅ The Delegation Pattern (memorize this)
parent.addEventListener("click", (e) => {
  const target = e.target.closest(".selector");
  if (!target) return;
  // handle the event
});

8. Custom Events

You can create and dispatch your own custom events — useful for component communication:

// CREATE a custom event
const myEvent = new CustomEvent("userLoggedIn", {
    detail: { username: "Idris", role: "admin" },  // your custom data
    bubbles: true,     // allow it to bubble
    cancelable: true   // allow preventDefault
});

// LISTEN for it
document.addEventListener("userLoggedIn", (e) => {
    console.log("User logged in:", e.detail.username);
    console.log("Role:", e.detail.role);
});

// DISPATCH (fire) it
document.dispatchEvent(myEvent);

9. Real-World Patterns

Pattern 1: Toggle Menu / Modal

const openBtn = document.querySelector("#open-modal");
const closeBtn = document.querySelector("#close-modal");
const modal = document.querySelector("#modal");
const overlay = document.querySelector("#overlay");

function openModal() {
    modal.classList.add("active");
    overlay.classList.add("active");
}

function closeModal() {
    modal.classList.remove("active");
    overlay.classList.remove("active");
}

openBtn.addEventListener("click", openModal);
closeBtn.addEventListener("click", closeModal);
overlay.addEventListener("click", closeModal);  // click outside closes

// Escape key closes
document.addEventListener("keydown", (e) => {
    if (e.key === "Escape") closeModal();
});

Pattern 2: Live Search Filter

const searchInput = document.querySelector("#search");
const items = document.querySelectorAll(".item");

searchInput.addEventListener("input", (e) => {
    const query = e.target.value.toLowerCase();

    items.forEach(item => {
        const text = item.textContent.toLowerCase();
        const match = text.includes(query);
        item.classList.toggle("hidden", !match);  // hide non-matching
    });
});

Pattern 3: Tabs

// HTML:
// <div class="tabs">
//   <button class="tab active" data-tab="tab1">Tab 1</button>
//   <button class="tab" data-tab="tab2">Tab 2</button>
//   <button class="tab" data-tab="tab3">Tab 3</button>
// </div>
// <div class="panel active" id="tab1">Content 1</div>
// <div class="panel" id="tab2">Content 2</div>
// <div class="panel" id="tab3">Content 3</div>

const tabContainer = document.querySelector(".tabs");

// Event delegation — one listener for all tabs
tabContainer.addEventListener("click", (e) => {
    const tab = e.target.closest(".tab");
    if (!tab) return;

    // Deactivate all tabs and panels
    document.querySelectorAll(".tab").forEach(t => t.classList.remove("active"));
    document.querySelectorAll(".panel").forEach(p => p.classList.remove("active"));

    // Activate clicked tab and its panel
    tab.classList.add("active");
    document.querySelector(`#${tab.dataset.tab}`).classList.add("active");
});

Pattern 4: Infinite Scroll

window.addEventListener("scroll", () => {
    // How far we've scrolled + viewport height
    const scrolledTo = window.scrollY + window.innerHeight;
    // Total height of the page
    const pageHeight = document.documentElement.scrollHeight;

    // If we're within 100px of the bottom
    if (pageHeight - scrolledTo < 100) {
        loadMoreContent();  // fetch and append more items
    }
});

Pattern 5: Drag to Reorder (simplified)

const list = document.querySelector("#sortable");
let draggedItem = null;

list.addEventListener("dragstart", (e) => {
    draggedItem = e.target.closest("li");
    draggedItem.classList.add("dragging");
});

list.addEventListener("dragend", () => {
    draggedItem.classList.remove("dragging");
    draggedItem = null;
});

list.addEventListener("dragover", (e) => {
    e.preventDefault();  // required to allow drop
    const afterEl = getDragAfterElement(list, e.clientY);
    if (afterEl) {
        list.insertBefore(draggedItem, afterEl);
    } else {
        list.append(draggedItem);
    }
});

function getDragAfterElement(container, y) {
    const elements = [...container.querySelectorAll("li:not(.dragging)")];
    return elements.reduce((closest, child) => {
        const box = child.getBoundingClientRect();
        const offset = y - box.top - box.height / 2;
        if (offset < 0 && offset > closest.offset) {
            return { offset, element: child };
        }
        return closest;
    }, { offset: -Infinity }).element;
}

10. Event Listener Options

element.addEventListener("click", handler, {
    capture: false,   // listen during capturing phase (default: false)
    once: false,      // auto-remove after first fire (default: false)
    passive: false,   // promise not to call preventDefault (default: false)
    signal: controller.signal  // AbortSignal to remove the listener
});

passive: true — Performance for Scroll/Touch

// For scroll and touch events, setting passive: true
// tells the browser "I won't call preventDefault"
// This allows smooth scrolling without waiting for JS
document.addEventListener("scroll", handleScroll, { passive: true });
document.addEventListener("touchmove", handleTouch, { passive: true });

AbortController — Clean Removal of Multiple Listeners

const controller = new AbortController();

// Add multiple listeners tied to the same controller
btn.addEventListener("click", handleClick, { signal: controller.signal });
btn.addEventListener("mouseenter", handleHover, { signal: controller.signal });
document.addEventListener("keydown", handleKey, { signal: controller.signal });

// Remove ALL of them at once
controller.abort();  // all 3 listeners are removed instantly
🧠 Pro Pattern
AbortController is incredibly useful for cleanup — modals, popup menus, drag operations. When the modal closes, one controller.abort() removes all related listeners. No need to track each one individually.

0 The Problem — Why Async?

JavaScript is single-threaded — one thing at a time. Without async, a 3-second network request would freeze your entire page.

① Synchronous blocking — everything waits

❌ Sync: page freezes
console.log("1. Start");

// Imagine this is a 3-second network call
const data = blockingFetch(); // ← STUCK

// Nothing below runs until fetch is done.
// No clicks. No animations. Nothing.
console.log("2. Got data");
console.log("3. Update UI");
🧊 Browser tab freezes for 3 seconds
✅ Async: page stays alive
console.log("1. Start");

asyncFetch().then(data => {
  console.log("3. Got data"); // later
  console.log("4. Update UI");
});

// This runs IMMEDIATELY — doesn't wait
console.log("2. Fetch started, moving on");
✨ Page stays responsive throughout

② The coffee shop analogy

☕ SYNC (blocking) ☕ ASYNC (non-blocking) ─────────────────────────────────── ─────────────────────────────────── You walk up to the counter. You walk up to the counter. You order a coffee. You order a coffee. You STAND THERE and STARE. You get a NUMBER TICKET and sit down. Nobody else can order. Other customers can order now. Barista hands you the coffee. "Order 47 ready!" — you walk up. You finally leave. You were free the whole time. ❌ result = syncRequest(url) ✅ fetch(url).then(handleResult) ↑ everything stops here ↑ register a callback, walk away

③ Single-threaded but multitasking — the Event Loop

JS Thread: [Task 1]──[Task 2]──────────────────[Task 4]──[Task 5] ↓ registers callback Browser: [fetch running in background ···················] ↓ done Callback Queue: [handleResult queued] ↓ JS Thread: [Task 4 = handleResult()] Key insight: JS itself never "waits". The BROWSER does the waiting. JS registers a callback, continues working, and comes back when the result is ready.

③ Node.js style: error-first callbacks

Convention: callback(error, result)
function readFile(path, callback) {
  setTimeout(() => {
    if (!path) {
      callback(new Error("No path given"));
    } else {
      callback(null, "file contents here");
    }
  }, 200);
}

readFile("./data.txt", (err, data) => {
  if (err) { console.error(err); return; }
  console.log(data);
});
First arg is ALWAYS the error (null if success). Second arg is the result.

2 Promises

A Promise is an object that represents a value that isn't ready yet — it's either pending, fulfilled, or rejected.

pending
⏳ pending

Work in progress

fulfilled
✅ fulfilled

resolve() was called

rejected
❌ rejected

reject() was called

① new Promise((resolve, reject) => ...)

// Create a Promise manually
const myPromise = new Promise((resolve, reject) => {
  // Do some work...
  const success = true;

  if (success) {
    resolve("It worked! 🎉"); // fulfills
  } else {
    reject(new Error("It failed 💥")); // rejects
  }
});
resolve() → Promise becomes fulfilled reject() → Promise becomes rejected Only ONE can be called. Calling both is ignored after the first. Once settled, state NEVER changes. fulfilled → can't become rejected rejected → can't become fulfilled

Simulate async work with setTimeout
function delay(ms) {
  return new Promise(resolve => {
    setTimeout(resolve, ms);

}

// Use it like this:

⑨ Promise.all() — wait for ALL, fail fast if any fails

All succeed → get array of results
const p1 = Promise.resolve("user data");
const p2 = Promise.resolve("post data");
const p3 = Promise.resolve("comment data");

Promise.all([p1, p2, p3])
  .then(([users, posts, comments]) => {
    // All 3 arrived! Use them together
    console.log(users, posts, comments);
  });
// All 3 run in PARALLEL (much faster)
One fails → entire Promise.all() rejects
const p1 = Promise.resolve("ok");
const p2 = Promise.reject(new Error("fail"));
const p3 = Promise.resolve("ok");

Promise.all([p1, p2, p3])
  .then(results => console.log(results))
  .catch(err => {
    // p3's result is lost!
    console.error(err.message); // "fail"
  });

⑩ Promise.allSettled() — wait for all, get ALL results (no fail-fast)

Each result has status + value or reason
Promise.allSettled([
  Promise.resolve("success"),
  Promise.reject(new Error("oops")),
  Promise.resolve("also good")
]).then(results => {
  results.forEach(r => {
    if (r.status === "fulfilled")
      console.log("✅", r.value);
    else
      console.log("❌", r.reason.message);
  });
});
Output
✅ "success" ❌ "oops" ✅ "also good" Never rejects!

⑪ Promise.race() — first one wins

Resolves/rejects with the FIRST settled Promise
const fast = new Promise(res =>
  setTimeout(() => res("fast 🏃"), 500)
);
const slow = new Promise(res =>
  setTimeout(() => res("slow 🐢"), 2000)
);
const timeout = new Promise((_, rej) =>
  setTimeout(() => rej(new Error("Timeout!")), 1000)
);

Promise.race([fast, slow, timeout])
  .then(v => console.log(v)); // "fast 🏃"

3 async / await

async/await is syntactic sugar over Promises — it lets you write async code that reads like sync code, without the callback nesting.

① Basic async function — the keyword

async keyword
async function greet() {
  return "Hello!";
}
Arrow async
const greet = async () => {
  return "Hello!";
};
Method async
const obj = {
  async getData() {
    return 42;
  }
};

② await — pauses until the Promise resolves

await = "wait for this, then continue"
function delay(ms) {
  return new Promise(res => setTimeout(res, ms));
}

async function run() {
  console.log("Start");
  await delay(1000); // ← pauses HERE
  console.log("After 1 second");
  await delay(500);  // ← pauses HERE
  console.log("After 0.5 more seconds");
}
run();

③ async function ALWAYS returns a Promise

return value → Promise.resolve(value)
async function add(a, b) {
  return a + b; // looks sync
}

add(2, 3).then(v => console.log(v)); // 5
// It returned a Promise!
throw → Promise.reject(error)

  throw new Error("Oops");
}

fail().catch(err => {
  console.log(err.message); // "Oops"

⑨ await in forEach DOES NOT WORK — use for...of

❌ forEach ignores await
const ids = [1, 2, 3];

// forEach's callback is async, but
// forEach itself does NOT await them!
ids.forEach(async (id) => {
  const user = await fetchUser(id);
  console.log(user.name); // order = random!
});

console.log("Done"); // runs BEFORE fetches!
✅ for...of respects await
const ids = [1, 2, 3];

async function processAll() {
  for (const id of ids) {
    const user = await fetchUser(id);
    console.log(user.name); // in order!
  }
  console.log("Done"); // runs AFTER all
}
Remember: forEach, map, filter, reduce — none of these "await" their async callbacks. Only for...of loops honour async/await sequentially. Use Promise.all(ids.map(async id => ...)) for parallel.

⑩ Async IIFE — run async code at top level

IIFE = Immediately Invoked Function Expression
// You can't use await at top level
// (unless you use ES Modules)
// Solution: wrap in async IIFE

(async () => {
  const data = await fetchData();
  console.log(data);
})(); // ← called immediately!

// Modern ES Modules support top-level await:
// const data = await fetchData(); // works in .mjs

⑫ Complete: fetch → process → return data

Real-world async data pipeline
async function getUserSummary(userId) {
  try {
    // Step 1: fetch user
    const userRes  = await fetch(`/api/users/${userId}`);
    const user     = await userRes.json();

    // Step 2: fetch their posts
    const postsRes = await fetch(`/api/posts?userId=${userId}`);
    const posts    = await postsRes.json();

    // Step 3: process + return
    return {
      name:      user.name,
      email:     user.email,
      postCount: posts.length
    };
  } catch (err) {
    console.error("Failed to load user:", err);
    return null;
  }
}

4 fetch()

fetch() is the browser's built-in API for HTTP requests — it always returns a Promise.

① Basic GET request

fetch(url) → Promise<Response>
const response = await fetch(
  "https://api.example.com/data"
);
// response is a Response object
// NOT the data yet!

② fetch with .then() chain

Two .then() calls needed
fetch("https://jsonplaceholder.typicode.com/todos/1")
  .then(response => response.json()) // parse body
  .then(data => {
    console.log(data);
    // { id: 1, title: "...", completed: false }
  })
  .catch(err => console.error(err));

③ fetch with async/await — much cleaner

Two await calls — one for response, one for body
async function getTodo(id) {
  const response = await fetch(
    `https://jsonplaceholder.typicode.com/todos/${id}`
  );
  const todo = await response.json();
  console.log(todo.title);
  return todo;
}

④ Why TWO awaits? — Response vs Body

First await: fetch(url) → Resolves when HTTP HEADERS arrive (status code, content-type...) → Returns a Response object (body is still streaming) Second await: response.json() → Reads and PARSES the entire response BODY → Returns the actual JavaScript object you want ┌──────────────────────────────────────────────────────────┐ │ await fetch(url) → Response { status, headers }│ │ ↓ │ │ await response.json() → { id: 1, title: "..." } │ │ or │ │ await response.text() → raw string │ │ await response.blob() → binary file │ └──────────────────────────────────────────────────────────┘

⑤ Always check response.ok before processing

❌ Dangerous — 404 silently parsed as data
const res  = await fetch("/api/user/999");
const data = await res.json();
// data might be { error: "Not Found" }
// fetch() doesn't throw on 404!
✅ Safe — check response.ok first
const res = await fetch("/api/user/999");
if (!res.ok) {
  throw new Error(`HTTP error: ${res.status}`);
}
const data = await res.json();
// Safe to use now
fetch() only rejects on NETWORK failure (offline, DNS fail). HTTP errors like 404 or 500 still RESOLVE — you must check response.ok yourself!

⑥ POST request with JSON body

method + headers + body
async function createPost(post) {
  const res = await fetch(
    "https://jsonplaceholder.typicode.com/posts",
    {
      method:  "POST",
      headers: { "Content-Type": "application/json" },
      body:    JSON.stringify(post)  // ← must stringify!
    }
  );
  if (!res.ok) throw new Error(`Error: ${res.status}`);
  return await res.json();
}

createPost({ title: "Hello", body: "World", userId: 1 })
  .then(data => console.log("Created:", data.id));

⑦ Full error handling with try/catch

Handle both network errors and HTTP errors
async function safeFetch(url) {
  try {
    const res = await fetch(url);

    if (!res.ok) {
      throw new Error(`HTTP ${res.status}: ${res.statusText}`);
    }

    return await res.json();
  } catch (err) {
    if (err.name === "TypeError") {
      console.error("Network error — are you online?");
    } else {
      console.error("Request failed:", err.message);
    }
    return null;
  }
}

5 ES6 Modules

ES6 Modules let you split code across files with export and import — the standard way to organise JavaScript.

① Named export — export individual items

math.js — exporting
// math.js
export const PI = 3.14159;

export function add(a, b) {
  return a + b;
}

export const VERSION = "1.0";

② Named import — import by exact name

app.js — importing
// app.js
import { PI } from './math.js';

console.log(PI); // 3.14159

Export list at the bottom
// utils.js

function sub(a, b) { return a - b; }
const PI = 3.14;

export { add, sub, PI }; // all at once

④ Import multiple named exports

Pick what you need
import { add, sub, PI } from './utils.js';

console.log(add(2, 3)); // 5
console.log(sub(5, 2)); // 3
console.log(PI);         // 3.14

⑤ Default export — one main thing per file

One default per file
// Calculator.js
export default class Calculator {
  add(a, b) { return a + b; }
  sub(a, b) { return a - b; }
}
Or export at bottom

⑥ Default import — no curly braces, choose any name

No braces — name it anything

  • In a Promise chain, each .then() callback has its OWN scope — variables don't leak to later .then() calls
  • With async/await, all variables are in the same function scope — user stays accessible
  • Use const user = await ... then const posts = await ... on separate lines
SOLUTION — Bug explained + async/await fix
// BUG: Each .then() callback has its own closure.
// 'user' is only accessible in the 2nd .then().
// The 4th .then() (posts => ...) can't see 'user'.

// FIX: Convert to async/await — variables share scope
async function getUserPosts(userId) {
  try {
    const userRes = await fetch(
      `https://jsonplaceholder.typicode.com/users/${userId}`
    );
    if (!userRes.ok) throw new Error(`HTTP ${userRes.status}`);
    const user = await userRes.json();  // ← user is in scope

    const postsRes = await fetch(
      `https://jsonplaceholder.typicode.com/posts?userId=${user.id}`
    );
    if (!postsRes.ok) throw new Error(`HTTP ${postsRes.status}`);
    const posts = await postsRes.json();

    return {
      userName:  user.name,  // ✅ user is accessible here!
      postCount: posts.length
    };
  } catch (err) {
    console.error("Failed:", err.message);
    return null;
  }
}

// Test it:
getUserPosts(1).then(result => console.log(result));
// { userName: "Leanne Graham", postCount: 10 }

Promise States

⏳ pending

Neither resolved nor rejected yet. The initial state.

✅ fulfilled

resolve() was called. .then() handlers fire.

❌ rejected

reject() was called. .catch() handler fires.

async/await Syntax Cheat Sheet

// Declare
async function myFn() {}
const myFn = async () => {}
const obj = { async method() {} }

// Use inside async function
const result = await somePromise;
const [a, b] = await Promise.all([p1, p2]);

// Error handling
try { await ... } catch (err) { ... }
// Async always returns Promise
async function add() { return 5; }
add()  // → Promise.resolve(5)

// Call from non-async
myFn().then(result => ...)
myFn().catch(err => ...)

// Top-level: async IIFE
(async () => { await ... })()

fetch() 4-Step Pattern

async function getData(url) {
  try {
    const res  = await fetch(url);          // Step 1: send request
    if (!res.ok) throw new Error(res.status); // Step 2: check status
    const data = await res.json();           // Step 3: parse body
    return data;
  } catch (err) {                             // Step 4: handle errors
    console.error(err); return null;
  }
}

Common Mistakes

❌ Mistake ✅ Fix
await fetch() outside async function Wrap in async function or use async IIFE
Not checking response.ok Always check: if (!res.ok) throw new Error(...)
await inside forEach Use for...of or Promise.all(arr.map(async ...))
Sequential awaits for independent data Use Promise.all() to run in parallel
Forgetting second await response.json() fetch gives you a Response — body needs a second await
Using async but forgetting await Without await you get a pending Promise, not the value
Variable from Promise chain out of scope Use async/await — all vars share the same function scope

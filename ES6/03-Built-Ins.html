3.1 Symbols

What is a Symbol?

A Symbol is a new primitive type introduced in ES6 (alongside string, number, boolean, null, undefined). Every Symbol is unique. Even if two Symbols have the same description, they are never equal. Their primary purpose: creating guaranteed-unique object property keys that cannot collide with other properties.

const s1 = Symbol();
const s2 = Symbol();
console.log(s1 === s2); // false — every Symbol is unique

// You can give a description (just for debugging, not identity)
const id = Symbol("userId");
console.log(id);           // Symbol(userId)
console.log(id.description); // "userId"

// Same description, still different Symbols
const a = Symbol("key");
const b = Symbol("key");
console.log(a === b); // false

// ⚠️ Symbols are NOT created with 'new'
new Symbol(); // TypeError: Symbol is not a constructor

Symbols as Object Keys (Hidden Properties)

When you use a Symbol as an object key, it is invisible to for...in, Object.keys(), and JSON.stringify(). This makes them perfect for internal/private-like properties.

const SECRET = Symbol("secret");

const user = {
    name: "Idris",
    age: 25,
    [SECRET]: "hidden_token_123"
};

// Normal access works with the Symbol reference
console.log(user[SECRET]); // "hidden_token_123"

// But it's invisible to standard iteration:
console.log(Object.keys(user));       // ["name", "age"] — no SECRET
console.log(JSON.stringify(user));    // {"name":"Idris","age":25} — no SECRET
for (const key in user) { console.log(key); } // "name", "age" — no SECRET

// To find Symbol keys specifically:
console.log(Object.getOwnPropertySymbols(user)); // [Symbol(secret)]

Well-Known Symbols

JavaScript has built-in Symbols that let you customize how objects behave with language operators. These are called "well-known Symbols."

// Symbol.iterator — makes an object work with for...of
// Symbol.toPrimitive — controls how an object converts to a number or string
// Symbol.hasInstance — customizes instanceof behavior

// Example: Custom toPrimitive
const wallet = {
    currency: "USD",
    amount: 100,
    [Symbol.toPrimitive](hint) {
        if (hint === "number") return this.amount;
        if (hint === "string") return `${this.amount} ${this.currency}`;
        return this.amount;
    }
};

console.log(+wallet);            // 100 (number hint)
console.log(`Balance: ${wallet}`); // "Balance: 100 USD" (string hint)
console.log(wallet + 50);        // 150 (default hint → number)

Symbol.for() — The Global Symbol Registry

If you need to share a Symbol across different files or modules, use Symbol.for("key"). It creates a Symbol in a global registry. If a Symbol with that key already exists in the registry, it returns the existing one.

const s1 = Symbol.for("app.id");
const s2 = Symbol.for("app.id");
console.log(s1 === s2); // true! Same Symbol from the registry.

// Reverse lookup: find the key for a global Symbol
console.log(Symbol.keyFor(s1)); // "app.id"

// Symbol() without .for() is NOT in the registry
const local = Symbol("app.id");
console.log(Symbol.keyFor(local)); // undefined

3.2 Iteration & Iterable Protocols

Two Protocols, One System

ES6 defines two protocols that work together to enable iteration across the language:

  1. The Iterator Protocol — defines how to produce a sequence of values, one at a time.
  2. The Iterable Protocol — defines how an object advertises that it CAN be iterated.
🧠 Mental Model
An iterable is like a book. It knows it has pages.
An iterator is like a bookmark inside that book. It knows which page you're on and what the next page is.

The Iterator Protocol

An iterator is any object that has a next() method. Each call to next() returns an object with two properties: value (the current value) and done (whether the sequence is finished).

// Building an iterator from scratch
function createCounter(start, end) {
    let current = start;
    return {
        next() {
            if (current <= end) {
                return { value: current++, done: false };
            }
            return { value: undefined, done: true };
        }
    };
}

const counter = createCounter(1, 4);
console.log(counter.next()); // { value: 1, done: false }
console.log(counter.next()); // { value: 2, done: false }
console.log(counter.next()); // { value: 3, done: false }
console.log(counter.next()); // { value: 4, done: false }
console.log(counter.next()); // { value: undefined, done: true }
console.log(counter.next()); // { value: undefined, done: true } (stays done)

The Iterable Protocol

An iterable is any object that implements [Symbol.iterator]() — a method that returns a fresh iterator every time it's called. This is the protocol that for...of, the spread operator ..., destructuring, Array.from(), Promise.all(), and new Map()/new Set() all use under the hood.

How for...of Works Under the Hood

const arr = ["a", "b", "c"];

// What you write:
for (const item of arr) {
    console.log(item);
}

// What the engine actually does:
const iterator = arr[Symbol.iterator](); // Get the iterator
let result = iterator.next();
while (!result.done) {
    console.log(result.value); // "a", "b", "c"
    result = iterator.next();
}

Making a Custom Object Iterable

const range = {
    start: 1,
    end: 5,

    // This method is called by for...of, spread, destructuring, etc.
    [Symbol.iterator]() {
        let current = this.start;
        const end = this.end;
        return {
            next() {
                return current <= end
                    ? { value: current++, done: false }
                    : { value: undefined, done: true };
            }
        };
    }
};

// Now it works with EVERYTHING that consumes iterables:
for (const n of range) { console.log(n); } // 1, 2, 3, 4, 5
const arr = [...range];                     // [1, 2, 3, 4, 5]
const [first, second] = range;               // 1, 2
const s = new Set(range);                   // Set {1, 2, 3, 4, 5}

Making a Class Iterable

class Playlist {
    constructor(...songs) {
        this.songs = songs;
    }

    [Symbol.iterator]() {
        let index = 0;
        const songs = this.songs;
        return {
            next() {
                return index < songs.length
                    ? { value: songs[index++], done: false }
                    : { done: true };
            }
        };
    }
}

const myPlaylist = new Playlist("Song A", "Song B", "Song C");

for (const song of myPlaylist) {
    console.log(`Now playing: ${song}`);
}
// "Now playing: Song A"
// "Now playing: Song B"
// "Now playing: Song C"

console.log([...myPlaylist]); // ["Song A", "Song B", "Song C"]
💡 Key Insight: Reusability
[Symbol.iterator]() returns a new iterator each time. This means you can iterate over the same iterable multiple times. Each for...of loop gets its own fresh iterator. 
for (const n of range) { console.log(n); } // 1, 2, 3, 4, 5
for (const n of range) { console.log(n); } // 1, 2, 3, 4, 5 (works again!)

3.3 Generators

What is a Generator?

A generator is a special function that can pause its execution and resume later. It uses the function* syntax and the yield keyword. Each time you call .next(), the function runs until the next yield, then pauses. Calling the generator function does NOT execute its body — it returns a generator object.

🧠 Mental Model
Think of a generator like a bookmark in a book. Each time you call .next(), you read until the next bookmark (yield), then you stop and close the book. When you call .next() again, you pick up exactly where you left off.

Basic Generator Syntax

function* countdown() {
    console.log("3...");
    yield 3;   // Pause #1 — return 3
    console.log("2...");
    yield 2;   // Pause #2 — return 2
    console.log("1...");
    yield 1;   // Pause #3 — return 1
    console.log("Go!");
    return 0; // done: true, value: 0
}

// Calling the function does NOT run the body!
const gen = countdown(); // Returns a Generator Object

console.log(gen.next()); // "3..." → { value: 3, done: false }
console.log(gen.next()); // "2..." → { value: 2, done: false }
console.log(gen.next()); // "1..." → { value: 1, done: false }
console.log(gen.next()); // "Go!" → { value: 0, done: true }
console.log(gen.next()); //        → { value: undefined, done: true }

All Valid Syntax Positions for the *

function* gen1() {}   // ✅ Most common
function *gen2() {}   // ✅ Also valid
function*gen3() {}    // ✅ Also valid

// As object methods
const obj = {
    *myGen() { yield 1; }
};

// As class methods
class MyClass {
    *items() { yield 1; yield 2; }
}

// ❌ Arrow functions CANNOT be generators
// const gen = *() => {};  // SyntaxError

Generators are Automatically Iterable

Every generator object implements both the iterator protocol (has .next()) AND the iterable protocol (has [Symbol.iterator]()). This means they work with for...of, spread, and destructuring out of the box.

function* colors() {
    yield "red";
    yield "green";
    yield "blue";
}

// for...of
for (const c of colors()) { console.log(c); } // red, green, blue

// Spread
const arr = [...colors()]; // ["red", "green", "blue"]

// Destructuring
const [first, second] = colors(); // "red", "green"
⚠️ for...of Ignores the return value!
for...of only reads yield values. The return value (where done: true) is NOT included in the loop. To capture it, you must call .next() manually. 
function* test() {
    yield 1;
    yield 2;
    return 3; // This is the "done" value
}

for (const v of test()) { console.log(v); }
// Only prints: 1, 2  (NOT 3)

// To get the return value, use .next() manually:
const g = test();
g.next(); // { value: 1, done: false }
g.next(); // { value: 2, done: false }
g.next(); // { value: 3, done: true }  ← return value captured

Infinite Data Streams

Generators can represent infinite sequences without consuming infinite memory. They produce values lazily (on demand).

// Infinite Fibonacci sequence
function* fibonacci() {
    let a = 0, b = 1;
    while (true) {  // Infinite loop — but it's safe because we yield!
        yield a;
        [a, b] = [b, a + b];
    }
}

// Take only what you need
const fib = fibonacci();
console.log(fib.next().value); // 0
console.log(fib.next().value); // 1
console.log(fib.next().value); // 1
console.log(fib.next().value); // 2
console.log(fib.next().value); // 3

// Infinite ID generator
function* idMaker(prefix = "id") {
    let n = 1;
    while (true) {
        yield `${prefix}_${n++}`;
    }
}

const userId = idMaker("user");
console.log(userId.next().value); // "user_1"
console.log(userId.next().value); // "user_2"
console.log(userId.next().value); // "user_3"

Sending Values INTO a Generator

You can pass a value into .next(value). That value becomes the result of the yield expression inside the generator. The first .next() call cannot send data (there's no yield waiting to receive it yet).

function* conversation() {
    const name = yield "What is your name?";
    const age  = yield `Hi ${name}! How old are you?`;
    return `${name} is ${age} years old.`;
}

const chat = conversation();
console.log(chat.next());          // { value: "What is your name?", done: false }
console.log(chat.next("Idris"));  // { value: "Hi Idris! How old are you?", done: false }
console.log(chat.next(25));      // { value: "Idris is 25 years old.", done: true }

yield* — Delegating to Another Generator

yield* delegates iteration to another iterable or generator. It's like saying "yield everything from this other source before continuing."

function* inner() {
    yield "b";
    yield "c";
}

function* outer() {
    yield "a";
    yield* inner();  // Delegate to inner generator
    yield "d";
}

console.log([...outer()]); // ["a", "b", "c", "d"]

// yield* works with ANY iterable, not just generators:
function* mixed() {
    yield* [1, 2];     // Delegate to an array
    yield* "hi";       // Delegate to a string
    yield* new Set([3]); // Delegate to a Set
}
console.log([...mixed()]); // [1, 2, "h", "i", 3]

Recursive Generators with yield*

// Flatten a deeply nested array
function* flatten(arr) {
    for (const item of arr) {
        if (Array.isArray(item)) {
            yield* flatten(item); // Recurse!
        } else {
            yield item;
        }
    }
}

const nested = [1, [2, [3, 4]], [5, 6]];
console.log([...flatten(nested)]); // [1, 2, 3, 4, 5, 6]

Early Termination: .return() and .throw()

You can force a generator to stop early with .return(), or inject an error with .throw().

function* count() {
    yield 1;
    yield 2;
    yield 3;
}

// .return() — force the generator to finish
const g1 = count();
g1.next();           // { value: 1, done: false }
g1.return("STOP");  // { value: "STOP", done: true }
g1.next();           // { value: undefined, done: true } (generator is dead)

// .throw() — inject an error into the generator
function* safe() {
    try {
        yield 1;
        yield 2;
    } catch (e) {
        console.log(`Caught: ${e}`);
    }
}

const g2 = safe();
g2.next();                  // { value: 1, done: false }
g2.throw("Something broke"); // "Caught: Something broke"

3.3b Generators & Iterators Together

Generators as a Shortcut for Iterables

Remember how much code it took to make a custom iterable in section 3.2? Generators make it drastically simpler. Instead of manually creating an iterator object with next(), you just write a generator function and yield your values.

// ❌ WITHOUT generators (verbose — we had to do this in 3.2)
const range = {
    start: 1,
    end: 5,
    [Symbol.iterator]() {
        let current = this.start;
        const end = this.end;
        return {
            next() {
                return current <= end
                    ? { value: current++, done: false }
                    : { done: true };
            }
        };
    }
};

// ✅ WITH generators (clean and simple)
const rangeGen = {
    start: 1,
    end: 5,
    *[Symbol.iterator]() {
        for (let i = this.start; i <= this.end; i++) {
            yield i;
        }
    }
};

console.log([...rangeGen]); // [1, 2, 3, 4, 5]

Making a Class Iterable with a Generator

class TodoList {
    constructor() { this.items = []; }
    add(item) { this.items.push(item); }

    // Generator as Symbol.iterator — makes the class iterable
    *[Symbol.iterator]() {
        for (const item of this.items) {
            yield item;
        }
    }
}

const todos = new TodoList();
todos.add("Learn ES6");
todos.add("Build a project");
todos.add("Get hired");

for (const todo of todos) {
    console.log(`☐ ${todo}`);
}
// ☐ Learn ES6
// ☐ Build a project
// ☐ Get hired

Practical Pattern: Paginated Data

// Simulate fetching paginated data from an API
function* fetchPages(totalPages) {
    for (let page = 1; page <= totalPages; page++) {
        // In real code, this would be: const data = await fetch(...);
        const data = { page, items: [`Item ${page}a`, `Item ${page}b`] };
        yield data;
    }
}

const pages = fetchPages(3);

// Consume pages lazily — only process them when needed
console.log(pages.next().value); // { page: 1, items: ["Item 1a", "Item 1b"] }
console.log(pages.next().value); // { page: 2, items: ["Item 2a", "Item 2b"] }
// Page 3 is never even created unless we call .next() again!

Q1: Write a generator function called range(start, end, step) that yields numbers from start to end (inclusive), incrementing by step. Default step is 1.

// range(1, 10, 2) → 1, 3, 5, 7, 9

Answer

function* range(start, end, step = 1) {
    for (let i = start; i <= end; i += step) {
        yield i;
    }
}

console.log([...range(1, 10, 2)]); // [1, 3, 5, 7, 9]

yield* Delegation

Q2: What is the output?

function* a() {
    yield 1;
    yield* [2, 3];
    yield 4;
}

function* b() {
    yield* a();
    yield 5;
}

console.log([...b()]);

Quiz

Sending Data

Q3: What does result equal?

function* calc() {
    const x = yield "Enter x:";
    const y = yield "Enter y:";
    return x + y;
}

const g = calc();
g.next();
g.next(10);
const result = g.next(20);

Answer

{ value: 30, done: true }. The first .next() runs until the first yield and returns "Enter x:". The second .next(10) sends 10 into the generator — x becomes 10 — and runs to the second yield. The third .next(20) sends 20 — y becomes 20 — and hits the return: x + y = 30.

3.4 Sets

What is a Set?

A Set is a collection of unique values. No duplicates are allowed. Values can be any type (primitives or objects). Sets maintain insertion order.

const s = new Set();

// Adding values
s.add(1);
s.add(2);
s.add(3);
s.add(2); // Ignored! 2 already exists.
s.add(1); // Ignored! 1 already exists.

console.log(s.size); // 3 (not 5)
console.log(s);      // Set(3) {1, 2, 3}

// Create from an array (instant deduplication!)
const unique = new Set([1, 1, 2, 2, 3, 3]);
console.log([...unique]); // [1, 2, 3]

Complete Set API

const colors = new Set(["red", "green", "blue"]);

colors.add("yellow");      // Add a value
colors.delete("green");   // Remove a value → true (was found)
colors.has("red");        // Check existence → true
colors.has("green");      // → false (was deleted)
console.log(colors.size); // 3

// Iteration
for (const color of colors) { console.log(color); }
colors.forEach(c => console.log(c));

colors.clear(); // Remove everything

Real-World Set Patterns

Pattern 1: Remove Array Duplicates (One-liner)

const nums = [5, 3, 5, 1, 3, 9, 1];
const unique = [...new Set(nums)]; // [5, 3, 1, 9]

Pattern 2: Set Operations (Union, Intersection, Difference)

const a = new Set([1, 2, 3, 4]);
const b = new Set([3, 4, 5, 6]);

// Union (all items from both)
const union = new Set([...a, ...b]); // {1, 2, 3, 4, 5, 6}

// Intersection (only items in both)
const inter = new Set([...a].filter(x => b.has(x))); // {3, 4}

// Difference (items in A but not in B)
const diff = new Set([...a].filter(x => !b.has(x))); // {1, 2}

Pattern 3: Tracking Visited Items

const visited = new Set();

function visitPage(url) {
    if (visited.has(url)) {
        console.log(`Already visited ${url}`);
        return;
    }
    visited.add(url);
    console.log(`First visit to ${url}`);
}
⚠️ Set Uses Strict Equality (===) with one exception
Sets compare values using ===, but they treat NaN === NaN as true (unlike normal JS where NaN !== NaN). Object references are compared, not contents — two different objects with the same properties are still two different Set entries. 
const s = new Set();
s.add(NaN);
s.add(NaN);
console.log(s.size); // 1 (NaN is deduplicated)

const obj1 = { id: 1 };
const obj2 = { id: 1 };
s.add(obj1);
s.add(obj2);
console.log(s.size); // 3 (obj1 and obj2 are different references)

3.5 WeakSets

A WeakSet is like a Set, but with three critical differences:

  1. Only objects can be stored (no primitives like numbers or strings).
  2. Weak references: if the object stored in a WeakSet is garbage collected (no other reference exists), the WeakSet entry is automatically removed.
  3. Not iterable: you cannot loop over a WeakSet or check its size.
const ws = new WeakSet();

let user = { name: "Idris" };
ws.add(user);
console.log(ws.has(user)); // true

user = null; // The original object has no more references.
// The WeakSet entry is automatically garbage collected.

// WeakSets CANNOT store primitives
ws.add(42);     // TypeError: Invalid value used in weak set
ws.add("text"); // TypeError

Real-World Use: Tracking Object State

// Track which DOM elements have been initialized
const initialized = new WeakSet();

function initWidget(element) {
    if (initialized.has(element)) return; // Already done
    initialized.add(element);
    // ...heavy initialization work...
}
// When the DOM element is removed, it's garbage collected,
// and the WeakSet entry disappears automatically. No memory leak!

3.6 Maps

What is a Map?

A Map is a collection of key-value pairs where keys can be ANY type (objects, functions, DOM elements — not just strings). Maps maintain insertion order and have a .size property.

🧠 Map vs Object
Plain objects only support string (or Symbol) keys. Maps support any type as a key. Maps are also faster for frequent additions/deletions and give you .size directly. 
const m = new Map();

// Set key-value pairs
m.set("name", "Idris");        // string key
m.set(42, "the answer");        // number key
m.set(true, "boolean key!");   // boolean key

const objKey = { id: 1 };
m.set(objKey, "object as key!"); // object key

const btn = document.querySelector("button");
m.set(btn, { clicks: 0 });       // DOM element key!

// Get values
console.log(m.get("name"));  // "Idris"
console.log(m.get(42));      // "the answer"
console.log(m.get(objKey)); // "object as key!"

// Other methods
m.has(42);          // true
m.delete(42);       // removes the entry
console.log(m.size); // 3

Creating a Map from an Array

// Pass an array of [key, value] pairs
const scores = new Map([
    ["Idris", 95],
    ["Ali", 88],
    ["Omar", 72]
]);

console.log(scores.get("Ali")); // 88

Iterating Over a Map

const m = new Map([["a", 1], ["b", 2], ["c", 3]]);

// for...of with destructuring (the cleanest way)
for (const [key, value] of m) {
    console.log(`${key}: ${value}`);
}

// Individual iterators
console.log([...m.keys()]);    // ["a", "b", "c"]
console.log([...m.values()]);  // [1, 2, 3]
console.log([...m.entries()]); // [["a",1], ["b",2], ["c",3]]

// forEach
m.forEach((value, key) => console.log(key, value));

Converting Between Map and Object

// Object → Map
const obj = { x: 10, y: 20 };
const map = new Map(Object.entries(obj));

// Map → Object
const backToObj = Object.fromEntries(map);
console.log(backToObj); // { x: 10, y: 20 }

3.7 WeakMaps

A WeakMap is like a Map with the same three restrictions as WeakSet:

  1. Keys must be objects (no primitive keys).
  2. Weak references: if the key object is garbage collected, the entry is removed.
  3. Not iterable: no .size, no for...of, no .keys().

Real-World Use: Private Data for Objects

// Store private data that automatically cleans up
const privateData = new WeakMap();

class User {
    constructor(name, password) {
        this.name = name;
        // Store password in a WeakMap keyed by 'this'
        privateData.set(this, { password });
    }

    checkPassword(attempt) {
        return privateData.get(this).password === attempt;
    }
}

let user = new User("Idris", "secret123");
console.log(user.checkPassword("secret123")); // true
console.log(user.password); // undefined — not on the object!

user = null; // User is garbage collected → WeakMap entry auto-removed

Real-World Use: Caching Expensive Computations

const cache = new WeakMap();

function expensiveProcess(obj) {
    if (cache.has(obj)) {
        console.log("From cache!");
        return cache.get(obj);
    }
    const result = /* heavy computation */ obj.data * 2;
    cache.set(obj, result);
    return result;
}
// When the object is garbage collected, the cached result disappears too.

3.8 Promises (Deep Dive)

What is a Promise?

A Promise is an object that represents a value that doesn't exist yet but will (or won't) at some point in the future. It has three states:

  1. Pending — the operation hasn't finished yet.
  2. Fulfilled (Resolved) — the operation succeeded, and a value is available.
  3. Rejected — the operation failed, and an error is available.
🧠 Mental Model
A Promise is like ordering food at a restaurant. You get a receipt (the Promise). The food isn't ready yet (pending). Eventually, the kitchen either delivers your food (fulfilled) or tells you they're out of that dish (rejected).

Creating a Promise

const myPromise = new Promise((resolve, reject) => {
    // Simulate an async operation (e.g., API call)
    const success = true;

    setTimeout(() => {
        if (success) {
            resolve("Data loaded!");  // → Fulfilled
        } else {
            reject("Network error"); // → Rejected
        }
    }, 1000);
});

// Consuming the Promise
myPromise
    .then(data => console.log(data))    // "Data loaded!"
    .catch(err => console.log(err))    // only runs if rejected
    .finally(() => console.log("Done")); // always runs

Promise Chaining

Each .then() returns a new Promise, allowing you to chain operations. The value returned from one .then() is passed to the next.

fetch("/api/user/1")
    .then(response => response.json())   // Parse JSON (returns a new Promise)
    .then(user => {
        console.log(user.name);
        return fetch(`/api/posts/${user.id}`); // Fetch user's posts
    })
    .then(response => response.json())
    .then(posts => console.log(posts))
    .catch(err => console.log("Error:", err)); // Catches ANY error in the chain

Promise.all() — Run in Parallel, Wait for All

Runs multiple Promises simultaneously. Resolves when ALL succeed. Rejects immediately if ANY one fails.

const p1 = fetch("/api/users");
const p2 = fetch("/api/posts");
const p3 = fetch("/api/comments");

Promise.all([p1, p2, p3])
    .then(([users, posts, comments]) => {
        console.log("All loaded!");
    })
    .catch(err => {
        console.log("One failed:", err); // First failure kills everything
    });

Promise.allSettled() — Wait for All, Don't Fail Early

Waits for ALL Promises to finish (fulfilled or rejected). Never short-circuits.

const results = await Promise.allSettled([
    fetch("/api/a"),
    fetch("/api/broken"),
    fetch("/api/c")
]);

// results = [
//   { status: "fulfilled", value: Response },
//   { status: "rejected",  reason: Error },
//   { status: "fulfilled", value: Response }
// ]

Promise.race() — First to Finish Wins

// Timeout pattern: race a fetch against a timer
const timeout = new Promise((_, reject) => {
    setTimeout(() => reject("Timeout!"), 5000);
});

Promise.race([fetch("/api/data"), timeout])
    .then(res => console.log("Data received"))
    .catch(err => console.log(err)); // "Timeout!" if fetch takes > 5s

Promise.any() — First to SUCCEED Wins

Like race(), but ignores rejections. Only rejects if ALL Promises reject.

// Try multiple CDN mirrors, use whichever responds first
Promise.any([
    fetch("https://cdn1.example.com/data"),
    fetch("https://cdn2.example.com/data"),
    fetch("https://cdn3.example.com/data")
]).then(fastest => console.log("Got data from fastest mirror"));

async / await (The Modern Way)

async/await is syntactic sugar over Promises. It makes async code look and behave like synchronous code.

// With .then() chains
fetch("/api/user/1")
    .then(res => res.json())
    .then(user => console.log(user))
    .catch(err => console.log(err));

// With async/await (same logic, way cleaner)
async function getUser() {
    try {
        const res = await fetch("/api/user/1");
        const user = await res.json();
        console.log(user);
    } catch (err) {
        console.log(err);
    }
}

Parallel async/await

// ❌ Sequential (slow) — waits for each before starting next
const users = await fetch("/api/users");
const posts = await fetch("/api/posts"); // waits for users to finish first!

// ✅ Parallel (fast) — fires both at the same time
const [users, posts] = await Promise.all([
    fetch("/api/users"),
    fetch("/api/posts")
]);
Quiz

Promises

Q1: What is the output order?

console.log("A");
Promise.resolve().then(() => console.log("B"));
console.log("C");
setTimeout(() => console.log("D"), 0);
Promise.resolve().then(() => console.log("E"));

Answer

A, C, B, E, D

Sync first (A, C). Then microtasks (Promise.then → B, E). Then macrotask (setTimeout → D).

Quiz

Promise.all vs Promise.allSettled

Q2: You need to fetch data from 3 APIs. One of them might fail, but you still want the results from the other two. Which do you use?

Answer

Promise.allSettled(). Promise.all() would reject the entire batch if even one fails. allSettled() waits for all to finish and tells you which succeeded and which failed.

3.9 Proxies

What is a Proxy?

A Proxy wraps an object and lets you intercept and redefine fundamental operations on that object: reading properties, writing properties, deleting properties, function calls, and more. It's like putting a security guard in front of an object.

const user = { name: "Idris", age: 25 };

const handler = {
    // Intercept property reads
    get(target, prop) {
        console.log(`Reading "${prop}"`);
        return prop in target ? target[prop] : `Property "${prop}" not found`;
    },

    // Intercept property writes
    set(target, prop, value) {
        console.log(`Writing "${prop}" = ${value}`);
        if (prop === "age" && typeof value !== "number") {
            throw new TypeError("Age must be a number");
        }
        target[prop] = value;
        return true;
    }
};

const proxy = new Proxy(user, handler);

proxy.name;              // Reading "name" → "Idris"
proxy.nonExistent;       // Reading "nonExistent" → 'Property "nonExistent" not found'
proxy.age = 26;          // Writing "age" = 26
proxy.age = "twenty";   // TypeError: Age must be a number

Real-World Use: Validation

function createValidated(schema) {
    return new Proxy({}, {
        set(target, prop, value) {
            if (schema[prop] && typeof value !== schema[prop]) {
                throw new TypeError(`${prop} must be a ${schema[prop]}`);
            }
            target[prop] = value;
            return true;
        }
    });
}

const user = createValidated({ name: "string", age: "number" });
user.name = "Idris"; // ✅
user.age = 25;       // ✅
user.age = "old";   // TypeError: age must be a number

Real-World Use: Negative Array Indexing

function negativeArray(arr) {
    return new Proxy(arr, {
        get(target, prop) {
            const index = Number(prop);
            if (index < 0) {
                return target[target.length + index];
            }
            return target[prop];
        }
    });
}

const arr = negativeArray(["a", "b", "c", "d"]);
console.log(arr[-1]); // "d" (last item)
console.log(arr[-2]); // "c" (second to last)

3.10 Module Summary

Built-InWhat You Know Now
SymbolsUnique primitives for object keys. Hidden from Object.keys() and for...in. Well-known Symbols customize language behavior (Symbol.iterator, Symbol.toPrimitive). Symbol.for() for global registry.
IteratorsObjects with a next() method returning { value, done }. Iterables implement [Symbol.iterator]() to work with for...of, spread, and destructuring.
Generatorsfunction* with yield. Pausable functions. Automatically iterable. Can receive values via .next(value). Perfect for infinite sequences and lazy evaluation.
SetUnique-value collection. add, has, delete, size. One-liner dedup: [...new Set(arr)]. Uses === but treats NaN === NaN.
WeakSetObjects only. Weak references (auto-cleanup). Not iterable. Use: tracking object state without memory leaks.
MapKey-value pairs with any key type. Ordered. .size. Natively iterable. Convert: Object.entries() ↔ Object.fromEntries().
WeakMapObject keys only. Weak references. Not iterable. Use: private data, caching.
PromisesPending → Fulfilled/Rejected. Chain with .then(). Error handling with .catch(). Promise.all (all or fail), allSettled (all, no fail), race (first done), any (first success). async/await is syntactic sugar.
ProxiesIntercept object operations (get, set, has, delete, etc.). Use: validation, logging, negative indexing, reactive systems (Vue.js uses Proxies internally).

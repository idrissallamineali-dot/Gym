ES6 Functions: The Complete Deep Dive

Arrow functions, default parameters, destructured parameters, JavaScript classes, inheritance, and the this keyword — the concept that breaks 90% of JavaScript developers.

2.1 Arrow Functions

The Evolution of Function Syntax

ES6 introduced arrow functions (=>) as a shorter way to write functions. But they're not just syntactic sugar — they behave fundamentally differently regarding this (we'll cover that deeply in section 2.11).

Step 1: From function declaration to arrow

// 1. Function Declaration (ES5)
function add(a, b) {
    return a + b;
}

// 2. Function Expression (ES5)
const add = function(a, b) {
    return a + b;
};

// 3. Arrow Function (ES6)
const add = (a, b) => {
    return a + b;
};

Step 2: Implicit Return (The Concise Body)

If the function body is a single expression, you can remove the curly braces {} AND the return keyword. The expression's result is automatically returned.

// With block body (explicit return)
const add = (a, b) => { return a + b; };

// With concise body (implicit return) — same result
const add = (a, b) => a + b;

Step 3: Single Parameter — Drop the Parentheses

If the function takes exactly ONE parameter, the parentheses are optional.

// With parentheses
const double = (n) => n * 2;

// Without parentheses (only for single param)
const double = n => n * 2;

// Zero parameters — parentheses REQUIRED
const greet = () => "Hello!";

// Two+ parameters — parentheses REQUIRED
const add = (a, b) => a + b;

The Object Return Trap

This trips up EVERYONE. When you want to implicitly return an object literal, you must wrap it in parentheses. Otherwise JavaScript thinks the curly braces are the function body.

// ❌ BUG: The engine sees {} as a function body, not an object
const makeUser = name => { name: name };
console.log(makeUser("Idris")); // undefined (!!)

// ✅ FIX: Wrap the object in parentheses
const makeUser = name => ({ name: name });
console.log(makeUser("Idris")); // { name: "Idris" }

// ✅ Even shorter with property shorthand
const makeUser = name => ({ name });

Real-World Arrow Function Patterns

Pattern 1: Array Method Callbacks

Arrow functions are most famously used as callbacks inside array methods like .map(), .filter(), and .find(). Let's demystify exactly what they do, so you don't get lost!

💡 The Conveyor Belt Analogy
High-order array methods are like pre-built loops. You do NOT write the for loop yourself. The browser handles the looping and passes each item, one by one, to your arrow function. Your arrow function is the recipe that tells the machine what to do with that item.

1. Transforming Data with .map()

.map() loops over every item, runs your function on it, and collects the returned values into a new array of the exact same length.

const nums = [1, 2, 3];

// ❌ WITHOUT Array Methods (Standard Loop):
const doubledOld = [];
for (let i = 0; i < nums.length; i++) {
    doubledOld.push(nums[i] * 2);
}

// ✅ WITH Array Method + Arrow Function:
const doubledNew = nums.map(n => n * 2); // [2, 4, 6]
// Read it: "Map each number 'n' to 'n * 2'"

2. Filtering Data with .filter()

.filter() loops over every item and runs a test function. If your arrow function returns true, the item is kept; if false, it is discarded.

const scores = [5, 12, 8, 20];

// ❌ WITHOUT Array Methods (Standard Loop):
const passingOld = [];
for (let i = 0; i < scores.length; i++) {
    if (scores[i] > 10) {
        passingOld.push(scores[i]);
    }
}

// ✅ WITH Array Method + Arrow Function:
const passingNew = scores.filter(s => s > 10); // [12, 20]
// Read it: "Filter scores to keep only elements 's' greater than 10"

3. Accumulating with .reduce()

.reduce() boils an array down to a single value (like a sum). It takes an accumulator (running total) and the current element.

const vals = [10, 20, 30];

// ❌ WITHOUT Array Methods (Standard Loop):
let sumOld = 0;
for (let i = 0; i < vals.length; i++) {
    sumOld += vals[i];
}

// ✅ WITH Array Method + Arrow Function:
const sumNew = vals.reduce((total, n) => total + n, 0); // 60
// Read it: "Reduce values starting at 0, adding each 'n' to the total"

4. Sorting with .sort()

To sort numbers, we pass a comparison callback (a, b) => a - b. If the result is negative, a comes first. If positive, b comes first.

const list = [10, 2, 8];
const ascending = [...list].sort((a, b) => a - b);  // [2, 8, 10]
const descending = [...list].sort((a, b) => b - a); // [10, 8, 2]

5. Chaining Operations

Because these methods return new arrays, you can **chain** them together. Let's read this chain like a sentence:

const numbers = [1, 2, 3, 4, 5];

const result = numbers
    .filter(n => n > 2)               // Step 1: Keep numbers > 2 → [3, 4, 5]
    .map(n => n * 10)                 // Step 2: Multiply each by 10 → [30, 40, 50]
    .reduce((sum, n) => sum + n, 0);  // Step 3: Add them all up → 120

console.log(result); // 120

Pattern 2: Immediately Invoked Arrow Functions

const result = (() => {
    const x = 10;
    const y = 20;
    return x + y;
})();
console.log(result); // 30

Pattern 3: Currying (Functions that return functions)

Arrows make currying incredibly clean. This is a common pattern in functional programming and React (Higher-Order Components).

// A function that creates custom multipliers
const multiply = factor => num => num * factor;

const double = multiply(2);
const triple = multiply(3);

console.log(double(5)); // 10
console.log(triple(5)); // 15

// What this actually looks like expanded:
const multiply = function(factor) {
    return function(num) {
        return num * factor;
    };
};
⚠️ Things Arrow Functions CANNOT Do
Arrow functions are NOT a replacement for all functions. They lack certain features:

1. No own this — they inherit from the parent scope (more in 2.11)
2. No arguments object — use rest parameters (...args) instead
3. Cannot be used as constructors — new (() => {}) throws a TypeError
4. No prototype property — they cannot be used with new
5. Cannot be used as generators — no function* equivalent 
// No 'arguments' object
const bad = () => {
    console.log(arguments); // ReferenceError (in strict mode)
};

// Fix: use rest parameters
const good = (...args) => {
    console.log(args); // [1, 2, 3] — a real array
};
good(1, 2, 3);

// Cannot be used as constructors
const Person = (name) => { this.name = name; };
new Person("Idris"); // TypeError: Person is not a constructor

2.2 Quiz

Object Return Trap

Q2: What does this return? Why?

const getUser = () => { name: "Idris", age: 25 };
console.log(getUser());

Answer

undefined. The engine interprets { name: "Idris", age: 25 } as a function body with a label expression (name: is a label, "Idris" is a standalone string). No return statement exists, so it returns undefined. Fix: () => ({ name: "Idris", age: 25 })

Q3: What does result equal?

const greet = greeting => name => `${greeting}, ${name}!`;
const result = greet("Hello")("Idris");

Answer

"Hello, Idris!". greet("Hello") returns a new function name => \`Hello, ${name}!\`. Then we immediately call that function with ("Idris").

2.3 Default Function Parameters

The ES5 Problem

In ES5, there was no way to set default parameter values. Developers used the || operator, which was buggy because it triggered on any falsy value (including 0, "", and false).

// ES5: The buggy pattern
function greet(name) {
    name = name || "Guest";
    return "Hello, " + name;
}
greet("");    // "Hello, Guest" — BUG! Empty string IS a valid name.
greet(0);     // "Hello, Guest" — BUG! 0 IS a valid value.
greet(false); // "Hello, Guest" — BUG!

The ES6 Fix: Default Parameters

Default parameters only trigger when the argument is undefined (not passed, or explicitly undefined). They do NOT trigger on other falsy values.

function greet(name = "Guest") {
    return `Hello, ${name}`;
}

greet();           // "Hello, Guest" ← default used
greet(undefined); // "Hello, Guest" ← default used
greet("");         // "Hello, "      ← empty string kept! ✅
greet(0);          // "Hello, 0"     ← zero kept! ✅
greet(null);       // "Hello, null"  ← null kept (not undefined)
greet("Idris");    // "Hello, Idris" ← normal

Defaults Can Be Expressions

Default values are evaluated at call time (not at definition time). They can be any expression: function calls, other parameters, math — anything.

// Default that references another parameter
function createRange(start, end = start + 10) {
    return [start, end];
}
createRange(5);     // [5, 15]
createRange(5, 20); // [5, 20]

// Default that calls a function
let id = 0;
function nextId() { return ++id; }

function createUser(name, uniqueId = nextId()) {
    return { name, uniqueId };
}
createUser("Idris");  // { name: "Idris", uniqueId: 1 }
createUser("Ali");    // { name: "Ali",   uniqueId: 2 }
createUser("Omar", 99); // { name: "Omar", uniqueId: 99 }

Defaults with Arrow Functions

const tax = (price, rate = 0.2) => price * rate;
tax(100);      // 20
tax(100, 0.1); // 10

2.4 Defaults and Destructuring

The real power comes when you combine destructured parameters with defaults. This is the exact pattern used in every React component, every Express.js route handler, and every modern API function.

Destructured Object Parameters with Defaults

function createCard({
    title,
    subtitle = "No subtitle",
    theme = "dark",
    rounded = true
}) {
    console.log(title, subtitle, theme, rounded);
}

createCard({ title: "Hello" });
// "Hello", "No subtitle", "dark", true

createCard({ title: "News", theme: "light", rounded: false });
// "News", "No subtitle", "light", false

Providing a Default for the Entire Object

What if someone calls the function with no arguments at all? The destructuring will crash because it tries to destructure undefined. Fix: default the whole parameter to {}.

// ❌ Crashes if called with no arguments
function setup({ debug = false, verbose = false }) {}
setup(); // TypeError: Cannot destructure property 'debug' of undefined

// ✅ Fix: default the whole parameter to {}
function setup({ debug = false, verbose = false } = {}) {}
setup(); // Works! debug = false, verbose = false

Destructured Array Parameters with Defaults

function drawLine([x1 = 0, y1 = 0], [x2 = 0, y2 = 0]) {
    console.log(`From (${x1},${y1}) to (${x2},${y2})`);
}
drawLine([5], [10, 20]); // "From (5,0) to (10,20)"

Defaults and Destructuring

Answer

2.5 Quiz

Default Evaluation Trap

Q2: What does result equal?

let counter = 0;
function getId() { return ++counter; }

function makeItem(name, id = getId()) {
    return { name, id };
}

const a = makeItem("X");
const b = makeItem("Y");
const c = makeItem("Z", 100);
const result = [a.id, b.id, c.id];

Answer

[1, 2, 100]. Defaults are evaluated at call time, not at definition time. The first two calls trigger getId(), incrementing the counter. The third call provides an explicit id (100), so the default is never evaluated.

2.6 - 2.7 JavaScript Classes

What Classes Actually Are

ES6 classes are syntactic sugar over JavaScript's existing prototype-based inheritance. Under the hood, they still use prototypes. Classes just make the syntax cleaner and more familiar to developers coming from Java, C#, or Python.

🧠 Mental Model
A class is a blueprint for creating objects. The constructor is the machine that stamps out individual objects from that blueprint. Each object created is called an instance.

Creating a Class

class Player {
    // The constructor runs automatically when you use 'new'
    constructor(name, score) {
        this.name = name;    // instance property
        this.score = score;  // instance property
    }

    // Methods — shared by ALL instances via the prototype
    greet() {
        return `Hi, I'm ${this.name}`;
    }

    addPoints(points) {
        this.score += points;
        return this.score;
    }
}

// Creating instances
const p1 = new Player("Idris", 0);
const p2 = new Player("Ali", 50);

console.log(p1.greet());       // "Hi, I'm Idris"
console.log(p2.addPoints(10)); // 60

// They are independent instances
console.log(p1.score); // 0 (p1 was not affected by p2)

Getters and Setters

Getters and setters let you define properties that are computed dynamically. They look like property access but run a function internally.

class Circle {
    constructor(radius) {
        this.radius = radius;
    }

    // Getter: access like a property, not a method call
    get area() {
        return Math.PI * this.radius ** 2;
    }

    // Getter with formatting
    get diameter() {
        return this.radius * 2;
    }

    // Setter: assign like a property, validation runs internally
    set diameter(d) {
        if (d < 0) throw new Error("Diameter cannot be negative");
        this.radius = d / 2;
    }
}

const c = new Circle(5);
console.log(c.area);     // 78.54 — accessed like a property, not c.area()
console.log(c.diameter); // 10
c.diameter = 20;         // Triggers the setter, updates radius to 10
console.log(c.radius);   // 10

Static Methods

Static methods belong to the class itself, not to instances. You call them on the class name directly. Common use: utility functions and factory methods.

class MathHelper {
    static add(a, b) { return a + b; }
    static random(min, max) {
        return Math.floor(Math.random() * (max - min + 1)) + min;
    }
}

// Called on the class, NOT on an instance
MathHelper.add(5, 10);     // 15
MathHelper.random(1, 100); // e.g. 42

// Cannot call on instances:
const m = new MathHelper();
m.add(5, 10); // TypeError: m.add is not a function

Q1: Create a class BankAccount with a constructor that takes owner and balance (default 0). Add methods deposit(amount) and withdraw(amount) (which should throw an error if amount > balance). Add a getter summary that returns "Owner: X, Balance: Y".

Answer

    constructor(owner, balance = 0) {
        this.owner = owner;
        this.balance = balance;
    }

    deposit(amount) {
        this.balance += amount;
        return this.balance;
    }

            throw new Error("Insufficient funds");
        }
        this.balance -= amount;
        return this.balance;

    }
}

2.9 Super and Extends (Inheritance)

Inheritance: Creating Specialized Classes

extends creates a child class that inherits all methods and properties from a parent class. super() calls the parent's constructor. You must call super() before using this in the child's constructor.

class Animal {
    constructor(name, sound) {
        this.name = name;
        this.sound = sound;
    }

    speak() {
        return `${this.name} says ${this.sound}`;
    }
}

class Dog extends Animal {
    constructor(name) {
        // super() MUST be called before 'this'
        super(name, "Woof"); // Calls Animal's constructor
        this.tricks = [];    // Dog-specific property
    }

    // Dog-specific method
    learnTrick(trick) {
        this.tricks.push(trick);
    }

    // Override the parent method
    speak() {
        return super.speak() + "!"; // Call parent version + customize
    }
}

const rex = new Dog("Rex");
rex.learnTrick("sit");
console.log(rex.speak());    // "Rex says Woof!"
console.log(rex.tricks);     // ["sit"]
console.log(rex instanceof Dog);    // true
console.log(rex instanceof Animal); // true

The super() Rule

⚠️ You MUST call super() before using this
If you forget super(), or try to access this before calling it, you get a ReferenceError. 
class Cat extends Animal {
    constructor(name) {
        this.indoor = true; // ❌ ReferenceError: Must call super before 'this'
        super(name, "Meow");
    }
}

// If you don't need extra constructor logic, you can omit it entirely.
// The parent's constructor is inherited automatically.
class Fish extends Animal {
    // No constructor needed! Animal's constructor is used.
    swim() { return `${this.name} is swimming`; }
}

const nemo = new Fish("Nemo", "blub");
console.log(nemo.speak()); // "Nemo says blub" (inherited method)
console.log(nemo.swim());  // "Nemo is swimming" (own method)

Method Overriding with super

A child class can define a method with the same name as the parent to override it. Use super.methodName() to call the parent's version if you want to extend (not fully replace) the behavior.

class Shape {
    constructor(color) { this.color = color; }
    describe() { return `A ${this.color} shape`; }
}

class Square extends Shape {
    constructor(color, size) {
        super(color);
        this.size = size;
    }

    // Override describe, but use the parent's version as a base
    describe() {
        return super.describe() + ` (square, ${this.size}px)`;
    }
}

const sq = new Square("blue", 50);
console.log(sq.describe()); // "A blue shape (square, 50px)"
2.10 Quiz

Super and Extends

Q1: Create a class Vehicle with make and speed (default 0). Add method accelerate(amount) and brake(amount). Then create a child class ElectricVehicle that adds a battery property (default 100) and overrides accelerate to reduce battery by 1 on each call (using super.accelerate() to also increase speed).

Answer

class Vehicle {
    constructor(make, speed = 0) {
        this.make = make;
        this.speed = speed;
    }
    accelerate(amount) { this.speed += amount; }
    brake(amount) { this.speed = Math.max(0, this.speed - amount); }
}

class ElectricVehicle extends Vehicle {
    constructor(make, battery = 100) {
        super(make);
        this.battery = battery;
    }
    accelerate(amount) {
        super.accelerate(amount);
        this.battery = Math.max(0, this.battery - 1);
    }
}

2.11 Working with 'this'

🧠 The Golden Rule of 'this'
In a regular function, this is determined by HOW the function is called (runtime binding).
In an arrow function, this is determined by WHERE the function is written (lexical binding).

Rule 1: Global Context

console.log(this); // In a browser: the Window object
                     // In Node.js: {} (empty module object)

Rule 2: Object Method (Implicit Binding)

When a function is called as a method of an object, this refers to the object before the dot.

const user = {
    name: "Idris",
    greet() {
        console.log(this.name); // "Idris" — 'this' is the object before the dot
    }
};
user.greet(); // 'this' = user

Rule 3: The "Extracted Method" Trap

If you pull a method out of its object and call it standalone, this is lost.

const user = {
    name: "Idris",
    greet() { console.log(this.name); }
};

// Call as method — works
user.greet(); // "Idris"

// Extract the function into a variable — 'this' is LOST
const fn = user.greet;
fn(); // undefined (or throws error in strict mode)
// 'this' is now window (or undefined in strict mode)

Rule 4: Explicit Binding (call, apply, bind)

You can force a specific this value using .call(), .apply(), or .bind().

function introduce(greeting) {
    console.log(`${greeting}, I'm ${this.name}`);
}

const user = { name: "Idris" };

// .call() — call immediately with a specific 'this'
introduce.call(user, "Hello"); // "Hello, I'm Idris"

// .apply() — same as call, but args are an array
introduce.apply(user, ["Hi"]); // "Hi, I'm Idris"

// .bind() — returns a NEW function with 'this' permanently set
const boundFn = introduce.bind(user);
boundFn("Hey"); // "Hey, I'm Idris"

Rule 5: Constructor (new keyword)

When a function is called with new, this refers to the newly created object.

function Player(name) {
    // 'new' creates a fresh empty object and sets 'this' to it
    this.name = name; // adds 'name' to the new object
}
const p = new Player("Idris"); // 'this' = the new Player object

Rule 6: Event Listeners

In a DOM event listener using a regular function, this refers to the element that the listener is attached to.

btn.addEventListener("click", function() {
    console.log(this);          // the <button> element
    this.classList.toggle("active"); // works!
});

btn.addEventListener("click", () => {
    console.log(this);          // ❌ window! Arrow has no own 'this'
    this.classList.toggle("active"); // TypeError!
});

The Priority Hierarchy

When multiple rules conflict, this is the order of precedence (highest to lowest):

  1. new binding (constructor)
  2. Explicit binding (call, apply, bind)
  3. Implicit binding (object method — obj.method())
  4. Default binding (standalone call → window or undefined)

2.12 Arrow Functions and 'this'

This is the section that separates junior developers from senior developers. Arrow functions do NOT have their own this. They inherit this from the surrounding scope at the time they are defined (lexical binding).

The Classic Bug: setTimeout with 'this'

const timer = {
    seconds: 0,

    // ❌ BUG: Regular function inside setTimeout
    startBad() {
        setInterval(function() {
            this.seconds++; // 'this' is window, not timer!
            console.log(this.seconds); // NaN
        }, 1000);
    },

    // ✅ FIX: Arrow function inherits 'this' from startGood
    startGood() {
        setInterval(() => {
            this.seconds++; // 'this' is timer! ✅
            console.log(this.seconds); // 1, 2, 3...
        }, 1000);
    }
};

The ES5 Workaround (Before Arrows Existed)

Before ES6, developers had to save this into a variable (usually called self or that).

// ES5 workaround — ugly but it worked
startOld: function() {
    var self = this; // save 'this' before it changes
    setInterval(function() {
        self.seconds++; // use 'self' instead of 'this'
    }, 1000);
}

NEVER Use Arrow Functions as Object Methods

// ❌ Arrow as object method — 'this' is NOT the object
const user = {
    name: "Idris",
    greet: () => {
        console.log(this.name); // undefined! 'this' is window.
    }
};

// ✅ Use method shorthand for object methods
const user = {
    name: "Idris",
    greet() {
        console.log(this.name); // "Idris" ✅
    }
};

Arrow Functions Inside Class Methods

This is a very common React pattern. You define an arrow function INSIDE a regular method so that this is always the class instance.

class TodoList {
    constructor() {
        this.items = [];
    }

    fetchAndRender() {
        // Arrow function inside a method — 'this' is the TodoList instance
        fetch("/api/todos")
            .then(res => res.json())
            .then(data => {
                this.items = data; // ✅ 'this' is the TodoList instance
                this.render();
            });
    }

    render() {
        console.log(this.items);
    }
}

The Complete Decision Guide

SituationUseWhy
Array callbacks (.map, .filter)ArrowShort, clean, no this needed
setTimeout / setIntervalArrowPreserves this from surrounding method
Promise .then() chainsArrowPreserves this from surrounding method
Object methodsRegular (shorthand)Needs its own this = the object
Event listeners (need this = element)RegularNeeds this = the DOM element
Class methodsRegular (shorthand)Needs this = the instance
ConstructorsRegular / ClassArrows cannot be constructors
Standalone utility functionsEitherNo this involved
2.13 Quiz

Arrow Functions and 'this'

Q1: What is the output?

const obj = {
    value: 42,
    getValue: () => this.value,
    getValueCorrect() { return this.value; }
};

console.log(obj.getValue());
console.log(obj.getValueCorrect());

Answer

undefined and 42.

getValue is an arrow function — it does NOT have its own this. It inherits this from the surrounding scope (the module/global scope), where this.value is undefined. getValueCorrect is a regular method — this correctly refers to obj.

2.13 Quiz

The Callback Trap

Q2: Fix this code so that the setTimeout callback correctly prints the player's name.

const player = {
    name: "Idris",
    delayedGreet() {
        setTimeout(function() {
            console.log("Hello, " + this.name);
        }, 1000);
    }
};
player.delayedGreet(); // Prints "Hello, undefined"

Answer

// Replace 'function()' with an arrow function:
delayedGreet() {
    setTimeout(() => {
        console.log("Hello, " + this.name);

The arrow function inherits this from delayedGreet, which is called on player, so this.name = "Idris".

2.13 Quiz

The Chained 'this' Trap

Q3: Predict the output of ALL four lines.

const obj = {
    name: "Outer",
    inner: {
        name: "Inner",
        getName() { return this.name; },
        getNameArrow: () => this.name
    }
};

console.log(obj.inner.getName());      // A
console.log(obj.inner.getNameArrow()); // B

const extracted = obj.inner.getName;
console.log(extracted());              // C

const bound = obj.inner.getName.bind(obj);
console.log(bound());                  // D

Answer

A: "Inner" — regular method, this = the object before the dot (obj.inner).
B: undefined — arrow function, this = surrounding scope (module/global), not obj.
C: undefined — extracted from object, standalone call, this = window/undefined.
D: "Outer" — .bind(obj) permanently sets this = obj (not obj.inner).

'this' KeywordDetermined by how the function is called: global → window, method → object, new → instance, call/apply/bind → explicit. Priority: new > bind > method > default.
Arrow + 'this'Arrows inherit this lexically (from where they're written). Perfect for callbacks inside methods. Never use as object methods or event listeners that need this = element.

1.1 Harmony, ES6, ES2015...

JavaScript vs. ECMAScript

ECMAScript is the specification — a document that describes how the language should behave. It is maintained by a committee called TC39 (Technical Committee 39). JavaScript is the implementation of that specification. Browser engines (Chrome's V8, Firefox's SpiderMonkey, Safari's JavaScriptCore) each write their own implementation based on the ECMAScript spec.

🧠 Mental Model
ECMAScript = the recipe book.
JavaScript = the actual dish that the chef (the browser engine) cooks from that recipe.

The Timeline

YearVersionWhat Happened
1997ES1JavaScript is born and standardized.
1999ES3Regular expressions, try/catch, switch.
2009ES5strict mode, JSON, Array methods (forEach, map, filter, reduce).
2015ES6 / ES2015MASSIVE update: let/const, arrows, classes, modules, promises, destructuring, spread/rest, for...of, template literals, symbols, iterators, generators, Map, Set, WeakMap, WeakSet, Proxy, Reflect.
2016+ES2016, ES2017...Small yearly updates (async/await, Object.entries, optional chaining, nullish coalescing...).

Why Was ES6 So Important?

Between ES5 (2009) and ES6 (2015), JavaScript exploded in popularity. Node.js was born. Single-page applications (SPAs) became the norm. Developers were building massive applications with a language that was never designed for it. ES6 was a 6-year effort to modernize JavaScript into a language capable of scaling to enterprise-level codebases.

During those 6 years of development, the upcoming version was codenamed "Harmony". As it got closer to completion, people started calling it ES6 (the 6th edition). Finally, right before release, the committee switched to a yearly naming convention and officially named it ES2015.

💡 In Practice
Most developers just say "ES6." But "ES6" and "ES2015" are the exact same thing. Everything from ES6 onward is collectively called "Modern JavaScript" or "ES6+".

1.2 Let and Const

The Problem: var is Function Scoped

In most programming languages, a variable declared inside a block (like an if statement or a for loop) only exists inside that block. JavaScript's var broke this convention. It was function scoped, meaning it leaked out of all blocks except function bodies.

function checkScore() {
    var score = 50;

    if (score >= 50) {
        var passed = true;   // Declared INSIDE the if block
        var message = "You passed!";
    }

    console.log(passed);  // true  — it leaked out!
    console.log(message); // "You passed!" — it leaked out!
}
checkScore();

// This causes real bugs when variable names collide:
function buggyCode() {
    var x = 10;
    for (var x = 0; x < 3; x++) {} // The loop variable OVERWRITES the original x!
    console.log(x); // 3 — our original x = 10 is gone forever!
}

The Fix: let and const are Block Scoped

ES6 introduced let and const. They are block scoped, which means they exist ONLY inside the nearest pair of curly braces {}.

function checkScoreES6() {
    let score = 50;

    if (score >= 50) {
        let passed = true;
        const message = "You passed!";
    }

    console.log(passed);  // ReferenceError: passed is not defined
    console.log(message); // ReferenceError: message is not defined
}

// The loop variable is now safely isolated:
function fixedCode() {
    let x = 10;
    for (let x = 0; x < 3; x++) {} // This 'x' is a DIFFERENT variable, locked in the loop.
    console.log(x); // 10 — our original x is perfectly safe!
}

Hoisting: The Creation Phase

When JavaScript runs your code, it doesn't just go line by line. It first does a Creation Phase where it scans the entire scope and allocates memory for all variable declarations. This is called hoisting.

How var hoisting works:

var is hoisted AND immediately initialized to undefined. That's why you can access it before its declaration line — you just get undefined instead of an error.

console.log(playerName); // undefined (not an error!)
var playerName = "Idris";
console.log(playerName); // "Idris"

// What the engine actually does during the Creation Phase:
// var playerName = undefined;   ← hoisted + initialized
// console.log(playerName);      ← undefined
// playerName = "Idris";         ← assignment happens at runtime
// console.log(playerName);      ← "Idris"

How let/const hoisting works (The Temporal Dead Zone):

let and const ARE hoisted — but they are NOT initialized. They sit in memory in an uninitialized state. If you try to access them before their declaration line, the engine throws a ReferenceError. The zone between the start of the block and the declaration line is called the Temporal Dead Zone (TDZ).

// ┌─── TEMPORAL DEAD ZONE for 'score' ───┐
// │                                       │
   console.log(score); // ❌ ReferenceError   │
   const x = 10;      //                     │
   console.log(score); // ❌ Still in TDZ!    │
// │                                       │
   let score = 100;   // ← TDZ ENDS HERE ───┘
   console.log(score); // ✅ 100

The TDZ Interview Trap

This is the tricky part. Even if a variable with the same name exists in an outer scope, the TDZ of the inner scope shadows it and causes an error.

let color = "global red";

function paint() {
    // You might expect this to print "global red".
    // But it doesn't! The 'let color' on line 7 is hoisted
    // to the top of this function block, creating a TDZ.
    console.log(color); // ❌ ReferenceError: Cannot access 'color' before initialization
    let color = "local blue";
}
paint();

var Attaches to the Global Object

In the browser, the global object is window. When you declare a variable with var in the global scope (outside any function), it physically attaches itself as a property of the window object. This can accidentally overwrite browser APIs.

var name = "Idris";
console.log(window.name); // "Idris" — leaked to the global object!

// Dangerous: what if you accidentally overwrite a browser API?
var fetch = "data"; // You just destroyed the fetch() API!

// let and const do NOT attach to window.
let token = "ABC";
console.log(window.token); // undefined (Safe!)

var Allows Redeclaration, let/const Do Not

var x = 10;
var x = 20; // ✅ No error! This silently overwrites x. Dangerous.

let y = 10;
let y = 20; // ❌ SyntaxError: Identifier 'y' has already been declared

const: Reassignment vs. Mutation

const prevents reassignment (changing what the variable points to). It does NOT prevent mutation (changing the contents of what it points to).

🧠 Mental Model: The Box Analogy
Think of const as a box with a label glued on it. You cannot rip the label off and glue it onto a different box (reassignment). But you can absolutely open the box and change the items inside it (mutation). 
// REASSIGNMENT (changing what the variable points to)
const name = "Idris";
name = "Ali"; // ❌ TypeError: Assignment to constant variable

// MUTATION (changing the contents of the thing it points to)
const user = { name: "Idris", age: 25 };
user.name = "Ali";   // ✅ Works! We changed a property INSIDE the object.
user.role = "admin"; // ✅ Works! We added a new property.
delete user.age;     // ✅ Works! We deleted a property.

const nums = [1, 2, 3];
nums.push(4);       // ✅ Works! [1, 2, 3, 4]
nums[0] = 999;     // ✅ Works! [999, 2, 3, 4]

// But you CANNOT point the variable to a completely new object/array:
user = { name: "Ali" };  // ❌ TypeError
nums = [5, 6];          // ❌ TypeError

How to TRULY Freeze an Object: Object.freeze()

If you want a truly immutable object where even the contents cannot change, you need Object.freeze().

const config = Object.freeze({
    apiUrl: "https://api.example.com",
    timeout: 5000
});

config.apiUrl = "hacked"; // Silently fails (or throws in strict mode)
config.newProp = "test";  // Silently fails
console.log(config.apiUrl); // "https://api.example.com" (unchanged!)
⚠️ Object.freeze() is Shallow!
Object.freeze() only freezes the top level. If your object contains nested objects, those nested objects are still mutable! To deep-freeze, you must recursively freeze every nested object. 
const nested = Object.freeze({
    level1: "frozen",
    deep: { level2: "NOT frozen" }
});

nested.level1 = "changed";      // ❌ Fails (frozen)
nested.deep.level2 = "changed"; // ✅ Works! (nested object is NOT frozen)

The Classic Loop Interview Question

This is the most famous var vs let interview question. You WILL see it.

// ❌ The Bug (var)
for (var i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 100);
}
// Output: 3, 3, 3
// Why? There is only ONE 'i' in memory (var is function scoped).
// By the time the timeouts fire, the loop is done and i === 3.
// All 3 callbacks read the same 'i', which is 3.

// ✅ The Fix (let)
for (let j = 0; j < 3; j++) {
    setTimeout(() => console.log(j), 100);
}
// Output: 0, 1, 2
// Why? 'let' creates a BRAND NEW variable in memory for EVERY iteration.
// Each callback closes over its own private copy of 'j'.
✅ The Rule
1. Default to const for everything.
2. Use let ONLY when you know you will reassign (like a loop counter or accumulator).
3. Never use var. There is zero reason to use it in modern JavaScript.

1.4 Template Literals

The ES5 Pain: String Concatenation

// ES5: Building a string was painful.
var name = "Idris";
var age = 25;
var greeting = "Hello, my name is " + name + " and I am " + age + " years old.";

// Multi-line strings required ugly escape characters:
var html = "<div>\n" +
           "  <h1>" + title + "</h1>\n" +
           "  <p>" + content + "</p>\n" +
           "</div>";

ES6 Template Literals: The Fix

Template literals use backticks (` `) instead of quotes. They support multi-line strings natively and expression interpolation with ${}.

// Clean string interpolation
const greeting = `Hello, my name is ${name} and I am ${age} years old.`;

// Multi-line strings just work. No \n needed.
const html = `
  <div>
    <h1>${title}</h1>
    <p>${content}</p>
  </div>
`;

Expressions Inside ${}

You can put ANY valid JavaScript expression inside ${}: math, function calls, ternaries, array methods — anything that returns a value.

// Math
console.log(`Tax: $${(price * 0.2).toFixed(2)}`);

// Ternary
console.log(`Status: ${isActive ? "Online" : "Offline"}`);

// Function calls
function shout(str) { return str.toUpperCase() + "!!!"; }
console.log(`${shout("hello")}`); // "HELLO!!!"

// Array methods
const items = ["Apple", "Banana"];
console.log(`Items: ${items.join(", ")}`); // "Items: Apple, Banana"

Nesting Template Literals

When generating complex HTML from arrays, you can nest template literals inside each other using .map() and .join().

const users = [
    { name: "Idris", role: "admin" },
    { name: "Ali", role: "user" }
];

const table = `
  <table>
    ${users.map(u => `
      <tr>
        <td>${u.name}</td>
        <td>${u.role}</td>
      </tr>
    `).join("")}
  </table>
`;

Tagged Template Literals (Advanced)

You can run a template literal through a tag function before it evaluates. The function receives the static string parts and the dynamic values separately. This is how libraries like React's styled-components work under the hood. It's also essential for HTML sanitization to prevent XSS attacks.

function highlight(strings, ...values) {
    // strings = ["I bought ", " for ", ""]
    // values  = ["apples", "$5"]
    return strings.reduce((result, str, i) => {
        const val = values[i] !== undefined ? `<mark>${values[i]}</mark>` : "";
        return result + str + val;
    }, "");
}

const item = "apples";
const cost = "$5";
const html = highlight`I bought ${item} for ${cost}`;
// "I bought <mark>apples</mark> for <mark>$5</mark>"

Real-World Use Case: HTML Sanitization

function safeHTML(strings, ...values) {
    return strings.reduce((result, str, i) => {
        let val = String(values[i] ?? "");
        // Escape dangerous HTML characters
        val = val.replace(/&/g, "&amp;")
                 .replace(/</g, "&lt;")
                 .replace(/>/g, "&gt;");
        return result + str + val;
    }, "");
}

const userInput = '<script>alert("hacked")</script>';
const safe = safeHTML`<p>Welcome, ${userInput}</p>`;
// "<p>Welcome, &lt;script&gt;alert(&quot;hacked&quot;)&lt;/script&gt;</p>"
// The script tag is neutralized!

1.6 Destructuring

Destructuring is a way to extract values from arrays and objects into distinct variables in a single statement.

Object Destructuring

const user = {
    name: "Idris",
    age: 25,
    email: "idris@mail.com"
};

// ES5: Extract properties one by one
var name = user.name;
var age = user.age;

// ES6: Extract multiple properties in one line
const { name, age, email } = user;

Renaming Variables

If you want the variable name to differ from the property name, use propertyName: newName.

const response = { status: 200, data: [1, 2, 3] };

// Extract 'status' but call the variable 'httpStatus'
const { status: httpStatus, data: payload } = response;
console.log(httpStatus); // 200
console.log(payload);    // [1, 2, 3]

Default Values

If a property doesn't exist, you can assign a fallback to prevent undefined.

const settings = { theme: "dark" };

const { theme, fontSize = 16, lang = "en" } = settings;
console.log(theme);    // "dark" (from object)
console.log(fontSize); // 16    (default, because fontSize doesn't exist)
console.log(lang);     // "en"  (default)

Renaming AND Defaulting at the Same Time

const data = { resp: "ok" };
const { resp: responseStatus = "failed" } = data;
console.log(responseStatus); // "ok"

const empty = {};
const { resp: status2 = "failed" } = empty;
console.log(status2); // "failed" (default applied because resp doesn't exist)

Deep / Nested Destructuring

const company = {
    name: "TechCorp",
    address: {
        city: "London",
        zip: "EC1A",
        geo: { lat: 51.5, lng: -0.09 }
    }
};

// Extract deeply nested values:
const { address: { city, geo: { lat } } } = company;
console.log(city); // "London"
console.log(lat);  // 51.5

Array Destructuring

Arrays destructure by position, not by name.

const rgb = [255, 100, 50];

// Extract all three
const [r, g, b] = rgb;

// Skip items with empty commas
const [red, , blue] = rgb;
console.log(blue); // 50

// Default values
const [a, b, c, d = 0] = [10, 20, 30];
console.log(d); // 0 (default applied)

// Swap variables without a temporary variable!
let x = 1, y = 2;
[x, y] = [y, x]; // x is now 2, y is now 1

Destructuring Function Parameters (The React Pattern)

This is the most important real-world use case. Instead of passing a large options object and accessing options.title, you destructure directly in the parameter list. This is exactly how React components receive props.

// Without destructuring (ugly)
function createCard(options) {
    console.log(options.title);
    console.log(options.subtitle);
    console.log(options.active);
}

// With destructuring + defaults (clean)
function createCard({ title, subtitle = "No subtitle", active = false }) {
    console.log(title, subtitle, active);
}

createCard({ title: "Hello" });
// "Hello", "No subtitle", false

Destructuring Nested Objects AND Arrays Together

const apiResponse = {
    status: 200,
    data: {
        users: [
            { id: 1, name: "Idris" },
            { id: 2, name: "Ali" }
        ]
    }
};

// Extract the first user's name directly:
const { data: { users: [firstUser] } } = apiResponse;
console.log(firstUser.name); // "Idris"

// Or go even deeper:
const { data: { users: [{ name: firstName }] } } = apiResponse;
console.log(firstName); // "Idris"

1.8 Object Literal Shorthand

Property Shorthand

When the variable name and the property name are the same, you can skip the duplication.

const name = "Idris";
const age = 25;
const role = "admin";

// ES5: Repetitive
var user = { name: name, age: age, role: role };

// ES6: Shorthand
const user = { name, age, role };
// Exactly the same result: { name: "Idris", age: 25, role: "admin" }

Method Shorthand

You no longer need to write : function for methods inside objects.

// ES5
var calc = {
    add: function(a, b) { return a + b; },
    sub: function(a, b) { return a - b; }
};

// ES6 Method Shorthand
const calc = {
    add(a, b) { return a + b; },
    sub(a, b) { return a - b; }
};

Computed Property Names

You can use variables or expressions as keys directly inside an object literal using square brackets [].

const field = "email";

// ES5: Had to create the object first, then add the dynamic key
var user = {};
user[field] = "idris@mail.com";

// ES6: Do it inline
const user = {
    name: "Idris",
    [field]: "idris@mail.com",          // key = "email"
    ["is" + "Active"]: true,            // key = "isActive"
    [`score_${2024}`]: 100            // key = "score_2024"
};

Returning Shorthand Objects from Arrow Functions

When returning an object from a single-line arrow function, you MUST wrap it in parentheses. Otherwise, the engine confuses the object's {} with the function body's {}.

// ❌ BUG: Returns undefined (engine thinks {} is the function body)
const makeUser = (name) => { name };

// ✅ FIX: Wrap in parentheses
const makeUser = (name) => ({ name });
console.log(makeUser("Idris")); // { name: "Idris" }

1.10 - 1.12 Iteration & The For...of Loop

1.10 What is an Iterable?

An iterable is any object that implements the Symbol.iterator method. Built-in iterables include: Arrays, Strings, Maps, Sets, NodeLists, TypedArrays, and the arguments object. Plain objects {} are NOT iterable.

1.11 The Family of Loops: Deep Comparison

const fruits = ["apple", "banana", "mango"];

// ─── 1. Classic For Loop (ES3) ───
// Verbose. Error-prone (off-by-one). But gives you full control.
for (let i = 0; i < fruits.length; i++) {
    console.log(fruits[i]);
}

// ─── 2. for...in (ES5) — TERRIBLE FOR ARRAYS ───
// Designed for objects, NOT arrays.
// Iterates over KEYS (not values), and keys are STRINGS.
// Also iterates over inherited prototype properties!
for (const key in fruits) {
    console.log(key);        // "0", "1", "2" (strings, not numbers!)
    console.log(fruits[key]); // "apple", "banana", "mango"
}

// ─── 3. forEach (ES5) ───
// Clean, but you CANNOT use 'break', 'continue', or 'return' to exit.
// It ALWAYS runs through every item.
fruits.forEach((fruit, index) => {
    // if (fruit === "banana") break; ← SyntaxError!
    console.log(index, fruit);
});

// ─── 4. for...of (ES6) — THE WINNER ───
// Iterates over VALUES directly (not keys).
// Works with break, continue, return.
// Works on all iterables (arrays, strings, maps, sets, NodeLists).
for (const fruit of fruits) {
    if (fruit === "banana") continue; // ✅ Works!
    console.log(fruit);
}

1.12 for...of in Depth

Looping Over Strings

for (const char of "Hello") {
    console.log(char); // "H", "e", "l", "l", "o"
}

Looping Over a Map

const scores = new Map();
scores.set("Idris", 95);
scores.set("Ali", 88);

for (const [name, score] of scores) {
    console.log(`${name}: ${score}`);
}
// "Idris: 95", "Ali: 88"

Looping Over a Set

const unique = new Set([1, 2, 2, 3, 3]);

for (const num of unique) {
    console.log(num); // 1, 2, 3 (duplicates removed)
}

Looping Over DOM NodeLists

const buttons = document.querySelectorAll("button");

// for...of works directly on NodeLists! No need to convert to array.
for (const btn of buttons) {
    btn.addEventListener("click", () => console.log("clicked"));
}

Getting the Index with .entries()

If you need the index alongside the value (like forEach gives you), combine for...of with .entries() and destructuring.

const colors = ["red", "green", "blue"];

for (const [index, color] of colors.entries()) {
    console.log(`${index}: ${color}`);
}
// "0: red", "1: green", "2: blue"

Using break to Stop Early

const nums = [10, 20, 30, 40, 50];

for (const num of nums) {
    if (num > 25) break; // Stop immediately
    console.log(num);
}
// Only prints: 10, 20
⚠️ for...of Does NOT Work on Plain Objects
Plain objects {} are not iterable. If you try for (const x of myObj), you get a TypeError.

To loop over an object, use:
Object.keys(obj) → array of keys
Object.values(obj) → array of values
Object.entries(obj) → array of [key, value] pairs 
const user = { name: "Idris", age: 25, role: "admin" };

// Loop over an object using for...of + Object.entries()
for (const [key, value] of Object.entries(user)) {
    console.log(`${key}: ${value}`);
}
// "name: Idris", "age: 25", "role: admin"

1.14 Spread... Operator

The spread operator (...) takes an iterable and expands (unpacks) its elements.

Spreading Arrays

// Copying an array (shallow copy)
const original = [1, 2, 3];
const copy = [...original]; // [1, 2, 3] — a new array, safe to mutate

// Merging arrays
const a = [1, 2];
const b = [3, 4];
const merged = [...a, ...b, 5]; // [1, 2, 3, 4, 5]

// Adding items at specific positions
const middle = [0, ...a, 99, ...b]; // [0, 1, 2, 99, 3, 4]

Spreading Strings

const chars = [..."Hello"]; // ["H", "e", "l", "l", "o"]

Spreading Objects

// Copying an object
const user = { name: "Idris", age: 25 };
const clone = { ...user }; // { name: "Idris", age: 25 }

// Merging objects (later properties overwrite earlier ones)
const defaults = { theme: "light", lang: "en", fontSize: 14 };
const userPrefs = { theme: "dark", fontSize: 18 };
const final = { ...defaults, ...userPrefs };
// { theme: "dark", lang: "en", fontSize: 18 }
// userPrefs values overwrite defaults values

Spread in Function Calls

const nums = [5, 10, 3, 8];

// ES5 way to pass an array to Math.max:
Math.max.apply(null, nums); // ugly

// ES6 spread:
Math.max(...nums); // 10 — clean!
⚠️ The Shallow Copy Trap
Spread creates a shallow copy. If your object contains nested objects, only the references are copied, not the deep values. Mutating nested properties on the copy will affect the original! 
const original = {
    name: "Idris",
    settings: { theme: "dark" } // nested object
};
const copy = { ...original };

// Top-level properties are safe:
copy.name = "Ali";
console.log(original.name); // "Idris" ✅ (original unchanged)

// Nested objects are NOT safe — they share the same reference:
copy.settings.theme = "light";
console.log(original.settings.theme); // "light" 😱 (original was mutated!)

// Fix: Spread the nested objects too
const deepCopy = { 
    ...original, 
    settings: { ...original.settings } 
};

1.15 ...Rest Parameter

The rest parameter uses the same ... syntax, but does the opposite of spread. It gathers multiple elements into a single array.

💡 How to Tell Them Apart
Spread = used where VALUES are expected (right side of =, function arguments).
Rest = used where NAMES are expected (left side of =, function parameters).

Rest in Function Parameters

In ES5, you had to use the arguments object to handle variable-length arguments. But arguments is NOT a real array — you couldn't use .map(), .filter(), or .reduce() on it. The rest parameter fixes this by giving you a real array.

// ES5: The ugly way
function sumOld() {
    var args = Array.prototype.slice.call(arguments); // convert to array
    return args.reduce(function(a, b) { return a + b; }, 0);
}

// ES6: Clean and modern
function sum(...numbers) {
    // 'numbers' is a REAL array. Full access to .map(), .filter(), .reduce().
    return numbers.reduce((acc, n) => acc + n, 0);
}
console.log(sum(1, 2, 3, 4)); // 10

Mixing Named Parameters with Rest

Rest must always be the LAST parameter. Named parameters grab their values first, then rest collects everything else.

function createTeam(captain, ...members) {
    console.log(`Captain: ${captain}`);
    console.log(`Team: ${members.join(", ")}`);
}

createTeam("Idris", "Ali", "Omar", "Yusuf");
// Captain: Idris
// Team: Ali, Omar, Yusuf

Rest in Array Destructuring

const [first, second, ...remaining] = [10, 20, 30, 40, 50];
console.log(first);     // 10
console.log(second);    // 20
console.log(remaining); // [30, 40, 50]

Rest in Object Destructuring (Remove a Property)

This is a common pattern to create a copy of an object with specific properties removed — without using the delete keyword (which mutates the original).

const user = { 
    id: 1, 
    name: "Idris", 
    password: "secret123", 
    role: "admin" 
};

// Remove 'password' and 'id', keep everything else
const { password, id, ...safeUser } = user;
console.log(safeUser); // { name: "Idris", role: "admin" }
console.log(user);     // Original is untouched!
1.16 Quiz

Using the Rest Parameter

Q1: Write a function multiply(multiplier, ...items) that multiplies each item by the multiplier and returns a new array.

multiply(2, 1, 2, 3); // → [2, 4, 6]

Answer

const multiply = (multiplier, ...items) => {
    return items.map(item => item * multiplier);
};
1.16 Quiz

Rest vs Spread

Q2: For each line, identify whether ... is being used as Spread or Rest.

const [a, ...b] = [1, 2, 3, 4];      // Line A
const c = [...b, 5, 6];               // Line B
function test(...args) {}              // Line C
test(...c);                            // Line D

Answer

Line A: Rest (gathering remaining elements into b)
Line B: Spread (expanding b into a new array)
Line C: Rest (gathering function arguments into args)
Line D: Spread (expanding c into individual arguments)

1.16 Quiz

Object Rest

Q3: Given const product = { id: 1, name: "Laptop", price: 999, stock: 50 }, create a new object called display that contains everything EXCEPT id and stock. Do it in one line.

Answer

const { id, stock, ...display } = product;
// display = { name: "Laptop", price: 999 }

06 — The fetch() API & Real-World Projects

The grand finale. You've mastered callbacks, Promises, and async/await — now it's time to talk to the internet. In this lesson, you'll learn the fetch() API and build real projects that pull live data from actual servers.

1. What Is fetch()?

Every modern web application needs to communicate with servers — loading user data, submitting forms, fetching images, checking weather, searching products. fetch() is the built-in browser function that makes all of this possible.

The Old Way vs. The New Way

Before fetch(), developers used XMLHttpRequest (often abbreviated as XHR). It was verbose, callback-heavy, and frankly painful to work with. Here's a quick comparison:

// ❌ The old way — XMLHttpRequest (painful)
const xhr = new XMLHttpRequest();
xhr.open('GET', 'https://api.example.com/data');
xhr.onreadystatechange = function() {
    if (xhr.readyState === 4 && xhr.status === 200) {
        const data = JSON.parse(xhr.responseText);
        console.log(data);
    }
};
xhr.send();
// ✅ The new way — fetch() with async/await (beautiful)
const response = await fetch('https://api.example.com/data');
const data = await response.json();
console.log(data);

That's it. Two lines to do what used to take ten. And because fetch() returns a Promise, it works perfectly with async/await — everything you learned in the previous lessons.

💡 Key Insight fetch() is built into every modern browser. No libraries, no npm packages, no setup — just call it and go.

The Basic Syntax

// Simplest possible fetch call
const response = await fetch(url);

// With options (for POST, PUT, etc.)
const response = await fetch(url, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(data)
});

The first argument is always the URL — the address of the server you're talking to. The optional second argument is a config object where you specify the HTTP method, headers, body, and more.

2. HTTP Methods Explained

When your browser talks to a server, it uses HTTP methods to communicate its intent. Think of them as verbs — they tell the server what action you want to perform.

Method Purpose Real-World Example
GET Read / request data Load a user's profile page
POST Send / create new data Submit a new blog post
PUT Replace existing data entirely Update your entire profile
PATCH Partially update data Change just your email address
DELETE Remove data Delete a comment
✅ Best Practice GET is the default method for fetch(). If you just call fetch(url) without specifying a method, it will automatically use GET. You only need to specify the method for POST, PUT, PATCH, and DELETE. 
// GET is the default — these are identical:
await fetch('https://api.example.com/posts');
await fetch('https://api.example.com/posts', { method: 'GET' });

// For other methods, you MUST specify:
await fetch('https://api.example.com/posts', { method: 'POST', ... });
await fetch('https://api.example.com/posts/1', { method: 'DELETE' });

3. The Response Object

When fetch() resolves, it gives you a Response object. This object contains everything about the server's reply — status codes, headers, and the body data.

Key Properties & Methods

const response = await fetch('https://api.example.com/data');

// Was the request successful? (status 200-299)
console.log(response.ok);       // true or false

// What's the exact status code?
console.log(response.status);   // 200, 404, 500, etc.

// Parse the body as JSON (this is ALSO async!)
const data = await response.json();

// Or parse as plain text
const text = await response.text();
⚠️ Common Gotcha response.json() returns a Promise, not the actual data! You must await it (or use .then()). This is the #1 mistake beginners make with fetch(). Always write const data = await response.json();

Common HTTP Status Codes

Code Meaning When You'll See It
200 OK Everything worked perfectly
201 Created Your POST request created a new resource
400 Bad Request You sent invalid data to the server
401 Unauthorized You need to log in first
404 Not Found The resource doesn't exist
500 Server Error Something broke on the server's side
💡 Important Detail fetch() only rejects its Promise on network failures (no internet, DNS error, etc.). A 404 or 500 response does NOT cause a rejection — the Promise still resolves! That's why you must always check response.ok manually.

4. Making a GET Request (Step by Step)

Let's build the complete, production-quality pattern for making a GET request. This is the template you'll use in every project:

async function fetchData() {
    try {
        // Step 1: Make the request
        const response = await fetch('https://api.example.com/data');

        // Step 2: Check if the request was successful
        if (!response.ok) {
            throw new Error(`HTTP error! Status: ${response.status}`);
        }

        // Step 3: Parse the JSON body
        const data = await response.json();

        // Step 4: Use the data
        console.log(data);

    } catch (error) {
        // Step 5: Handle errors (network failure OR bad status)
        console.error('Failed to fetch:', error.message);
    }
}

Let's break down each step:

  1. await fetch(url) — Sends the request and waits for the server to respond.
  2. if (!response.ok) — Checks the status code. If it's outside 200-299, we throw our own error.
  3. await response.json() — Parses the response body from raw text into a JavaScript object.
  4. Use the data — Now data is a normal JS object you can work with.
  5. catch — Handles both network errors AND the errors we threw for bad status codes.

5. Making a POST Request

GET reads data. POST creates data. When you submit a form, create a new account, or write a comment — that's a POST request.

The POST Pattern

const response = await fetch('https://api.example.com/posts', {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json'    // Tell the server we're sending JSON
    },
    body: JSON.stringify({                    // Convert JS object to JSON string
        title: 'My New Post',
        body: 'This is the content...',
        userId: 1
    })
});

Three things are different from a GET request:

  1. method: 'POST' — Tells the server we're sending data, not requesting it.
  2. headers — The Content-Type: application/json header tells the server "the data I'm sending is in JSON format."
  3. body — The actual data you're sending. Must be a string, so we use JSON.stringify() to convert our JavaScript object.
⚠️ Don't Forget JSON.stringify() The body must be a string. If you pass a raw object like body: { title: 'Hello' }, it will be converted to "[object Object]" and the server won't understand it. Always use JSON.stringify().

async function createPost() {

    const body  = document.getElementById('post-body').value;

    } catch (err) {
        console.error(err.message);
    }
}

// Full GitHub profile viewer code:
async function fetchGitHub() {
    const username = document.getElementById('gh-username').value.trim();
    if (!username) return;

    output.innerHTML = '<div class="spinner"></div>';

    try {
        const response = await fetch(`https://api.github.com/users/${username}`);

        if (response.status === 404) {
            throw new Error(`User "${username}" not found`);
        }
        if (!response.ok) {
            throw new Error(`HTTP error: ${response.status}`);
        }

        const user = await response.json();

        // Build the profile card HTML
        output.innerHTML = `
            <div class="github-card">
                <img src="${user.avatar_url}" alt="avatar">
                <div class="info">
                    <h4>${user.name || user.login}</h4>
                    <p class="bio">${user.bio || 'No bio available'}</p>
                    <div class="stats">
                        <span class="stat-badge">📦 ${user.public_repos} repos</span>
                        <span class="stat-badge">📍 ${user.location || 'Unknown'}</span>
                    </div>
                    <a href="${user.html_url}" target="_blank">View on GitHub →</a>
                </div>
            </div>
        `;
    } catch (err) {
        output.innerHTML = `<div class="error-msg">😕 ${err.message}</div>`;
    }
}
✅ Notice the Error Handling We check for 404 specifically to give a user-friendly "not found" message. We check response.ok for all other errors. And the catch block handles network failures (no internet). This is production-quality error handling.

// Weather app code:
async function fetchWeather() {
    const city = document.getElementById('weather-city').value.trim();
    if (!city) return;

    output.innerHTML = '<div class="spinner"></div>';

    try {
        const response = await fetch(`https://wttr.in/${encodeURIComponent(city)}?format=j1`);
        if (!response.ok) throw new Error('City not found');

        const data = await response.json();
        const current = data.current_condition[0];
        const temp = current.temp_C;
        const condition = current.weatherDesc[0].value;
        const emoji = getWeatherEmoji(condition);

        output.innerHTML = `
            <div class="weather-card">
                <div class="weather-emoji">${emoji}</div>
                <div class="temp">${temp}°C</div>
                <div class="condition">${condition}</div>
                <div class="city-name">📍 ${city}</div>
            </div>
        `;
    } catch (err) {
        output.innerHTML = `<div class="error-msg">🌧️ ${err.message}</div>`;
    }
}

function getWeatherEmoji(condition) {
    const c = condition.toLowerCase();
    if (c.includes('sun') || c.includes('clear'))   return '☀️';
    if (c.includes('cloud') || c.includes('overcast')) return '☁️';
    if (c.includes('rain') || c.includes('drizzle'))  return '🌧️';
    if (c.includes('snow'))                            return '❄️';
    if (c.includes('thunder'))                         return '⛈️';
    if (c.includes('fog') || c.includes('mist'))      return '🌫️';
    return '🌤️';
}
💡 Why encodeURIComponent()? City names like "New York" contain spaces. URLs can't have spaces, so encodeURIComponent() converts "New York" to "New%20York". Always encode user input before putting it in a URL.

8. Handling Loading, Errors & Empty States

Every production app that fetches data has 3 possible states. If you don't handle all three, your app will feel broken to users.

State What the User Sees When It Happens
⏳ Loading A spinner or skeleton screen While waiting for the server's response
✅ Success The actual data / content When the fetch resolves with good data
❌ Error A friendly error message When the network fails or server returns an error

The Best-Practice Template

async function loadData() {
    // 1. Show LOADING state
    showLoading();

    try {
        const response = await fetch(url);
        if (!response.ok) throw new Error(`HTTP ${response.status}`);
        const data = await response.json();

        if (data.length === 0) {
            // 2a. Show EMPTY state
            showEmpty('No results found.');
        } else {
            // 2b. Show SUCCESS state
            showData(data);
        }
    } catch (err) {
        // 3. Show ERROR state
        showError(err.message);
    }
}
✅ Pro Tip Always set the loading state before the try block (or as the first thing inside it). If you put it inside try after the fetch, the user sees nothing during the request. Setting it first ensures the spinner appears instantly.

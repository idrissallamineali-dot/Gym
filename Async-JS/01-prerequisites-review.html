01 — Prerequisites Review

A warm-up lap through every fundamental concept you'll need before we tackle asynchronous JavaScript. If anything here feels unfamiliar, review it first — the rest of the course builds directly on these ideas.

1. Why This Review Matters

Asynchronous JavaScript is not a standalone concept that lives in isolation. It is built on top of several fundamental JavaScript features, and those features must be second nature before you can understand how Promises, async/await, and the Event Loop actually work.

Here's what async code relies on heavily:

  • Functions as first-class citizens — you'll be passing functions around as arguments constantly.
  • Callback functions — the entire history of async JS started with callbacks.
  • Arrow functions — modern async code uses arrow functions everywhere for conciseness.
  • Array methods — processing API data means chaining .map(), .filter(), etc.
  • try…catch — async operations can fail (network down, server error), and you need to handle that.
  • Destructuring & template literals — API responses are objects; you'll destructure them on every line.
  • JSON — the universal language of web APIs.
⚠ Warning If more than two items in the list above feel genuinely unfamiliar, pause here. Go back and work through those topics first. Attempting async concepts without these foundations will feel like learning to run before you can walk.

If everything feels at least somewhat familiar, that's great — this lesson will solidify your understanding and give you hands-on practice with each concept. Let's begin.

2. Functions as First-Class Citizens

In JavaScript, functions are values. That single sentence changes everything. It means a function is no different from a number, a string, or an object — you can store it in a variable, pass it as an argument to another function, and return it from a function.

This concept is the bedrock of asynchronous JavaScript. When you write setTimeout(myFunc, 1000), you're passing a function as a value to setTimeout. Without first-class functions, none of this would be possible.

Three Ways to Create Functions

1. Function Declaration — the classic way. Hoisted to the top of its scope, so you can call it before the line where it's written.

JSfunction greet(name) {
  return `Hello, ${name}!`;
}

console.log(greet("Alice")); // "Hello, Alice!"

2. Function Expression — store an anonymous function in a variable. Not hoisted.

JSconst greet = function(name) {
  return `Hey there, ${name}!`;
};

console.log(greet("Bob")); // "Hey there, Bob!"

3. Arrow Function — the modern, concise syntax introduced in ES6. Also not hoisted.

JSconst greet = (name) => `Yo, ${name}!`;

console.log(greet("Charlie")); // "Yo, Charlie!"
💡 Tip All three of these syntaxes produce a function value. The key insight is that the function itself is just data — you can assign it, reassign it, even put it inside an array. This is what "first-class" means.

Passing a Function as an Argument

Here's the pattern that unlocks everything in async JS — handing a function to another function:

JSfunction doMath(a, b, operation) {
  return operation(a, b);
}

const add = (x, y) => x + y;
const multiply = (x, y) => x * y;

console.log(doMath(3, 4, add));      // 7
console.log(doMath(3, 4, multiply)); // 12

Notice: we pass add and multiply without parentheses. We're passing the function itself, not calling it. This is the exact same pattern used by setTimeout, addEventListener, .map(), and every async API in JavaScript.

3. Callback Functions (The Most Important Prerequisite)

A callback is simply a function you pass to another function, to be called back (invoked) at a later time. That's it. There's no special keyword or syntax — it's just a function used as an argument.

Why are callbacks the most important prerequisite? Because the entire history of async JavaScript began with callbacks. Before Promises existed, callbacks were the only way to handle asynchronous operations. And even today, Promises are built on top of the same idea.

A Simple Callback Example

JSfunction processUserInput(callback) {
  const name = "Alice";
  callback(name); // call the function that was passed in
}

function greet(userName) {
  console.log(`Welcome, ${userName}!`);
}

processUserInput(greet); // pass greet as a callback
// Output: "Welcome, Alice!"

Read that code carefully: greet is passed to processUserInput without parentheses. Inside processUserInput, it's called as callback(name). The function we passed in gets "called back."

setTimeout — The Classic Async Callback

setTimeout is the simplest asynchronous function in JavaScript. It takes two arguments: a callback function and a delay in milliseconds. It tells the browser: "Wait this many milliseconds, then call this function."

JSconsole.log("Starting...");

setTimeout(() => {
  console.log("3 seconds have passed!");
}, 3000);

console.log("This runs IMMEDIATELY — no waiting.");

// Output order:
// "Starting..."
// "This runs IMMEDIATELY — no waiting."
// "3 seconds have passed!"   ← appears 3 seconds later!
⚠ Key Insight Notice the output order! setTimeout does not pause the code. JavaScript keeps running the next lines immediately. The callback runs later, when the timer expires. This is asynchronous behavior — and it's the whole reason this course exists.

addEventListener — Another Callback Pattern

JSconst button = document.querySelector("#myBtn");

button.addEventListener("click", () => {
  console.log("Button was clicked!");
});

// The arrow function above is a callback.
// It doesn't run now — it runs LATER, when the user clicks.

Same pattern: you pass a function, and the browser calls it later (when the event fires). This is exactly how async code works — you hand off a function and trust that it will be called at the right time.

4. Arrow Functions Deep Dive

Arrow functions (=>) are the dominant syntax in modern JavaScript, and you'll see them on virtually every line of async code. Let's make sure you know all the variations.

The Full Spectrum of Arrow Syntax

JS// 1. Multiple parameters, with a body block
const add = (a, b) => {
  return a + b;
};

// 2. Multiple parameters, implicit return (no curly braces)
const add = (a, b) => a + b;

// 3. Single parameter — parentheses optional
const double = n => n * 2;

// 4. No parameters — parentheses required
const sayHi = () => "Hello!";

// 5. Returning an object literal — wrap in parentheses
const makeUser = (name) => ({ name: name, active: true });
⚠ Common Gotcha If you want to return an object literal with an implicit return, you must wrap it in parentheses: () => ({ key: value }). Without the parentheses, JavaScript thinks the curly braces are a function body, not an object.

Comparison Table

Feature Regular Function Arrow Function
Syntax function(x) { ... } (x) => { ... }
Implicit return ❌ Not possible ✅ (x) => x * 2
Hoisted ✅ Declarations are hoisted ❌ Never hoisted
this binding Gets its own this Inherits this from parent
arguments object ✅ Available ❌ Not available
Use as method ✅ Works correctly ⚠ Can cause this issues
Best for callbacks Works fine ✅ Preferred — shorter & cleaner
💡 Tip For async code, you'll almost always use arrow functions. They're shorter, and the inherited this binding usually does what you want. Use regular functions only when you specifically need your own this (like in object methods or constructors).

5. Array Methods That Use Callbacks

When you fetch data from an API (which is the entire point of async JS), you'll receive arrays of objects. To process that data, you'll chain array methods — and every single one of them takes a callback function.

.map() — Transform Every Element

Creates a new array by calling your callback on each element. The original array is untouched.

JSconst numbers = [1, 2, 3, 4, 5];
const doubled = numbers.map(n => n * 2);
console.log(doubled); // [2, 4, 6, 8, 10]

.filter() — Keep Only Matching Elements

Creates a new array with only the elements where the callback returns true.

JSconst numbers = [1, 2, 3, 4, 5, 6];
const evens = numbers.filter(n => n % 2 === 0);
console.log(evens); // [2, 4, 6]

.find() — Get the First Match

Returns the first element where the callback returns true, or undefined if none match.

JSconst users = [
  { name: "Alice", age: 25 },
  { name: "Bob", age: 30 },
  { name: "Charlie", age: 35 }
];

const found = users.find(u => u.age > 28);
console.log(found); // { name: "Bob", age: 30 }

.reduce() — Boil Down to a Single Value

Takes a callback with an accumulator and the current element. Returns one final value.

JSconst numbers = [1, 2, 3, 4, 5];
const sum = numbers.reduce((acc, n) => acc + n, 0);
console.log(sum); // 15

.forEach() — Do Something With Each Element (No Return)

Runs a callback on each element but does not return a new array. Used for side effects (logging, DOM updates).

JSconst fruits = ["apple", "banana", "cherry"];
fruits.forEach(fruit => console.log(`I like ${fruit}`));
// "I like apple"
// "I like banana"
// "I like cherry"
✅ Pattern Recognition Notice how every method above follows the same pattern: array.method(callback). The callback is always a function that receives the current element and returns something. This is the exact same "pass a function, it gets called later" pattern we saw with setTimeout and addEventListener. It's callbacks all the way down.

6. try…catch (Error Handling)

When you make async requests — fetching data from an API, loading a file, connecting to a database — things can and will go wrong. The network might be down, the server might return an error, or the URL might be wrong. You need a way to handle failures gracefully instead of crashing your entire app.

That's what try...catch does. It lets you try some risky code, and if it throws an error, you catch that error and handle it however you want.

Basic Syntax

JStry {
  // Code that might fail
  const data = riskyOperation();
  console.log(data);
} catch (error) {
  // Code that runs ONLY if an error was thrown
  console.log("Something went wrong:", error.message);
} finally {
  // Code that ALWAYS runs, error or not
  console.log("Cleanup complete.");
}

The Error Object

When JavaScript throws an error, it creates an Error object with useful properties:

Property Description Example
error.message Human-readable error description "Cannot read property 'name' of undefined"
error.name Type of error "TypeError", "ReferenceError"
error.stack Stack trace showing where it happened Full trace with file and line numbers

Throwing Your Own Errors

You can also throw errors yourself using the throw keyword. This is useful for validation:

JSfunction divide(a, b) {
  if (b === 0) {
    throw new Error("Cannot divide by zero!");
  }
  return a / b;
}

try {
  const result = divide(10, 0);
} catch (error) {
  console.log(error.message); // "Cannot divide by zero!"
}
💡 Why This Matters for Async In the upcoming lessons, you'll write code like try { const data = await fetch(url); } catch (error) { ... }. The try...catch pattern is identical — the only difference is that the risky code is asynchronous. Master it now with synchronous code, and the async version will feel natural.

7. Destructuring & Template Literals

These two features are not async-specific, but you'll use them on every single line that processes API data. A quick review to make sure they're sharp.

Object Destructuring

Instead of accessing object properties with dot notation over and over, you can extract them into variables in one clean line:

JSconst user = {
  name: "Alice",
  age: 28,
  email: "alice@example.com",
  location: "NYC"
};

// ❌ Without destructuring — repetitive
console.log(user.name);
console.log(user.age);
console.log(user.email);

// ✅ With destructuring — clean
const { name, age, email } = user;
console.log(name);  // "Alice"
console.log(age);   // 28
console.log(email); // "alice@example.com"

Renaming During Destructuring

JSconst { name: userName, age: userAge } = user;
console.log(userName); // "Alice"
console.log(userAge);  // 28

Default Values

JSconst { name, role = "user" } = user;
console.log(role); // "user" (property didn't exist, default was used)

Nested Destructuring

JSconst apiResponse = {
  data: {
    user: { name: "Alice", id: 42 },
    token: "abc123"
  },
  status: 200
};

const { data: { user: { name }, token }, status } = apiResponse;
console.log(name);   // "Alice"
console.log(token);  // "abc123"
console.log(status); // 200

Array Destructuring

JSconst colors = ["red", "green", "blue"];
const [first, second, third] = colors;
console.log(first);  // "red"
console.log(second); // "green"

// Skip elements with commas
const [, , blue] = colors;
console.log(blue); // "blue"

Template Literals

Template literals use backticks (`) instead of quotes, and allow embedded expressions with ${...}:

JSconst name = "Alice";
const age = 28;

// ❌ String concatenation — messy
const msg1 = "Hello, " + name + ". You are " + age + " years old.";

// ✅ Template literal — clean
const msg2 = `Hello, ${name}. You are ${age} years old.`;

// You can put any expression inside ${...}
const msg3 = `In 5 years you'll be ${age + 5}.`;
const msg4 = `Name uppercased: ${name.toUpperCase()}`;
✅ Real-World Async Pattern Here's a sneak peek of how destructuring and template literals combine in async code:

const { name, avatar } = await fetch('/api/user').then(r => r.json());

One line: fetch data, parse JSON, destructure the result. You'll write this exact pattern many times.

8. JSON (JavaScript Object Notation)

JSON is the universal format for sending data over the internet. When you fetch data from an API, the response body is almost always a JSON string. You need to convert it to a JavaScript object before you can use it — and you need JSON.parse() to do that.

What JSON Looks Like

JSON looks almost identical to a JavaScript object, but with a few strict rules:

  • All keys must be double-quoted strings: "name", not name.
  • Values can be: strings, numbers, booleans, null, arrays, or objects.
  • No trailing commas, no functions, no undefined.
JSON{
  "name": "Alice",
  "age": 28,
  "isActive": true,
  "hobbies": ["coding", "reading"],
  "address": {
    "city": "New York",
    "zip": "10001"
  }
}

JSON.stringify() — Object → JSON String

Converts a JavaScript object into a JSON string. Used when sending data to a server.

JSconst user = { name: "Alice", age: 28, active: true };
const jsonString = JSON.stringify(user);
console.log(jsonString);
// '{"name":"Alice","age":28,"active":true}'
console.log(typeof jsonString); // "string"

// Pretty-print with 2-space indentation
const pretty = JSON.stringify(user, null, 2);
console.log(pretty);
// {
//   "name": "Alice",
//   "age": 28,
//   "active": true
// }

JSON.parse() — JSON String → Object

Converts a JSON string back into a JavaScript object. Used when receiving data from a server.

JSconst jsonString = '{"name":"Alice","age":28,"active":true}';
const user = JSON.parse(jsonString);
console.log(user.name);   // "Alice"
console.log(user.age);    // 28
console.log(typeof user); // "object"
⚠ Common Error JSON.parse() will throw an error if you pass it invalid JSON. This is exactly why you'll wrap your async code in try...catch — the JSON you receive from a server might be malformed.

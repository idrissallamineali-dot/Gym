01 — The Promise Constructor & 3 States

Focus topic: Understanding how to create a Promise from scratch and how its state transitions work permanently.

1. The Mental Model: What is a Promise?

A Promise is not the actual data itself. Think of it as a tamper-proof sealed box that represents a value you will receive in the future.

When you create a Promise, it starts in one state and can transition to exactly one of two final states:

The 3 Unbreakable States:
  • ⏳ pending — The task is currently running. No result yet.
  • ✅ fulfilled — The task succeeded. It holds a value.
  • ❌ rejected — The task failed. It holds a reason/error.

2. Anatomy of the Constructor

You create a Promise using new Promise(). You pass it a single function called the executor:

const myPromise = new Promise((resolve, reject) => {
  // 1. Synchronous work runs immediately
  // 2. Trigger an async task (timer, etc.)
  
  const success = true;

  if (success) {
    resolve("Data delivered! 📦");  // Changes state to FULFILLED
  } else {
    reject("Something broke! 💥");  // Changes state to REJECTED
  }
});

Notice the two parameters JavaScript passes into your function:

  • resolve(val): Call this function when your work succeeds.
  • reject(err): Call this function when your work fails.

3. The Golden Rule: Settling is Permanent 🔒

Once a Promise is settled (fulfilled or rejected), its state is frozen forever.

⚠️ Once resolved or rejected, it cannot change: Calling resolve() after reject() (or vice-versa) does absolutely nothing. The first settlement wins. 
const p = new Promise((resolve, reject) => {
  resolve("First decision ✅");
  reject("Too late, I will be ignored! ❌");
  resolve("Also ignored! ❌");
});

// State is permanently 'fulfilled' with value "First decision ✅"

07 — Objects

Objects are the backbone of JavaScript. Nearly everything in JS is an object — arrays, functions, dates, errors. Understanding how to create, access, manipulate, and iterate over objects is fundamental to every line of code you will ever write.

1. What Is an Object?

An object is an unordered collection of key-value pairs. Each pair is called a property. The key (or property name) is always a string (or Symbol), and the value can be anything — a number, string, boolean, array, function, or even another object.

Object structure ┌─────────────────────────────────────────────┐ │ Object │ │ │ │ key → value │ │ ───────────────────────────────────────── │ │ "name" → "Idris" │ │ "age" → 25 │ │ "isActive" → true │ │ "skills" → ["JS", "CSS", "HTML"] │ │ "greet" → function() { ... } │ └─────────────────────────────────────────────┘

Unlike arrays (which are ordered by index), objects organize data by meaningful names. This makes them perfect for representing real-world entities — a user, a product, a configuration.

2. Creating Objects

2.1 — Object Literal (The Standard Way)

const user = {
    name: "Idris",
    age: 25,
    isTraining: true,
    skills: ["JS", "CSS", "HTML"]
};

2.2 — Empty Object (Add Properties Later)

const config = {};
config.theme = "dark";
config.language = "en";

2.3 — Object.create()

Creates a new object with a specified prototype. We will cover prototypes later, but know this exists.

const proto = { greet() { return `Hello, ${this.name}`; } };
const user = Object.create(proto);
user.name = "Idris";
user.greet();  // "Hello, Idris"

3. Accessing Properties

There are two ways to access a property on an object. Knowing when to use which is critical.

3.1 — Dot Notation

The most common way. Clean and readable. Use this by default.

const user = { name: "Idris", age: 25 };

user.name;   // "Idris"
user.age;    // 25

3.2 — Bracket Notation

Uses a string (or variable containing a string) inside brackets. Required in three situations:

// 1. When the key is stored in a variable:
const key = "name";
user[key];            // "Idris"
user.key;             // undefined — looks for a property literally called "key"

// 2. When the key has special characters or spaces:
const obj = { "first name": "Idris", "background-color": "blue" };
obj["first name"];       // "Idris"
obj["background-color"];  // "blue"
// obj.first name → SyntaxError
// obj.background-color → interpreted as subtraction!

// 3. When the key is computed dynamically:
const prefix = "user";
const data = { user1: "Alice", user2: "Bob" };
data[prefix + "1"];     // "Alice"
data[`${prefix}2`];     // "Bob"
Rule of thumb Use dot notation when the key is a simple, known name.
Use bracket notation when the key is dynamic, has special characters, or is stored in a variable.

3.3 — Accessing Non-Existent Properties

user.email;             // undefined — no error, just undefined
user.address.city;      // ❌ TypeError: Cannot read properties of undefined
user?.address?.city;    // undefined — safe with optional chaining (Lesson 03)

4. Adding, Modifying, and Deleting Properties

Objects are mutable — you can change them after creation, even if declared with const (remember: const locks the reference, not the contents).

const user = { name: "Idris" };

// Add new properties:
user.age = 25;
user.skills = ["JS", "CSS"];
user["is-active"] = true;

// Modify existing properties:
user.name = "Idris Updated";
user.age = 26;

// Delete properties:
delete user["is-active"];
console.log(user);
// { name: "Idris Updated", age: 26, skills: ["JS", "CSS"] }

5. Methods: Functions Inside Objects

When a function is stored as a property of an object, it is called a method.

const calculator = {
    // ES5 way:
    add: function(a, b) {
        return a + b;
    },

    // ES6 shorthand (preferred):
    subtract(a, b) {
        return a - b;
    }
};

calculator.add(5, 3);       // 8
calculator.subtract(10, 4);  // 6

5.1 — this Inside Methods

Inside a method (regular function), this refers to the object the method belongs to:

const user = {
    name: "Idris",
    age: 25,

    introduce() {
        return `Hi, I'm ${this.name} and I'm ${this.age}.`;
    },

    birthday() {
        this.age++;
        return `Happy birthday! Now ${this.age}.`;
    }
};

user.introduce();  // "Hi, I'm Idris and I'm 25."
user.birthday();   // "Happy birthday! Now 26."
Do NOT use arrow functions for object methods Arrow functions do not have their own this. They inherit this from the surrounding scope, which for a top-level object is the global scope (or undefined in strict mode):

const user = { name: "Idris", greet: () => this.name };
user.greet(); // undefined ← broken!

Always use regular functions or ES6 shorthand for object methods.

6. ES6 Object Enhancements

ES6 introduced several shortcuts that make working with objects cleaner.

6.1 — Property Shorthand

When a variable name matches the property name, you can skip the colon:

const name = "Idris";
const age = 25;
const role = "Developer";

// Without shorthand:
const user = { name: name, age: age, role: role };

// With shorthand (ES6):
const user2 = { name, age, role };

// Both create: { name: "Idris", age: 25, role: "Developer" }

6.2 — Computed Property Names

You can use an expression inside [] as a property name when creating an object:

const field = "email";

const user = {
    name: "Idris",
    [field]: "idris@example.com",          // email: "idris@example.com"
    [`${field}Verified`]: true             // emailVerified: true
};

6.3 — Method Shorthand

// Old way:
const obj = {
    sayHi: function() { return "Hi"; }
};

// ES6 shorthand:
const obj2 = {
    sayHi() { return "Hi"; }
};

7. Object Destructuring (ES6)

Destructuring lets you unpack properties from an object into individual variables. This is used constantly in modern JavaScript.

7.1 — Basic Destructuring

const user = { name: "Idris", age: 25, role: "Developer" };

// Without destructuring:
const name = user.name;
const age = user.age;

// With destructuring:
const { name, age, role } = user;
console.log(name);  // "Idris"
console.log(age);   // 25
console.log(role);  // "Developer"

7.2 — Rename Variables

// Use a colon to give the variable a different name:
const { name: userName, age: userAge } = user;
console.log(userName);  // "Idris"
console.log(userAge);   // 25
// 'name' and 'age' are NOT created — only 'userName' and 'userAge'

7.3 — Default Values

const { name, email = "not set" } = user;
console.log(email);  // "not set" (user has no email property)

7.4 — Nested Destructuring

const user = {
    name: "Idris",
    address: {
        city: "Paris",
        country: "France"
    }
};

const { address: { city, country } } = user;
console.log(city);     // "Paris"
console.log(country);  // "France"
// Note: 'address' itself is NOT created as a variable

7.5 — Rest With Objects

const { name, ...rest } = { name: "Idris", age: 25, role: "Dev" };
console.log(name);  // "Idris"
console.log(rest);  // { age: 25, role: "Dev" }

7.6 — Destructuring in Function Parameters

This is extremely common — you destructure the argument directly in the function signature:

// Without destructuring:
function greet(user) {
    return `Hello, ${user.name}! Age: ${user.age}`;
}

// With destructuring (cleaner — you see exactly what you need):
function greet({ name, age }) {
    return `Hello, ${name}! Age: ${age}`;
}

greet({ name: "Idris", age: 25 });  // "Hello, Idris! Age: 25"
This pattern is everywhere React components, Express route handlers, API response parsing, configuration objects — destructuring in parameters is the standard way professionals write clean, readable function signatures.

8. The Spread Operator With Objects

// Shallow copy an object:
const original = { name: "Idris", age: 25 };
const copy = { ...original };
copy.age = 30;
console.log(original.age);  // 25 — safe!

// Merge objects (later properties overwrite earlier ones):
const defaults = { theme: "light", lang: "en", debug: false };
const userPrefs = { theme: "dark", lang: "fr" };

const settings = { ...defaults, ...userPrefs };
// { theme: "dark", lang: "fr", debug: false }
// userPrefs overwrites defaults for theme and lang

// Add or override specific properties:
const updated = { ...original, age: 26, email: "a@b.com" };
// { name: "Idris", age: 26, email: "a@b.com" }
Spread creates a shallow copy only Nested objects inside the spread are still shared references. If you need a fully independent deep copy, use structuredClone(obj).

9. Checking If a Property Exists

const user = { name: "Idris", age: 25 };

// Method 1: 'in' operator (checks own + inherited properties)
"name" in user;     // true
"email" in user;    // false

// Method 2: hasOwnProperty() (checks OWN properties only)
user.hasOwnProperty("name");   // true
user.hasOwnProperty("toString");  // false (inherited from Object prototype)

// Method 3: Compare to undefined (works but fragile)
user.name !== undefined;   // true
// Fails if the property exists but is explicitly set to undefined

// Modern best practice: Object.hasOwn() (ES2022)
Object.hasOwn(user, "name");   // true

10. Iterating Over Objects

Objects are not directly iterable with for...of. You need to convert them first. Here are all the ways:

10.1 — Object.keys() → Array of Key Names

const user = { name: "Idris", age: 25, role: "Dev" };

Object.keys(user);
// ["name", "age", "role"]

10.2 — Object.values() → Array of Values

Object.values(user);
// ["Idris", 25, "Dev"]

10.3 — Object.entries() → Array of [key, value] Pairs

Object.entries(user);
// [["name", "Idris"], ["age", 25], ["role", "Dev"]]

10.4 — Looping Patterns

// Pattern 1: for...in (iterates over keys directly)
for (const key in user) {
    console.log(`${key}: ${user[key]}`);
}

// Pattern 2: Object.keys() + forEach
Object.keys(user).forEach(key => {
    console.log(`${key}: ${user[key]}`);
});

// Pattern 3: Object.entries() + for...of (cleanest — gives both key and value)
for (const [key, value] of Object.entries(user)) {
    console.log(`${key}: ${value}`);
}

// Pattern 4: Object.entries() + destructuring with map/filter/reduce
const stringValues = Object.entries(user)
    .filter(([key, val]) => typeof val === "string")
    .map(([key, val]) => `${key}=${val}`);
// ["name=Idris", "role=Dev"]
Object.entries() is the modern standard It converts the object to an array of pairs, which means you can use all the powerful array methods (map, filter, reduce) on objects. This is the bridge between objects and arrays.

11. Object.assign(), Object.freeze(), and Object.seal()

11.1 — Object.assign() — Merge / Copy Objects

// Copy into a new object:
const copy = Object.assign({}, user);

// Merge multiple objects into a target:
const target = { a: 1 };
const source1 = { b: 2 };
const source2 = { c: 3 };

Object.assign(target, source1, source2);
console.log(target);  // { a: 1, b: 2, c: 3 } — target is mutated!

// Nowadays, the spread operator is preferred for copying/merging.

11.2 — Object.freeze() — Make an Object Fully Immutable

const config = Object.freeze({
    apiUrl: "https://api.example.com",
    timeout: 5000
});

config.apiUrl = "hacked!";   // ❌ Silently fails (or throws in strict mode)
config.newProp = "test";     // ❌ Cannot add
delete config.timeout;       // ❌ Cannot delete

console.log(config.apiUrl);  // "https://api.example.com" — unchanged
Freeze is shallow Object.freeze() only freezes the top level. Nested objects can still be mutated:

const obj = Object.freeze({ inner: { x: 1 } });
obj.inner.x = 99; // ✅ This works! Inner object is not frozen.

To deep-freeze, you would need to recursively freeze every nested object.

11.3 — Object.seal() — Allow Modification, Prevent Add/Delete

const user = Object.seal({ name: "Idris", age: 25 });

user.name = "Updated";   // ✅ Can modify existing
user.email = "a@b.com";  // ❌ Cannot add new
delete user.age;          // ❌ Cannot delete

12. Object.fromEntries() — Array of Pairs → Object

The reverse of Object.entries(). Converts an array of [key, value] pairs back into an object.

const entries = [["name", "Idris"], ["age", 25]];

const obj = Object.fromEntries(entries);
// { name: "Idris", age: 25 }

// Powerful pattern: transform an object's values using entries + fromEntries
const prices = { apple: 1, banana: 2, cherry: 3 };

const doubled = Object.fromEntries(
    Object.entries(prices).map(([fruit, price]) => [fruit, price * 2])
);
// { apple: 2, banana: 4, cherry: 6 }

13. Nested Objects and Real-World Patterns

const student = {
    id: 42,
    name: "Idris",
    contact: {
        email: "idris@example.com",
        phone: {
            mobile: "+33 6 12 34 56 78",
            work: null
        }
    },
    courses: [
        { name: "JS Fundamentals", completed: true },
        { name: "ES6", completed: false }
    ]
};

// Access deeply nested data:
student.contact.phone.mobile;           // "+33 6 12 34 56 78"
student.courses[1].name;                // "ES6"

// Safe access with optional chaining:
student.contact?.phone?.work;           // null
student.contact?.fax?.number;           // undefined (no crash)

// Destructure nested data:
const { contact: { email }, courses } = student;
console.log(email);    // "idris@example.com"
console.log(courses);  // [{...}, {...}]

// Find incomplete courses using array methods on nested data:
const incomplete = student.courses
    .filter(c => !c.completed)
    .map(c => c.name);
// ["ES6"]

14. Factory Functions & Constructor Functions

When you need to create many objects with the same shape, don't repeat the object literal. Use a function to generate them.

14.1 — Factory Function (Returns a New Object)

function createUser(name, age) {
    return {
        name,
        age,
        greet() {
            return `Hi, I'm ${this.name}`;
        }
    };
}

const user1 = createUser("Idris", 25);
const user2 = createUser("Alice", 30);

user1.greet();  // "Hi, I'm Idris"
user2.greet();  // "Hi, I'm Alice"

14.2 — Constructor Function (Uses new)

function User(name, age) {
    this.name = name;
    this.age = age;
    this.greet = function() {
        return `Hi, I'm ${this.name}`;
    };
}

const user3 = new User("Bob", 28);
user3.greet();  // "Hi, I'm Bob"

The new keyword does three things automatically:

  1. Creates a new empty object {}.
  2. Sets this inside the function to point to that new object.
  3. Returns the new object (implicitly).
Convention Constructor functions are named in PascalCase (User, Product, Order) to distinguish them from regular functions. If you see PascalCase, it means "call me with new."

Modern JS uses the class syntax instead of constructor functions — same concept, cleaner code.

15. Prototypes — How Objects Inherit

Every object in JavaScript has a hidden internal link to another object called its prototype. When you access a property that does not exist on the object, the engine automatically looks up the prototype chain.

const user = { name: "Idris" };

// 'user' doesn't have a toString() method.
// But it works because the engine finds it on Object.prototype:
user.toString();  // "[object Object]"
The Prototype Chain user { name: "Idris" } │ └──▶ Object.prototype { toString(), hasOwnProperty(), ... } │ └──▶ null (end of chain) When you call user.toString(): 1. Engine checks user → no toString() found. 2. Engine checks Object.prototype → found! Uses it.

You do not need to master prototypes right now, but understanding that this chain exists explains why every object has methods like toString(), hasOwnProperty(), and valueOf() even though you never defined them.

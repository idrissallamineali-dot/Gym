02 — Variables & Data Types

The absolute building blocks of every program you will ever write. Master this and everything else becomes logical.

1. What Is a Variable?

A variable is a labeled container that holds a value in the computer's memory.

When you create a variable, you are telling the JavaScript engine: "Reserve a space in memory, give it this name, and store this value inside."

let age = 25;

What happened in that single line:

  1. Declaration — the keyword let tells the engine to create a new variable.
  2. Naming — the identifier age becomes the label you use to refer to that memory space.
  3. Assignment — the = operator stores the value 25 into that memory space.

You can also declare without assigning. The variable exists but holds no useful value yet:

let score;
console.log(score);  // undefined — it exists but has no value assigned

2. The Three Declaration Keywords: var, let, const

JavaScript has three ways to create a variable. Understanding the differences is critical — this comes up in interviews, code reviews, and real bugs constantly.

2.1 — var (The Old Way)

var is the original keyword from 1995. It works, but it has behaviors that cause bugs:

var name = "Idris";
var name = "Ali";    // ✅ No error! var allows re-declaration
console.log(name);   // "Ali" — silently overwrote the first one

Problem 1: var is Function-Scoped, NOT Block-Scoped

A block is any code inside curly braces { } — like an if statement, a for loop, or a while loop. var ignores these blocks completely. It only respects function boundaries.

if (true) {
    var leaked = "I escaped the block!";
}

console.log(leaked);  // "I escaped the block!" — var leaked out of the if block

This is dangerous. You think the variable is private to that if block, but it is actually accessible everywhere in the function (or globally if not inside any function).

Problem 2: var Hoisting Creates Confusion

As we learned in Lesson 01, var declarations are hoisted to the top of their scope and initialized as undefined:

console.log(x);  // undefined (not an error — hoisted and initialized)
var x = 10;

This silent undefined can mask bugs. You expect an error, but you get undefined instead, and your program continues running with broken data.

Rule Never use var in modern code. It exists only for legacy compatibility. Always use let or const.

2.2 — let (The Modern Mutable Variable)

let was introduced in ES6 (2015) to fix the problems of var.

let score = 100;
score = 200;   // ✅ Reassignment is allowed

let score = 300;  // ❌ SyntaxError! Re-declaration is NOT allowed

Fix 1: let is Block-Scoped

if (true) {
    let trapped = "I cannot escape!";
}

console.log(trapped);  // ❌ ReferenceError: trapped is not defined

The variable stays locked inside the { } block where it was declared. This is exactly what you expect and want.

Fix 2: let Has a Temporal Dead Zone (TDZ)

console.log(y);  // ❌ ReferenceError! Cannot access 'y' before initialization
let y = 10;

let is hoisted, but it is not initialized. The zone between the top of the block and the declaration line is called the Temporal Dead Zone. Accessing the variable in this zone throws an immediate error — which is good, because it tells you exactly where the bug is.

2.3 — const (The Constant Reference)

const works exactly like let (block-scoped, TDZ) but with one extra rule: you cannot reassign it after initialization.

const PI = 3.14159;
PI = 3;  // ❌ TypeError: Assignment to constant variable

You must assign a value at the moment of declaration:

const x;  // ❌ SyntaxError: Missing initializer in const declaration
The trap: const does NOT make objects immutable const prevents reassignment of the variable (the pointer), but it does NOT prevent mutation of the value the variable points to. This is a critical distinction that confuses many developers: 
const user = { name: "Idris", age: 25 };

user.age = 26;         // ✅ Works! You mutated the object, not the variable
console.log(user.age);  // 26

user = { name: "Ali" };  // ❌ TypeError! You tried to reassign the variable itself

Think of it this way: const locks the address (which memory slot the variable points to), but not the contents at that address. The object at that address can still be changed.

3. Variable Naming Rules & Conventions

3.1 — Hard Rules (Breaking These = Error)

  • Names can contain letters, digits, underscores _, and dollar signs $.
  • Names cannot start with a digit. 1name → error. name1 → fine.
  • Names cannot be reserved keywords (let, const, function, return, class, etc.).
  • Names are case-sensitive. age and Age are different variables.
// ✅ Valid names
let firstName = "Idris";
let _privateVar = 42;
let $element = "div";
let camelCaseIsGood = true;

// ❌ Invalid names
let 2fast = "error";      // starts with digit
let my-name = "error";    // hyphens not allowed
let let = "error";        // reserved keyword

3.2 — Naming Conventions (Not Errors, But Professional Standards)

ConventionUsed ForExample

UPPER_SNAKE_CASETrue constants (values that never change)const MAX_RETRIES = 3;

Pro tip: name variables for what they represent let x = 25; tells you nothing.
let userAge = 25; tells you everything.
Descriptive names save you hours of debugging later.

4. Data Types: The Two Categories

Every single value in JavaScript falls into one of two categories:

CategoryWhat They AreHow Many
PrimitivesSimple, atomic, indivisible values7 types

This split determines how values are stored in memory, how they are compared, and how they behave when copied. Understanding this is non-negotiable.

5. The 7 Primitive Data Types

Primitives are the simplest building blocks. They are immutable — once created, the value itself cannot be changed (you can reassign a variable to a new value, but you cannot mutate the original value in memory).

5.1 — String (Text Masterclass)

A string is an ordered sequence of character symbols representing text. Created using single quotes ', double quotes ", or backticks ` (template literals).

let single = 'Single quote';
let double = "Double quote";
let template = `Backtick literal`;

⚠️ The Immutability Trap
A common beginner mistake is thinking string methods change the variable:
let text = "hello";
text.toUpperCase();
console.log(text); // "hello" (UNCHANGED!)

Since strings are primitive, they cannot be changed. You must capture the returned value in a variable:
let text = "hello";
text = text.toUpperCase(); // ✅ reassigned to the new value!
console.log(text); // "HELLO"

ES6 Template Literals (The Powerhouses)

Template literals use backticks (`) instead of quotes, enabling advanced expressions directly inside the text using ${expression}.

Rule 1: Multiline Formatting

const address = `Idris Ahmed
123 Gymnasium Street
Paris, France`;
// Preserves actual newlines and spaces exactly as typed! No \n needed.

Rule 2: String Interpolation (Inline Calculations)

const price = 29.99;
const taxRate = 0.2;
const receipt = `Price: $${price} (+ Tax: $${(price * taxRate).toFixed(2)}) = Total: $${(price * (1 + taxRate)).toFixed(2)}`;
console.log(receipt); // "Price: $29.99 (+ Tax: $6.00) = Total: $35.99"

Rule 3: Ternaries and Decision Making Inside Strings

const active = true;
const userStatus = `Your profile is currently ${active ? 'active' : 'inactive'}.`;

10 Professional String Recipes (Code Patterns)

Here are 10 highly visual recipes showing exactly how string properties and methods are combined to solve real-world problems:

Recipe 1: Capitalizing the First Letter

const capitalize = str => str[0].toUpperCase() + str.slice(1);
capitalize("gym"); // "Gym"

Recipe 2: Reversing a String via Array Transition

const reverseStr = str => str.split("").reverse().join("");
reverseStr("hello"); // "olleh"

Recipe 3: Checking for a Palindrome

const isPalindrome = str => {
    const clean = str.toLowerCase().replaceAll(" ", "");
    return clean === clean.split("").reverse().join("");
};
isPalindrome("Race Car"); // true

Recipe 4: Masking Sensitive Data (Credit Card)

const maskCard = card => card.slice(-4).padStart(card.length, "*");
maskCard("1234567812345678"); // "************5678"

Recipe 5: Parsing Username and Domain from Email

const email = "idris@gymnasium.com";
const [username, domain] = email.split("@");
console.log(username); // "idris"
console.log(domain);   // "gymnasium.com"

Recipe 6: Title Case a Sentence

const titleCase = sentence => sentence
    .toLowerCase()
    .split(" ")
    .map(word => word[0].toUpperCase() + word.slice(1))
    .join(" ");
titleCase("hello WORLD from gymnasium"); // "Hello World From Gymnasium"

Recipe 7: Truncate Text with Ellipsis

const truncate = (str, max) => str.length > max ? str.slice(0, max) + "..." : str;
truncate("Welcome to Javascript", 10); // "Welcome to..."

Recipe 8: Check if String Contains Only Numbers

const isNumeric = str => !isNaN(str) && !isNaN(parseFloat(str)) && !str.includes(" ");
isNumeric("45209"); // true
isNumeric("45 2");  // false

Recipe 9: Count Word Occurrences

const countOccurrences = (str, word) => str.split(word).length - 1;
countOccurrences("apple banana apple cherry apple", "apple"); // 3

Recipe 10: Generate Initials from Name

const getInitials = name => name
    .toUpperCase()
    .split(" ")
    .map(n => n[0])
    .join(".");
getInitials("john fitzgerald kennedy"); // "J.F.K"

5.2 — Number

JavaScript has one number type for both integers and decimals (floating-point). Unlike Java or C, there is no separate int or float.

let integer = 42;
let decimal = 3.14;
let negative = -17;
let exponential = 2.5e6;  // 2,500,000

Special number values:

let inf = Infinity;         // result of dividing by zero: 1 / 0
let negInf = -Infinity;      // -1 / 0
let notANumber = NaN;        // "Not a Number" — result of invalid math
The floating-point trap JavaScript uses IEEE 754 double-precision floating point. This means decimal math can produce surprising results:

0.1 + 0.2 === 0.3 → false (the actual result is 0.30000000000000004)

This is not a JavaScript bug — it affects all languages using floating-point. For precise decimal calculations (money, measurements), use integer math (multiply by 100, work in cents) or dedicated libraries.

NaN — The Weirdest Value in JavaScript:

let result = "hello" * 5;  // NaN — you cannot multiply text by a number

// NaN is the ONLY value in JavaScript that is not equal to itself:
NaN === NaN;    // false (!!)

// To check for NaN, use:
Number.isNaN(result);  // true — the correct and safe way
isNaN("hello");         // true — but this old function has quirks, avoid it

5.3 — BigInt

Regular numbers have a safe limit: Number.MAX_SAFE_INTEGER = 9,007,199,254,740,991. Beyond this, precision breaks. BigInt handles arbitrarily large integers.

let big = 9007199254740991n;      // the "n" suffix creates a BigInt
let alsoBig = BigInt("123456789012345678901234567890");

// You cannot mix BigInt and Number in operations:
10n + 5;  // ❌ TypeError
10n + 5n; // ✅ 15n

You will rarely use BigInt as a beginner, but knowing it exists matters when you encounter large IDs or cryptographic numbers.

5.4 — Boolean

Only two possible values: true or false. The foundation of all logic, conditions, and decision-making in code.

let isLoggedIn = true;
let hasPermission = false;

// Comparison operators produce booleans:
10 > 5;      // true
10 === 5;    // false
"a" === "a";  // true

5.5 — Undefined

undefined means "a variable has been declared but has not been given a value yet." JavaScript itself assigns this automatically.

let x;
console.log(x);        // undefined — declared but never assigned
console.log(typeof x);  // "undefined"

You can also get undefined when:

  • A function has no return statement (it returns undefined)
  • You access a property that does not exist on an object
  • You access an array index that does not exist

5.6 — Null

null means "intentionally empty." It is a value that a programmer explicitly assigns to say "there is nothing here on purpose."

let selectedUser = null;  // We intentionally have no user selected right now
undefined vs null — the critical difference undefined = the engine is telling you "this was never assigned."
null = the developer is telling you "I deliberately set this to nothing."

Both represent "no value," but the intent is different. In your own code, use null to explicitly clear a variable. Let the engine handle undefined.
The infamous typeof bug typeof null returns "object" — this is a known bug in JavaScript since 1995 that was never fixed for backwards compatibility. null is NOT an object. It is a primitive. Just memorize this quirk.

5.7 — Symbol

A Symbol creates a completely unique, unreproducible identifier. Even two symbols with the same description are not equal.

let id1 = Symbol("id");
let id2 = Symbol("id");

id1 === id2;  // false — every Symbol is absolutely unique

Symbols are used as unique object property keys to avoid naming collisions. You will encounter them in frameworks and advanced patterns, but you do not need to use them daily as a beginner.

6. Objects: The Complex Data Type

Everything that is NOT a primitive is an Object. Objects are collections of key-value pairs (also called properties).

const user = {
    name: "Idris",
    age: 25,
    isTraining: true
};

// Accessing properties:
user.name;         // "Idris" — dot notation (most common)
user["age"];       // 25 — bracket notation (needed for dynamic keys)

// Modifying properties:
user.age = 26;            // change existing property
user.email = "a@b.com";   // add new property

// Deleting properties:
delete user.email;

7. How Data Types Live in Memory (Stack vs. Heap)

This is one of the most important mental models in all of programming. It explains why copying variables sometimes works the way you expect and sometimes doesn't.

7.1 — Primitives Live on the Stack (Copy by Value)

When you create a primitive variable, the value is stored directly on the Stack. When you copy a primitive to another variable, a completely independent duplicate is created.

let a = 10;
let b = a;    // b gets its own independent copy of 10
b = 99;

console.log(a);  // 10 — completely untouched
console.log(b);  // 99
Stack Memory ┌──────────────┬───────────────┐ │ a │ 10 │ ├──────────────┼───────────────┤ │ b │ 99 │ ← independent copy, changing b did not touch a └──────────────┴───────────────┘

7.2 — Objects Live on the Heap (Copy by Reference)

Objects are too large and dynamic to fit on the Stack. Instead, they are stored on the Heap. The variable on the Stack only holds a reference (an address, a pointer) to where the object lives on the Heap.

When you "copy" an object variable, you copy the reference, not the object. Both variables now point to the same object.

let original = { name: "Idris" };
let copy = original;   // copy now points to the SAME object on the Heap

copy.name = "Changed!";

console.log(original.name);  // "Changed!" — BOTH were affected!
Stack Memory Heap Memory ┌──────────────┬───────────────┐ ┌─────────────────────────────────┐ │ original │ → Addr 0x4F2 │──────>│ Addr 0x4F2: │ ├──────────────┼───────────────┤ │ { name: "Changed!" } │ │ copy │ → Addr 0x4F2 │──────>│ │ └──────────────┴───────────────┘ └─────────────────────────────────┘ Both variables point to the SAME address. One object. Two doors to it.

7.3 — How to Create a True Copy of an Object

If you need an independent copy (a new object at a new Heap address), use:

// Method 1: Spread operator (shallow copy)
let trueCopy = { ...original };

// Method 2: Object.assign (shallow copy)
let trueCopy2 = Object.assign({}, original);

// Method 3: structuredClone (DEEP copy — copies nested objects too)
let deepCopy = structuredClone(original);

// Now modifying the copy does NOT affect the original:
trueCopy.name = "Safe";
console.log(original.name);  // "Changed!" — untouched!
Shallow vs Deep copy A shallow copy creates a new object, but if that object contains nested objects, those nested objects are still shared references.
A deep copy (structuredClone) duplicates everything recursively — fully independent.

8. The typeof Operator

The typeof operator tells you the data type of any value. It returns a string.

typeof 42;          // "number"
typeof "hello";     // "string"
typeof true;        // "boolean"
typeof undefined;   // "undefined"
typeof 10n;         // "bigint"
typeof Symbol();     // "symbol"
typeof null;        // "object"   ⚠️ KNOWN BUG (null is a primitive!)
typeof {};          // "object"
typeof [];          // "object"   ⚠️ Arrays are objects
typeof function(){}; // "function" (technically a subtype of object)
To check if something is an array Since typeof [] returns "object", use Array.isArray(value) instead.

9. Type Coercion: JavaScript's Most Confusing Feature

Because JavaScript is dynamically typed, the engine will sometimes automatically convert one type to another to make an operation work. This is called type coercion, and it is the source of most beginner bugs.

9.1 — Implicit Coercion (The Engine Does It Automatically)

// String + Number → the number becomes a string (concatenation)
"5" + 3;       // "53" (string!) — NOT 8!

// String - Number → the string becomes a number (math)
"5" - 3;       // 2 (number)

// Boolean in math → true becomes 1, false becomes 0
true + 1;      // 2
false + 1;     // 1

// Comparison with different types:
"10" == 10;    // true — the string was coerced to a number
"10" === 10;   // false — strict equality, no coercion, different types
Rule: Always use === (strict equality) The == operator converts types before comparing, which leads to bizarre results:

"" == false → true
0 == "" → true
null == undefined → true
[] == false → true

The === operator checks both value AND type. No surprises. Use it always.

9.2 — Explicit Coercion (You Do It On Purpose)

When you need to convert a type, do it explicitly — never rely on implicit coercion:

// Convert to Number:
Number("42");        // 42
Number("hello");     // NaN
Number(true);        // 1
Number(false);       // 0
Number(null);        // 0
Number(undefined);   // NaN
parseInt("42px");    // 42 — parses until it hits a non-number character
parseFloat("3.14"); // 3.14

// Convert to String:
String(42);          // "42"
(42).toString();     // "42"

// Convert to Boolean:
Boolean(1);          // true
Boolean(0);          // false
Boolean("");         // false
Boolean("hello");    // true

10. Truthy and Falsy Values

In JavaScript, every value has an inherent Boolean identity — it is either "truthy" or "falsy". This determines how it behaves in conditions (if, while, ternaries, logical operators).

The Complete Falsy List (memorize these — there are only 8):

Falsy ValueTypeExplanation
falseBooleanThe literal false value
0NumberZero
-0NumberNegative zero (yes, it exists)
0nBigIntBigInt zero
""StringEmpty string (no characters)
nullnullIntentional absence of value
undefinedundefinedNo value assigned
NaNNumberNot a Number

Everything else is truthy. Including things that surprise beginners:

// These are ALL truthy:
Boolean("0");       // true — it's a non-empty string, not the number 0
Boolean(" ");       // true — a space is a character
Boolean([]);        // true — empty array is still an object
Boolean({});        // true — empty object is still an object
Boolean("false");   // true — the STRING "false" is not the BOOLEAN false
How this is used in practice Instead of writing: if (username !== undefined && username !== null && username !== "")
You can write: if (username)

Since undefined, null, and "" are all falsy, this single check handles all three cases. This pattern is used everywhere in professional code.

11. Equality & Comparison: == vs ===

OperatorNameBehavior
==Loose EqualityConverts types, then compares values
===Strict EqualityCompares value AND type — no conversion
!=Loose InequalityConverts types, then checks if NOT equal
!==Strict InequalityNo conversion — checks value AND type are NOT equal
 
5 == "5";     // true — string "5" is coerced to number 5
5 === "5";    // false — number is not the same type as string

null == undefined;   // true — special coercion rule
null === undefined;  // false — different types

Object Equality: A Different Game

For objects (including arrays), === checks if both variables point to the exact same object in memory, NOT whether the contents are the same:

let arr1 = [1, 2, 3];
let arr2 = [1, 2, 3];

arr1 === arr2;  // false — same contents, but two different objects in memory!

let arr3 = arr1;
arr1 === arr3;  // true — both point to the exact same object on the Heap

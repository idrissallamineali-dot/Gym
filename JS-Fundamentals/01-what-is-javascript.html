01 — What Is JavaScript?

Everything you need to understand about the language itself before you write a single line of code. These concepts stay relevant at every level.

1. The Simple Definition

JavaScript is a programming language that makes web pages interactive.

HTML gives a page its structure (the skeleton).
CSS gives a page its style (the skin, colors, layout).
JavaScript gives a page its behavior (what happens when you click, scroll, type, or wait).

Without JavaScript, every web page would be a static poster — you could look at it, but you could never interact with it.

2. Where Does JavaScript Run?

JavaScript was originally built to run inside a web browser. Every modern browser has a built-in JavaScript Engine that reads and executes your code:

BrowserEngine Name
Google ChromeV8
FirefoxSpiderMonkey
SafariJavaScriptCore
EdgeV8 (same as Chrome)

In 2009, a developer named Ryan Dahl took the V8 engine out of Chrome and wrapped it in a standalone program called Node.js. This means JavaScript can now also run outside the browser — on servers, on your computer terminal, anywhere.

Why this matters to you When you write JS that manipulates a webpage (changing colors, showing popups), that runs in the browser.
When you run node myfile.js in your terminal, that runs outside the browser using Node.js.

The language is the same. The environment is different.

3. Core Characteristics of JavaScript

These are properties of the language itself. You will hear these terms throughout your entire career:

3.1 — JavaScript is Interpreted (Not Compiled)

Some languages (like C or Java) require you to compile all your code into machine code before you can run it. JavaScript does not. The engine reads your code line by line, interprets it, and executes it on the spot.

Modern reality Today's engines (V8) actually use a technique called Just-In-Time (JIT) compilation — they interpret first, then compile hot paths in the background for speed. But conceptually, you write code and it runs immediately. No build step required.

3.2 — JavaScript is Single-Threaded

JavaScript uses one single thread of execution. It can only do one thing at a time.

Think of it like a single cashier at a store. Customers (tasks) line up, and the cashier processes them one by one, in order. The cashier cannot serve two customers simultaneously.

This is managed by something called the Call Stack — a data structure that tracks which function is currently being executed. We will cover this deeply later.

What about async? JavaScript handles things like network requests and timers using the Event Loop — it delegates slow tasks to the browser/Node environment, continues processing the queue, and picks up the result when it's ready. The language itself is still single-threaded.

3.3 — JavaScript is Dynamically Typed

In some languages, you must declare what type of data a variable will hold:

Java (statically typed)// Java — you must specify the type
int age = 25;           // This variable can ONLY hold integers
String name = "Idris";  // This variable can ONLY hold strings

In JavaScript, you do not declare types. A variable can hold any type of data, and it can change type at any time:

JavaScript (dynamically typed)let x = 25;        // x is a Number
x = "hello";      // x is now a String — no error!
x = true;        // x is now a Boolean — still no error!

This is powerful (flexible) but also dangerous (easy to introduce bugs). This is why TypeScript exists — it adds type checking on top of JavaScript. But for now, just understand: JavaScript does not care what type you put inside a variable.

3.4 — JavaScript is Case-Sensitive

myVariable, MyVariable, and myvariable are three completely different things. Always be precise with your capitalization.

let name = "Idris";
console.log(Name);  // ❌ ReferenceError: Name is not defined

3.5 — JavaScript Uses Semicolons (Optional but Recommended)

Each statement in JavaScript can end with a semicolon ;. The engine has a feature called Automatic Semicolon Insertion (ASI) that adds them for you in most cases, but relying on ASI can cause subtle bugs. Most professional codebases use semicolons explicitly.

let a = 10;   // explicit semicolon — clean and clear
let b = 20    // no semicolon — works, but risky in edge cases

4. How JavaScript Executes Your Code

This is the mental model that will make everything else click. Even at an advanced level, this is how you debug problems:

Step 1: Creation Phase (Memory Allocation)

Before executing a single line, the engine scans your entire code and allocates memory for:

• Variables declared with var → set to undefined
• Function declarations → stored in full

This is called Hoisting — the engine "hoists" declarations to the top of their scope before running the code.

console.log(greeting);  // undefined (not an error — it was hoisted!)
var greeting = "Hello";

sayHi();  // "Hi!" (works — function declarations are fully hoisted)
function sayHi() {
    console.log("Hi!");
}
Critical note for ES6 Variables declared with let and const are also hoisted, but they are placed in a Temporal Dead Zone (TDZ) — you cannot access them before the line where they are declared. This is why let and const are safer than var.

Step 2: Execution Phase (Line by Line)

After the Creation Phase, the engine goes back to line 1 and starts executing the code line by line, top to bottom. Each time it enters a function, it creates a new Execution Context with its own memory space.

5. The Execution Context

Your most important mental model.

Every time JavaScript runs code, it creates an Execution Context — an environment that contains:

1. The Variable Environment — all the variables and functions available in this scope.
2. The Scope Chain — a reference to the outer (parent) scope, allowing access to variables declared outside.
3. The this keyword — a special reference that changes depending on context.

TypeWhen It Is Created
Global Execution ContextWhen your script first loads. There is only one.
Function Execution ContextEvery time a function is called. A new one is created per call.

These contexts are managed on the Call Stack (Last In, First Out). When a function finishes, its context is popped off the stack and destroyed.

6. Strict Mode

JavaScript has a special mode called Strict Mode that catches common mistakes and prevents unsafe actions. You activate it by writing this at the top of your file:

"use strict";

What it does:

• Prevents you from accidentally creating global variables (forgetting let/const)
• Throws errors for silent failures
• Forbids some syntax that future versions of JS might use

Most modern frameworks enable this automatically. It is considered best practice to always use it.

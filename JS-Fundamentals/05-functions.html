05 — Functions

Functions are the single most important concept in JavaScript. Everything — event handlers, callbacks, array methods, async operations, React components — is built on top of functions. Master this and everything else falls into place.

1. What Is a Function?

A function is a reusable block of code that performs a specific task. You define it once, then call it as many times as you need.

Think of a function like a machine in a factory:

  • You feed it inputs (raw materials) → these are called parameters.
  • It does some work internally (the function body).
  • It produces an output (the finished product) → this is the return value.
The function machine Inputs (Arguments) │ ▼ ┌─────────────────────┐ │ │ │ FUNCTION BODY │ │ (does the work) │ │ │ └─────────┬───────────┘ │ ▼ Output (Return Value)

2. The Three Ways to Create a Function

2.1 — Function Declaration

The classic way. Uses the function keyword followed by a name.

function greet(name) {
    return `Hello, ${name}!`;
}

console.log(greet("Idris"));  // "Hello, Idris!"
Key trait: Hoisted Function declarations are fully hoisted. You can call them before the line where they are written in your code. The engine reads the entire function during the Creation Phase. 
// This works! Function declarations are hoisted.
sayHello();  // "Hello!"

function sayHello() {
    console.log("Hello!");
}

2.2 — Function Expression

A function stored inside a variable. The function itself has no name (anonymous) — the variable name is how you call it.

const greet = function(name) {
    return `Hello, ${name}!`;
};

console.log(greet("Idris"));  // "Hello, Idris!"
Key trait: NOT hoisted Function expressions are not hoisted. The variable is hoisted (into the TDZ if using const/let), but the function is not assigned until the engine reaches that line. 
// This CRASHES! Function expressions are NOT hoisted.
sayHello();  // ❌ TypeError: sayHello is not a function

const sayHello = function() {
    console.log("Hello!");
};

2.3 — Arrow Function (ES6)

The modern, shorter syntax introduced in ES6. This is what you are learning in your training right now.

// Standard arrow function with a body block:
const greet = (name) => {
    return `Hello, ${name}!`;
};

// Concise arrow function (implicit return — one expression only):
const greetShort = (name) => `Hello, ${name}!`;

// Single parameter — parentheses are optional:
const double = n => n * 2;

// No parameters — empty parentheses required:
const getRandom = () => Math.random();

// Multiple parameters — parentheses required:
const add = (a, b) => a + b;
When to use which? Arrow functions are the modern default for most situations. Use function declarations when you need hoisting or when defining methods on objects (because of this behavior — covered in Section 10). You will almost never need function expressions in modern code.

3. Parameters and Arguments

This distinction is simple but you must know it precisely:

  • Parameters = the placeholder variable names defined in the function signature. They are the labels on the machine's input slots.
  • Arguments = the actual concrete values you pass in when calling the function. They are the raw materials you feed into the machine.
//        parameters ↓
function add(a, b) {
    return a + b;
}

//    arguments ↓
add(5, 10);  // 15

3.1 — What Happens When Arguments Don't Match Parameters?

function test(a, b, c) {
    console.log(a, b, c);
}

// Fewer arguments than parameters → missing ones become undefined
test(1, 2);        // 1  2  undefined

// More arguments than parameters → extras are silently ignored
test(1, 2, 3, 4);  // 1  2  3  (4 is ignored)

3.2 — Default Parameters (ES6)

You can assign a fallback value that is used when no argument is provided (or when undefined is passed).

function createUser(name, role = "member", active = true) {
    return { name, role, active };
}

createUser("Idris");                    // { name: "Idris", role: "member", active: true }
createUser("Idris", "admin");            // { name: "Idris", role: "admin", active: true }
createUser("Idris", "admin", false);   // { name: "Idris", role: "admin", active: false }
Default parameters only trigger on undefined, not null createUser("Idris", undefined) → role is "member" (default kicks in).
createUser("Idris", null) → role is null (null is a deliberate value, not "missing").

3.3 — Rest Parameters (ES6)

The rest parameter ... gathers all remaining arguments into a real array. It must be the last parameter.

function sum(...numbers) {
    let total = 0;
    for (const n of numbers) {
        total += n;
    }
    return total;
}

sum(1, 2, 3);         // 6
sum(10, 20, 30, 40);  // 100

// Can combine with regular parameters:
function logAll(label, ...items) {
    console.log(label);  // "Shopping list:"
    console.log(items);  // ["milk", "bread", "eggs"]
}
logAll("Shopping list:", "milk", "bread", "eggs");

4. The return Statement

The return keyword does two things simultaneously:

  1. Sends a value back to the place where the function was called.
  2. Immediately stops the function — no code after return will execute.
function divide(a, b) {
    if (b === 0) {
        return "Cannot divide by zero";  // Exits here if b is 0
    }
    return a / b;  // Only reached if b is NOT 0
}

divide(10, 2);  // 5
divide(10, 0);  // "Cannot divide by zero"

4.1 — Functions Without return

If a function does not have a return statement, it automatically returns undefined.

function sayHi() {
    console.log("Hi!");
    // No return statement
}

let result = sayHi();
console.log(result);  // undefined

4.2 — Implicit Return (Arrow Functions Only)

Arrow functions have a shortcut: if you omit the curly braces {}, the single expression is automatically returned without writing return.

// With curly braces → explicit return required
const square = (n) => {
    return n * n;
};

// Without curly braces → implicit return (cleaner)
const squareShort = n => n * n;

// Both produce the same result:
square(5);       // 25
squareShort(5);  // 25
Common trap: Returning an object with implicit return If you want to implicitly return an object literal, you must wrap it in parentheses. Otherwise the engine confuses the {} with a function body block.

const getUser = () => ({ name: "Idris", age: 25 }); ← Correct
const getUser = () => { name: "Idris", age: 25 }; ← Broken (interpreted as a code block)

5. Scope: Where Variables Live and Die

Every function creates its own scope — an isolated environment where variables live. Variables declared inside a function cannot be accessed from outside. This is called encapsulation.

function calculate() {
    let secret = 42;  // Only exists inside this function
    console.log(secret);  // 42 ✅
}

calculate();
console.log(secret);  // ❌ ReferenceError: secret is not defined

5.1 — The Scope Chain (Lexical Scope)

When a function tries to use a variable, the engine searches for it in this order:

  1. Local scope — inside the current function.
  2. Outer function scope — the function that wraps the current one.
  3. Global scope — the top-level of your script.

This search path is called the Scope Chain. It always goes outward, never inward.

let globalVar = "I am global";

function outer() {
    let outerVar = "I am outer";

    function inner() {
        let innerVar = "I am inner";

        console.log(innerVar);   // ✅ Found in local scope
        console.log(outerVar);   // ✅ Found in outer scope (one level up)
        console.log(globalVar);  // ✅ Found in global scope (two levels up)
    }

    inner();
    console.log(innerVar);  // ❌ Error — outer cannot look INTO inner
}

outer();
The Scope Chain (one-way glass bubbles) ┌─────────────────────────────────────────────────┐ │ GLOBAL SCOPE │ │ globalVar = "I am global" │ │ │ │ ┌─────────────────────────────────────────┐ │ │ │ outer() SCOPE │ │ │ │ outerVar = "I am outer" │ │ │ │ │ │ │ │ ┌─────────────────────────────────┐ │ │ │ │ │ inner() SCOPE │ │ │ │ │ │ innerVar = "I am inner" │ │ │ │ │ │ │ │ │ │ │ │ Can see: innerVar ✅ │ │ │ │ │ │ Can see: outerVar ✅ (look up) │ │ │ │ │ │ Can see: globalVar ✅ (look up) │ │ │ │ │ └─────────────────────────────────┘ │ │ │ │ │ │ │ │ Can see: outerVar ✅ │ │ │ │ Can see: globalVar ✅ │ │ │ │ Can see: innerVar ❌ (cannot look down) │ │ │ └─────────────────────────────────────────┘ │ └─────────────────────────────────────────────────┘
Lexical means "written position" JavaScript uses lexical scoping — the scope is determined by where the function is written in the source code, NOT where it is called. This is a fixed, permanent relationship set at write-time.

6. Closures

A closure is what happens when a function remembers the variables from its outer scope, even after the outer function has finished executing and its execution context has been removed from the Call Stack.

This is arguably the most important concept in JavaScript. It is the secret to data privacy, factory functions, state management, and modern patterns.

function createCounter() {
    let count = 0;  // Stored in createCounter's activation record

    return function() {
        count++;          // Remembers and modifies count from outer scope
        return count;
    };
}

const counter = createCounter();  // createCounter() has finished executing!
counter();  // 1
counter();  // 2
Visual: Scope Allocation in Heap Memory 1. Call Stack: createCounter() runs, creates "count = 0". 2. createCounter() returns the inner function and leaves the stack. 3. BUT the returned function holds an invisible pointer [Scope] -> Heap: STACK MEMORY HEAP MEMORY ┌──────────────────────┐ ┌─────────────────────────────┐ │ counter variable │ ──Pointers────> │ Returned Function Object │ └──────────────────────┘ │ [[Scope]] ──Addr 0x2A─── │ └──────────────┬──────────────┘ │ ▼ ┌─────────────────────────────┐ │ Addr 0x2A: Scope Bubble │ │ count = 2 │ └─────────────────────────────┘ Because the function is alive, its birth-bubble scope in the Heap cannot be garbage-collected!

3 Production Closure Patterns

Study these three real-world developer patterns to see exactly how closures are used in professional projects:

Pattern 1: Private State / Data Encapsulation

If you want to prevent external scripts from maliciously altering important numbers (like bank balances or configurations), keep them private inside a closure bubble, exposing only safe accessor methods.

function createBankAccount(owner, initialBalance) {
    let balance = initialBalance; // Completely private variable!

    return {
        deposit(amount) {
            if (amount > 0) {
                balance += amount;
                console.log(`Deposited $${amount}. Balance: $${balance}`);
            }
        },
        withdraw(amount) {
            if (amount > balance) {
                console.log("Insufficient funds!");
            } else {
                balance -= amount;
                console.log(`Withdrew $${amount}. Balance: $${balance}`);
            }
        },
        getBalance() {
            return balance; // Safe reading access, no editing allowed!
        }
    };
}

const account = createBankAccount("Idris", 1000);
account.deposit(500);   // "Deposited $500. Balance: $1500"
account.balance = 999999; // ❌ Fails to alter the balance (not an object property!)
console.log(account.getBalance()); // 1500 ✅

Pattern 2: Factory Functions (Currying Custom Helpers)

We can write a general function that "stamps out" specialized child functions by enclosing a configuration parameter inside a closure bubble.

function createLogger(prefix) {
    return function(message) {
        console.log(`[${prefix.toUpperCase()}] ${message}`);
    };
}

const logError = createLogger("error");
const logDebug = createLogger("debug");

logError("Database connection failed!"); // "[ERROR] Database connection failed!"
logDebug("Cache checked.");              // "[DEBUG] Cache checked."

Pattern 3: Performance Caching (Memoization Decorator)

Closures can store a private cache object. Whenever the function is called, it checks the private cache before executing expensive calculations.

function memoizeHeavyCalculation() {
    const cache = {}; // Private memory table

    return function(num) {
        if (num in cache) {
            console.log("Pulled from cache memory! 🧠");
            return cache[num];
        }
        console.log("Running heavy mathematical calculations... ⚙️");
        const result = num * num * num; // pretend this is a heavy task
        cache[num] = result;
        return result;
    };
}

const calculate = memoizeHeavyCalculation();
calculate(10); // "Running heavy mathematical calculations... ⚙️" -> 1000
calculate(10); // "Pulled from cache memory! 🧠" -> 1000 ✅ (10x faster!)
Why closures are everywhere in modern systems Whenever you write an event listener, a setTimeout callback, or a React Hook like useState(), you are creating a closure! The callback remembers variables in the scope it was defined in, regardless of when it gets executed in the future.

6.1 — The Classic Closure Trap (Interviews Love This)

// ❌ THE BUG:
for (var i = 0; i < 3; i++) {
    setTimeout(function() {
        console.log(i);
    }, 1000);
}
// Expected: 0, 1, 2
// Actual:   3, 3, 3
// Why? 'var' is function-scoped, so there is only ONE 'i' variable.
// By the time the timeouts fire (1 second later), the loop has
// already finished and 'i' is 3. All three callbacks close over
// the same variable, which is now 3.

// ✅ THE FIX: Use 'let' (block-scoped → each iteration gets its own 'i')
for (let i = 0; i < 3; i++) {
    setTimeout(function() {
        console.log(i);
    }, 1000);
}
// Output: 0, 1, 2 ✅

7. Functions Are First-Class Citizens

In JavaScript, functions are values. They are objects. This means you can do anything with a function that you can do with any other value:

  • Store it in a variable.
  • Pass it as an argument to another function.
  • Return it from a function.
  • Store it in an array or object.

This is the foundation for callbacks, higher-order functions, and the entire modern JavaScript ecosystem.

// Stored in a variable:
const greet = () => "Hello!";

// Stored in an array:
const actions = [() => "run", () => "jump", () => "swim"];
actions[0]();  // "run"

// Stored in an object:
const math = {
    add: (a, b) => a + b,
    subtract: (a, b) => a - b
};
math.add(5, 3);  // 8

8. Callback Functions

A callback is a function that you pass as an argument to another function. The receiving function will "call it back" at the right time.

function processUserInput(callback) {
    const name = "Idris";
    callback(name);  // Call the function that was passed in
}

processUserInput(function(name) {
    console.log(`Welcome, ${name}!`);
});
// "Welcome, Idris!"

// Same thing with arrow syntax (cleaner):
processUserInput(name => console.log(`Welcome, ${name}!`));

Callbacks are everywhere in JavaScript:

// Event listeners use callbacks:
button.addEventListener("click", () => {
    console.log("Button was clicked!");
});

// setTimeout uses a callback:
setTimeout(() => {
    console.log("2 seconds have passed.");
}, 2000);

// Array methods use callbacks:
[1, 2, 3].forEach(num => console.log(num));
[1, 2, 3].map(num => num * 2);       // [2, 4, 6]
[1, 2, 3].filter(num => num > 1);     // [2, 3]

9. Higher-Order Functions

A higher-order function is any function that does at least one of these:

  1. Takes a function as an argument (receives a callback).
  2. Returns a function as its result.
// Takes a function as an argument:
function repeat(n, action) {
    for (let i = 0; i < n; i++) {
        action(i);
    }
}

repeat(3, i => console.log(`Iteration ${i}`));
// "Iteration 0", "Iteration 1", "Iteration 2"


// Returns a function:
function multiplier(factor) {
    return (number) => number * factor;  // Returns a new function
}

const double = multiplier(2);   // Creates a function that doubles
const triple = multiplier(3);   // Creates a function that triples

double(5);   // 10
triple(5);   // 15
This is the real power of functions Higher-order functions let you create abstract, reusable logic. Instead of writing separate double(), triple(), and quadruple() functions, you write one multiplier() that generates the specific function you need. This pattern is the foundation of functional programming.

10. The this Keyword

this is a special keyword that refers to the object that is currently executing the function. Its value depends on how the function is called, not where it is written.

10.1 — this in Regular Functions

const user = {
    name: "Idris",
    greet: function() {
        console.log(`Hello, I am ${this.name}`);
    }
};

user.greet();  // "Hello, I am Idris"
// 'this' refers to 'user' because 'user' is the object that called greet()

10.2 — this in Arrow Functions (The Critical Difference)

Arrow functions do NOT have their own this. They inherit this from their enclosing scope (lexical this).

const user = {
    name: "Idris",
    greet: () => {
        console.log(`Hello, I am ${this.name}`);
    }
};

user.greet();  // "Hello, I am undefined"
// Arrow function does NOT get 'user' as 'this'.
// It inherits 'this' from the surrounding scope (global/window),
// which has no 'name' property.

10.3 — When Arrow Functions ARE Useful for this

const timer = {
    seconds: 0,
    start: function() {
        // If we used a regular function here, 'this' would be
        // the global object (or undefined in strict mode), NOT 'timer'

        // Arrow function inherits 'this' from start(), which is 'timer' ✅
        setInterval(() => {
            this.seconds++;
            console.log(this.seconds);
        }, 1000);
    }
};

timer.start();  // 1, 2, 3, 4... ✅
Simple rules for this 1. Object method (regular function) → this = the object calling the method.
2. Arrow function → this = whatever this was in the surrounding scope.
3. Standalone function call → this = undefined (strict mode) or window (non-strict).
4. Event listener → this = the DOM element that triggered the event (if regular function).

Rule of thumb: Use regular functions for object methods. Use arrow functions for everything else.

11. Pure Functions vs Side Effects

A pure function has two rules:

  1. Given the same inputs, it always returns the same output.
  2. It does not modify anything outside itself (no side effects).
// ✅ Pure function — same input always produces same output, no side effects
function add(a, b) {
    return a + b;
}

// ❌ Impure function — modifies external state (side effect)
let total = 0;
function addToTotal(amount) {
    total += amount;  // Modifies a variable outside the function
    return total;
}

// ❌ Impure function — depends on external state
let taxRate = 0.2;
function calculateTax(price) {
    return price * taxRate;  // Uses a variable from outside — result changes if taxRate changes
}

Common side effects:

  • Modifying a global variable
  • Modifying the argument object (mutating an array/object passed in)
  • Writing to the console (console.log)
  • Modifying the DOM
  • Making network requests (fetch, API calls)
Why pure functions matter Pure functions are predictable, testable, and debuggable. Wherever possible, keep your functions pure. Isolate side effects to specific places in your code. This principle becomes critical in React, Redux, and any large-scale application.

12. IIFE (Immediately Invoked Function Expression)

An IIFE is a function that runs the instant it is defined. You will see this in legacy code and module patterns.

(function() {
    let private = "You cannot access me from outside";
    console.log(private);
})();
// "You cannot access me from outside"
// 'private' is scoped inside the IIFE — completely isolated

// Arrow function IIFE:
(() => {
    console.log("I also run immediately!");
})();

IIFEs were heavily used before ES6 modules to avoid polluting the global scope. Today, let/const and ES modules mostly replace the need for IIFEs, but you will still encounter them.

🔥 Challenge Katas

These are NOT simple exercises. These are tricky problems that test if you truly understand JavaScript. Predict the output, find the bug, and solve problems that require real thinking. No shortcuts — think first, then check.

Rules 1. Do NOT run the code first. Read it, trace it in your head, predict the output, THEN run it to verify.
2. Use the Hint if you're stuck — it points you in the right direction without giving the answer.
3. Use the Answer only after you've committed to your own answer.
4. If you get it wrong — good. That's where learning happens. Read the explanation carefully.

A. What's The Output? (Predict)

01 Predict Output

Hoisting Chaos

What does this print? Write down your answer BEFORE running it.

console.log(a);
console.log(b);
console.log(c);

var a = 1;
let b = 2;
const c = 3;
HintRemember how var, let, and const behave differently during the Creation Phase. One gets initialized to undefined, the other two are placed in the TDZ.
Answer 
console.log(a);  // undefined — var is hoisted and initialized to undefined
console.log(b);  // ❌ ReferenceError: Cannot access 'b' before initialization
// Line 3 never runs — the script crashes at line 2

var is hoisted + initialized to undefined. let and const are hoisted but in the Temporal Dead Zone — accessing them before declaration throws an error. The script stops at line 2 and line 3 never executes.

02 Predict Output

The Equality Nightmare

Predict true or false for each line:

console.log([] == []);
console.log([] == ![]);
console.log("" == false);
console.log("0" == false);
console.log(null == undefined);
console.log(null === undefined);
console.log(NaN === NaN);
Hint== does type coercion. Objects are compared by reference. ![] converts the array to a boolean first ([] is truthy, so ![] is false). NaN is the only value not equal to itself.
Answer 
[] == []            // false — two different objects in memory (different references)
[] == ![]           // true  — ![] is false, [] coerces to "", "" coerces to 0, false is 0. 0 == 0
"" == false         // true  — both coerce to 0
"0" == false        // true  — "0" coerces to 0, false is 0
null == undefined   // true  — special rule: they are loosely equal to each other and nothing else
null === undefined  // false — strict: different types (null vs undefined)
NaN === NaN         // false — NaN is NEVER equal to anything, including itself

This is why you always use ===. The == results above are almost impossible to predict without memorizing coercion tables.

03 Predict Output

Closure Trap

function createFunctions() {
    const result = [];
    for (var i = 0; i < 3; i++) {
        result.push(function() {
            return i;
        });
    }
    return result;
}

const fns = createFunctions();
console.log(fns[0]());
console.log(fns[1]());
console.log(fns[2]());
Hintvar is function-scoped, not block-scoped. All three closures share the same i variable. What is the value of i when the loop finishes?
Answer 
fns[0]()  // 3
fns[1]()  // 3
fns[2]()  // 3 — ALL return 3!

Because var i is function-scoped, there is one single i shared by all three closures. When the loop ends, i is 3. All three functions close over that same variable. Fix: replace var with let — each iteration gets its own block-scoped i.

04 Predict Output

this Gone Wrong

const user = {
    name: "Idris",
    greet: () => {
        return `Hello, ${this.name}`;
    },
    farewell() {
        return `Goodbye, ${this.name}`;
    }
};

console.log(user.greet());
console.log(user.farewell());

const fn = user.farewell;
console.log(fn());
HintArrow functions inherit this from the surrounding scope (the module/global). Regular methods get this from the object that calls them. When you extract a method into a standalone variable, what is calling it?
Answer 
user.greet()     // "Hello, undefined" — arrow function, this = global/module scope
user.farewell()  // "Goodbye, Idris" — regular method, this = user
fn()             // "Goodbye, undefined" — standalone call, this = global/undefined

Three different this traps in one exercise. The arrow function never gets user as this. The extracted method loses its this binding because it's no longer called as user.farewell().

05 Predict Output

Type Coercion Madness

Predict each result:

console.log("5" + 3);
console.log("5" - 3);
console.log("5" * "2");
console.log(true + true + true);
console.log(true + "1");
console.log([] + []);
console.log([] + {});
console.log({} + []);
HintThe + operator does string concatenation if either side is a string. For -, *, / it always converts to numbers. Arrays and objects are converted using .toString() first: [].toString() is "", {}.toString() is "[object Object]".
Answer 
"5" + 3             // "53" — string wins, concatenation
"5" - 3             // 2 — minus forces number conversion
"5" * "2"           // 10 — multiply forces number conversion
true + true + true  // 3 — true is 1 in numeric context: 1 + 1 + 1
true + "1"          // "true1" — string wins, true becomes "true"
[] + []             // "" — both become "", "" + "" = ""
[] + {}             // "[object Object]" — "" + "[object Object]"
{} + []             // 0 — {} is parsed as an empty block, then +[] is +""  which is 0
                    // (In the console it may show "[object Object]" — context-dependent)
06 Predict Output

Reference vs Value

let a = { x: 1 };
let b = a;
b.x = 99;
console.log(a.x);

let c = { x: 1 };
let d = c;
d = { x: 99 };
console.log(c.x);
Hintb.x = 99 mutates the object that both a and b point to. d = { x: 99 } creates a brand new object and points d to it — it does NOT mutate the original.
Answer 
a.x  // 99 — b mutated the shared object
c.x  // 1  — d was reassigned to a NEW object, c still points to the old one

Mutation (b.x = 99) changes the object in memory — affects all references. Reassignment (d = { }) makes the variable point to a new object — the old one is untouched.

07 Predict Output

Scope Chain Puzzle

let x = 10;

function outer() {
    let x = 20;

    function inner() {
        x++;
        console.log(x);
    }

    inner();
    console.log(x);
}

outer();
console.log(x);
Hintinner() modifies the x it finds through its scope chain. Which x is that — the one in outer or the global one? Does the global x change?
Answer 
// inner()  → 21  (x++ modifies outer's x from 20 to 21)
// outer()  → 21  (same outer x, now 21)
// global   → 10  (global x was never touched — inner found x in outer's scope first)
08 Predict Output

setTimeout Order

console.log("A");

setTimeout(() => console.log("B"), 0);

Promise.resolve().then(() => console.log("C"));

console.log("D");
HintJavaScript is single-threaded with an Event Loop. Synchronous code runs first. Then microtasks (Promises) run before macrotasks (setTimeout). Even setTimeout(..., 0) doesn't mean "immediately."
Answer 
// A — synchronous, runs first
// D — synchronous, runs second
// C — microtask (Promise), runs before macrotasks
// B — macrotask (setTimeout), runs last even with 0ms delay

The Event Loop processes: Call Stack (sync) → Microtask Queue (Promises) → Macrotask Queue (setTimeout, setInterval). setTimeout(fn, 0) doesn't mean "now" — it means "as soon as the queues allow."

B. Find The Bug (Debug)

09 Find the bug

The Filter That Returns Nothing

This code should return users older than 18, but it returns an empty array. Why? Fix it.

const users = [
    { name: "Alice", age: 25 },
    { name: "Bob", age: 17 },
    { name: "Charlie", age: 30 }
];

const adults = users.filter(user => {
    user.age > 18;
});

console.log(adults);  // [] ← WHY?
HintLook at the arrow function. It uses { } curly braces. What does that mean for the return value?
Answer

The arrow function has curly braces { } but no return statement. It implicitly returns undefined, which is falsy, so every element is filtered out.

// Fix 1: Add return
const adults = users.filter(user => {
    return user.age > 18;
});

// Fix 2: Remove curly braces (implicit return)
const adults = users.filter(user => user.age > 18);
10 Find the bug

The Broken Copy

The developer thought they made an independent copy. Why does the original change?

const original = {
    name: "Idris",
    scores: [90, 85, 92]
};

const copy = { ...original };
copy.name = "Changed";
copy.scores.push(100);

console.log(original.name);    // "Idris" ✅
console.log(original.scores);  // [90, 85, 92, 100] ← WHY?
HintSpread creates a shallow copy. Primitives (name) are duplicated. But what about the array inside?
Answer

Spread { ...obj } is a shallow copy. The scores array is an object — only the reference was copied, not the array itself. Both original.scores and copy.scores point to the same array.

// Fix: deep copy
const copy = structuredClone(original);

// Or manually spread nested values:
const copy = { ...original, scores: [...original.scores] };
11 Find the bug

The Sort Surprise

This sorts numbers. It looks correct. What's wrong?

const original = [3, 1, 4, 1, 5];
const sorted = original.sort((a, b) => a - b);

console.log(sorted);    // [1, 1, 3, 4, 5] ✅
console.log(original);  // ??? — What do you expect here?
console.log(sorted === original);  // ???
HintIs .sort() a mutating or non-mutating method?
Answer 
original  // [1, 1, 3, 4, 5] — MUTATED! sort() changes the original array
sorted === original  // true — they are the SAME array, same reference

.sort() is a mutating method. It sorts in place and returns the same array — not a new one. Fix: const sorted = [...original].sort((a,b) => a - b);

C. Algorithmic Katas (Build)

12 Build Think Hard

Digital Root

Write a function digitalRoot(n) that keeps summing the digits of a number until it becomes a single digit.

digitalRoot(493193);  // 4+9+3+1+9+3 = 29 → 2+9 = 11 → 1+1 = 2 → return 2
digitalRoot(0);       // 0
digitalRoot(99);      // 9
HintTwo approaches: 1) Convert number to string, split into digits, sum them, repeat while result >= 10. 2) There's a pure math formula: (n - 1) % 9 + 1 for n > 0.
Answer 
// Recursive approach:
function digitalRoot(n) {
    if (n < 10) return n;
    const sum = String(n).split("").reduce((acc, d) => acc + Number(d), 0);
    return digitalRoot(sum);
}

// Math shortcut:
const digitalRoot = n => n === 0 ? 0 : 1 + ((n - 1) % 9);
13 Build Think Hard

Longest Consecutive Sequence

Given an unsorted array of numbers, find the length of the longest consecutive sequence. Must run efficiently (don't just sort it).

longestConsecutive([100, 4, 200, 1, 3, 2]);  // 4 (sequence: 1,2,3,4)
longestConsecutive([0, 3, 7, 2, 5, 8, 4, 6, 1]);  // 9
HintPut all numbers in a Set for O(1) lookups. A sequence starts at a number that has no predecessor (n-1 not in the set). From that start, count consecutive numbers upward.
Answer 
function longestConsecutive(nums) {
    const numSet = new Set(nums);
    let longest = 0;

    for (const num of numSet) {
        // Only start counting if num is the START of a sequence
        if (!numSet.has(num - 1)) {
            let current = num;
            let streak = 1;

            while (numSet.has(current + 1)) {
                current++;
                streak++;
            }
            longest = Math.max(longest, streak);
        }
    }
    return longest;
}
14 Build Think Hard

Curry Any Function

Write a function curry(fn) that transforms a function so it can be called with one argument at a time.

function add(a, b, c) { return a + b + c; }

const curriedAdd = curry(add);

curriedAdd(1)(2)(3);     // 6
curriedAdd(1, 2)(3);    // 6
curriedAdd(1)(2, 3);    // 6
curriedAdd(1, 2, 3);   // 6
HintThe curried function needs to collect arguments until it has enough (>= fn.length). If not enough, return a new function that collects more. If enough, call the original function. Use recursion and the spread operator.
Answer 
function curry(fn) {
    return function curried(...args) {
        if (args.length >= fn.length) {
            return fn(...args);
        }
        return (...moreArgs) => curried(...args, ...moreArgs);
    };
}
15 Build Think Hard

Debounce

Write a function debounce(fn, delay) that returns a new function. That function, no matter how many times it's called, will only execute fn after delay milliseconds of silence (no further calls).

const log = debounce(() => console.log("Fired!"), 500);

log();  // starts 500ms timer
log();  // resets timer
log();  // resets timer — only this one fires after 500ms
HintUse setTimeout and clearTimeout. Store the timer ID in a closure. Each call clears the previous timer and starts a new one.
Answer 
function debounce(fn, delay) {
    let timeoutId;

    return function(...args) {
        clearTimeout(timeoutId);
        timeoutId = setTimeout(() => fn(...args), delay);
    };
}

This uses a closure to keep timeoutId private. Every call clears the previous timer and starts fresh. The function only fires when you stop calling it for delay ms. Used everywhere: search inputs, scroll handlers, resize listeners.

16 Build Think Hard

Pipe with Validation

Write a function pipe(value, ...fns) that passes a value through a series of functions left-to-right, but stops immediately if any function returns null or undefined.

const double = x => x * 2;
const addTen = x => x + 10;
const crash = x => null;
const triple = x => x * 3;

pipe(5, double, addTen);           // 20
pipe(5, double, crash, triple);     // null (stops at crash, triple never runs)
HintUse reduce. In each step, check if the accumulator is null or undefined before calling the next function.
Answer 
function pipe(value, ...fns) {
    return fns.reduce((acc, fn) => {
        if (acc === null || acc === undefined) return acc;
        return fn(acc);
    }, value);
}

// Or using nullish coalescing style:
const pipe = (value, ...fns) =>
    fns.reduce((acc, fn) => acc != null ? fn(acc) : acc, value);
17 Build Think Hard

Implement Array.prototype.reduce From Scratch

Write your own myReduce(arr, callback, initialValue) without using the built-in .reduce().

myReduce([1,2,3,4], (acc, curr) => acc + curr, 0);       // 10
myReduce([1,2,3,4], (acc, curr) => acc + curr);          // 10 (no initial → first element is initial)
myReduce([5,3,8,1], (acc, n) => n > acc ? n : acc, 0); // 8
HintIf no initial value is given, use arr[0] as the accumulator and start the loop at index 1. The callback receives (accumulator, currentElement, currentIndex, array).
Answer 
function myReduce(arr, callback, initialValue) {
    let acc = initialValue !== undefined ? initialValue : arr[0];
    let startIndex = initialValue !== undefined ? 0 : 1;

    for (let i = startIndex; i < arr.length; i++) {
        acc = callback(acc, arr[i], i, arr);
    }
    return acc;
}
18 Build Think Hard

Event Emitter

Build a mini event system. Create a class or factory function that supports on(event, callback), emit(event, ...data), and off(event, callback).

const emitter = createEmitter();

const onHello = name => console.log(`Hello, ${name}!`);

emitter.on("greet", onHello);
emitter.emit("greet", "Idris");  // "Hello, Idris!"
emitter.emit("greet", "Alice");  // "Hello, Alice!"
emitter.off("greet", onHello);
emitter.emit("greet", "Bob");    // (nothing — listener removed)
HintUse an object where each key is an event name and the value is an array of callback functions. on pushes to the array, emit calls every function in the array, off filters it out.
Answer 
function createEmitter() {
    const events = {};

    return {
        on(event, cb) {
            if (!events[event]) events[event] = [];
            events[event].push(cb);
        },
        off(event, cb) {
            if (!events[event]) return;
            events[event] = events[event].filter(fn => fn !== cb);
        },
        emit(event, ...args) {
            if (!events[event]) return;
            events[event].forEach(cb => cb(...args));
        }
    };
}

This combines closures (private events object), higher-order functions, rest parameters, spread, and array methods. It's a simplified version of Node.js EventEmitter and the browser's addEventListener.

03 — Conditionals & Logic

How to make your program think, decide, and take different paths. This is the brain of every application.

1. What Are Conditionals?

A conditional is a decision point in your code. The program evaluates a condition (an expression that resolves to true or false) and then executes different blocks of code depending on the result.

Without conditionals, your code would execute the same instructions every time, regardless of the situation. Conditionals give your program intelligence.

[ Start ] │ ▼ [ Is the condition true? ] │ │ YES NO │ │ ▼ ▼ [ Do this ] [ Do that ] │ │ └───────┬───────┘ ▼ [ Continue ]

2. Comparison Operators

Before we write conditions, we need the tools that produce true or false. These are the comparison operators:

OperatorMeaningExampleResult
===Strict equal (value AND type)5 === 5true
!==Strict not equal5 !== "5"true
>Greater than10 > 5true
<Less than3 < 7true
>=Greater than or equal5 >= 5true
<=Less than or equal4 <= 3false
Reminder from Lesson 02 Always use === and !== (strict). Never use == and != (loose) — they perform type coercion and produce unexpected results.

3. if, else if, else

This is the most fundamental conditional structure in all programming.

3.1 — if (Single Branch)

Execute a block of code only if the condition is true. If false, skip it entirely.

let temperature = 35;

if (temperature > 30) {
    console.log("It's hot outside!");
}
// This runs only when temperature is above 30

3.2 — if...else (Two Branches)

Do one thing if true, a different thing if false.

let age = 16;

if (age >= 18) {
    console.log("You can vote.");
} else {
    console.log("You cannot vote yet.");
}

3.3 — if...else if...else (Multiple Branches)

When you have more than two possible outcomes, chain else if blocks. The engine evaluates them top to bottom and stops at the first one that is true.

let score = 73;

if (score >= 90) {
    console.log("Grade: A");
} else if (score >= 80) {
    console.log("Grade: B");
} else if (score >= 70) {
    console.log("Grade: C");       // ← This one runs (73 >= 70 is true)
} else if (score >= 60) {
    console.log("Grade: D");       // ← Skipped even though 73 >= 60 is also true
} else {
    console.log("Grade: F");
}
Critical: Order matters The engine stops at the first true branch and ignores the rest. If you put the most general condition first (like score >= 60), it would catch everything and the more specific conditions below it would never run. Always order from most specific to least specific.

3.4 — Nested if Statements

You can put an if inside another if. This is called nesting.

let isLoggedIn = true;
let isAdmin = false;

if (isLoggedIn) {
    if (isAdmin) {
        console.log("Welcome, Admin!");
    } else {
        console.log("Welcome, User!");
    }
} else {
    console.log("Please log in.");
}
Avoid deep nesting Deeply nested if statements become hard to read quickly. Professional developers flatten them using guard clauses (covered in Section 8 of this lesson). As a rule, try to avoid going more than 2 levels deep.

4. Logical Operators

Logical operators let you combine multiple conditions into one expression. There are three:

OperatorNameMeaningExample
&&ANDBoth sides must be trueage > 18 && hasID
||ORAt least one side must be trueisAdmin || isModerator
!NOTFlips true to false, false to true!isLoggedIn

4.1 — AND (&&)

Returns true only if both conditions are true.

let age = 25;
let hasLicense = true;

if (age >= 18 && hasLicense) {
    console.log("You can drive.");
}

// Truth table for AND:
// true  && true  → true
// true  && false → false
// false && true  → false
// false && false → false

4.2 — OR (||)

Returns true if at least one condition is true.

let isAdmin = false;
let isModerator = true;

if (isAdmin || isModerator) {
    console.log("You have elevated permissions.");
}

// Truth table for OR:
// true  || true  → true
// true  || false → true
// false || true  → true
// false || false → false

4.3 — NOT (!)

Flips a boolean to its opposite.

let isOnline = false;

if (!isOnline) {
    console.log("User is offline.");  // This runs — !false is true
}

// Double NOT (!!) converts any value to its boolean equivalent:
!!"hello";   // true  (non-empty string is truthy)
!!0;         // false (0 is falsy)
!!null;      // false
!![];        // true  (empty array is truthy — remember from Lesson 02)

4.4 — Combining Operators (Operator Precedence)

When you mix && and || in the same expression, && has higher precedence — it is evaluated first, just like multiplication before addition in math.

let a = true, b = false, c = true;

// This:
a || b && c;
// Is evaluated as:
a || (b && c);    // true || (false && true) → true || false → true

// NOT as:
(a || b) && c;    // (true || false) && true → true && true → true

// To avoid confusion, ALWAYS use parentheses to make your intent explicit:
if ((age >= 18 && hasID) || isVIP) { ... }
Pro rule When in doubt, add parentheses ( ). They cost nothing and make your code crystal clear to anyone reading it.

5. Short-Circuit Evaluation

This is an advanced but essential concept. The logical operators && and || do not just return true or false — they return the actual value that determined the outcome, and they stop evaluating as soon as the result is known.

5.1 — || Short-Circuit (Returns the First Truthy Value)

The || operator evaluates left to right. It returns the first truthy value it finds, or the last value if none are truthy.

let username = "";
let displayName = username || "Anonymous";
// "" is falsy, so || moves to the right side
// displayName = "Anonymous"

let username2 = "Idris";
let displayName2 = username2 || "Anonymous";
// "Idris" is truthy, so || stops immediately
// displayName2 = "Idris"

This is a very common pattern for providing default values.

5.2 — && Short-Circuit (Returns the First Falsy Value)

The && operator returns the first falsy value it finds, or the last value if all are truthy.

let user = { name: "Idris" };
let greeting = user && user.name && `Hello, ${user.name}`;
// user is truthy → continue
// user.name is truthy → continue
// returns "Hello, Idris"

let noUser = null;
let greeting2 = noUser && noUser.name;
// null is falsy → stops immediately, returns null
// noUser.name is NEVER accessed (no error!)
Watch out with || and the value 0 Because 0 is falsy, using || for defaults can cause bugs when 0 is a valid value:

let count = 0; let result = count || 10; → result is 10, not 0!

This is why ?? (Nullish Coalescing) was invented — see Section 7.

6. The Ternary Operator

The ternary operator is a one-line shorthand for a simple if...else. It is the only operator in JavaScript that takes three operands.

// Syntax: condition ? valueIfTrue : valueIfFalse

let age = 20;
let status = age >= 18 ? "Adult" : "Minor";
console.log(status);  // "Adult"

This is equivalent to:

let status;
if (age >= 18) {
    status = "Adult";
} else {
    status = "Minor";
}

You can nest ternaries (but be careful):

let score = 85;
let grade = score >= 90 ? "A"
          : score >= 80 ? "B"
          : score >= 70 ? "C"
          : "F";

console.log(grade);  // "B"
When to use the ternary Use it for simple, single-value assignments. If the logic involves multiple statements, side effects, or complex conditions, use a regular if...else — readability matters more than brevity.

7. Nullish Coalescing (??) and Optional Chaining (?.)

These two ES2020 operators solve real problems that || and && could not handle cleanly.

7.1 — Nullish Coalescing (??)

The ?? operator returns the right-hand value only if the left-hand value is null or undefined. It does NOT treat 0, "", or false as "missing."

// Problem with ||:
let count = 0;
let result = count || 10;   // 10 ← WRONG! 0 is a valid count

// Solution with ??:
let result2 = count ?? 10;  // 0 ← CORRECT! 0 is not null/undefined

// Only null and undefined trigger the fallback:
null ?? "default";       // "default"
undefined ?? "default";  // "default"
0 ?? "default";           // 0
"" ?? "default";          // ""
false ?? "default";      // false

7.2 — Optional Chaining (?.)

When accessing properties on an object that might be null or undefined, you would normally crash with a TypeError. Optional chaining safely returns undefined instead of throwing an error.

let user = {
    name: "Idris",
    address: {
        city: "Paris"
    }
};

// Safe access — works fine:
user?.address?.city;       // "Paris"

// Safe access — property doesn't exist:
user?.phone?.number;       // undefined (no crash!)

// Without optional chaining, this would crash:
// user.phone.number → TypeError: Cannot read properties of undefined

// Works with methods too:
user.greet?.();            // undefined (greet doesn't exist, but no error)

// Works with arrays:
let arr = null;
arr?.[0];                  // undefined (no crash)
Combine them for maximum safety let city = user?.address?.city ?? "Unknown";
This safely accesses the nested property and provides a fallback if any part of the chain is missing.

8. The switch Statement

When you are comparing one variable against many specific values, a switch is cleaner than a long chain of else if.

let day = "Monday";

switch (day) {
    case "Monday":
        console.log("Start of the work week.");
        break;
    case "Friday":
        console.log("Almost weekend!");
        break;
    case "Saturday":
    case "Sunday":
        console.log("Weekend!");   // ← Multiple cases can share one block
        break;
    default:
        console.log("Regular day.");
}
Never forget the break! Without break, the engine will fall through and execute every case below the matched one, regardless of whether they match. This is one of the most common bugs in JavaScript. 
// FALL-THROUGH BUG:
let fruit = "apple";

switch (fruit) {
    case "apple":
        console.log("Apple!");   // ← This runs
        // NO BREAK HERE!
    case "banana":
        console.log("Banana!");  // ← This ALSO runs (fall-through!)
        break;
    default:
        console.log("Other");
}
// Output: "Apple!" and "Banana!" — almost certainly a bug

When to use switch vs if...else:

  • Use switch when comparing one value against multiple exact matches.
  • Use if...else when conditions involve ranges, complex logic, or different variables.

9. Guard Clauses (Early Returns)

A guard clause is a pattern where you handle the "wrong" or "edge" cases first and return early, so the main logic of your function stays flat and readable instead of being deeply nested.

Without guard clauses (deeply nested — hard to read):

function processOrder(user, item) {
    if (user) {
        if (user.isVerified) {
            if (item.inStock) {
                if (user.balance >= item.price) {
                    // Finally, the actual logic buried 4 levels deep!
                    console.log("Order placed!");
                }
            }
        }
    }
}

With guard clauses (flat and clean — professional standard):

function processOrder(user, item) {
    if (!user) return "No user provided.";
    if (!user.isVerified) return "User is not verified.";
    if (!item.inStock) return "Item is out of stock.";
    if (user.balance < item.price) return "Insufficient balance.";

    // Main logic — clean and clear, no nesting
    console.log("Order placed!");
}
This is how professionals write code Guard clauses eliminate "pyramid of doom" nesting. They make your code scannable — any reader can immediately see all the failure conditions at the top, and the happy path at the bottom. Adopt this pattern from day one.

01

Mobile-First Philosophy

Tailwind is mobile-first. A class with no prefix applies to all screen sizes starting from 0px. A prefixed class (e.g. lg:flex-row) kicks in at that breakpoint and above. You build the mobile layout first, then layer on overrides for larger screens.

💡 The Golden Rule

No prefix = all screens (0px+)

flex-col

Column layout from 0px all the way up to infinity — unless overridden.

Prefix = that width and UP

lg:flex-row

Row layout from 1024px upward. Below that, still column.

Raw CSS 
/* Mobile base */
.hero {
  display: flex;
  flex-direction: column;
  font-size: 1.25rem;
  padding: 1rem;
}

/* ≥ 1024px */
@media (min-width: 1024px) {
  .hero {
    flex-direction: row;
    font-size: 3rem;
    padding: 4rem;
  }
}
Tailwind Equivalent ✓ 
<!-- One element, no CSS file needed -->

<div class="
  flex flex-col          ← mobile
  text-xl                ← mobile
  p-4                    ← mobile

  lg:flex-row            ← ≥1024px
  lg:text-5xl            ← ≥1024px
  lg:p-16                ← ≥1024px
">
  ...content...
</div>

The 5 Breakpoints

Tailwind ships with 5 named breakpoints (plus 2xl). Each maps to a min-width media query. You layer classes from smallest to largest — no max-width queries needed.

Breakpoint Reference Table
Prefix Min-Width CSS @media equivalent Typical Device Example Usage
(none) 0px Always applies (no @media) 📱 Small phones flex flex-col
sm: 640px @media (min-width: 640px) 📱 Large phones / phablets sm:grid-cols-2
md: 768px @media (min-width: 768px) 📟 Tablets (iPad portrait) md:px-8 md:text-2xl
lg: 1024px @media (min-width: 1024px) 💻 Laptops / iPad landscape lg:flex-row lg:block
xl: 1280px @media (min-width: 1280px) 🖥️ Desktop monitors xl:max-w-7xl xl:px-16
2xl: 1536px @media (min-width: 1536px) 🖥️ Large / ultrawide displays 2xl:grid-cols-6

Note: breakpoints are min-width — each one activates and stays active for all larger sizes too.

Raw CSS equivalent 
.hero {
  display: flex;
  flex-direction: column; /* mobile */
  align-items: center;

@media (min-width: 1024px) {
  .hero {

  <!-- Image side -->

Responsive Spacing & Sizing

Padding, margins, and widths all take breakpoint prefixes. Use small padding on mobile (tight space), larger padding on wider screens for breathing room. Width classes control fluid vs fixed sizing.

Live Demo — Growing Padding Container

This container has responsive horizontal padding

px-4 on mobile → md:px-8 → lg:px-16

Equivalent to: padding-left/right grows from 1rem → 2rem → 4rem

Watch the inner content shift inward as screen gets wider

px-4 md:px-8 lg:px-16 → 16px → 32px → 64px horizontal padding

Common Responsive Padding Patterns

px-4 md:px-6 lg:px-8

Section horizontal padding (1rem→1.5rem→2rem)

py-8 md:py-12 lg:py-20

Section vertical padding (2rem→3rem→5rem)

p-4 lg:p-8

Card padding (1rem→2rem)

gap-4 lg:gap-8

Grid/Flex gap grows on desktop

Common Responsive Width Patterns

w-full lg:w-1/2

Full width mobile → half width desktop

w-full sm:w-auto

Full on mobile → shrink-to-fit on sm+

max-w-sm md:max-w-2xl lg:max-w-7xl

Max-width grows with screen

h-48 md:h-64 lg:h-96

Height: 192px → 256px → 384px

Spacing: Tailwind vs Raw CSS 
/* Raw CSS */
.section {
  padding: 2rem 1rem; /* py-8 px-4 */
}
@media (min-width: 768px) {
  .section {
    padding: 3rem 2rem; /* md:py-12 md:px-8 */
  }
}
@media (min-width: 1024px) {
  .section {
    padding: 5rem 4rem; /* lg:py-20 lg:px-16 */
  }
}
<!-- Tailwind -->

<section
  class="
    py-8 px-4
    md:py-12 md:px-8
    lg:py-20 lg:px-16
  "
>
  ...content...
</section>


No separate CSS file.
No class names to invent.
No @media rules to write.

Responsive Visibility

Show or hide elements depending on screen size. This is how navbars work — hamburger icon on mobile, full link list on desktop. The key utility is hidden combined with display utilities.

Visibility Patterns Reference
Tailwind Class Raw CSS Equivalent Result
hidden lg:block display:none → @media lg: display:block Hidden on mobile, visible on lg+
block lg:hidden display:block → @media lg: display:none Visible on mobile, hidden on lg+
hidden lg:flex display:none → @media lg: display:flex Flex container hidden until lg
flex lg:hidden display:flex → @media lg: display:none Flex visible on mobile, gone on lg
hidden sm:hidden md:block none → none → @media md: block Only visible on tablet (md) and up

Responsive Grid

CSS Grid + Tailwind breakpoint prefixes = the most powerful responsive layout tool. Start with 1 column on mobile, grow to 4+ on desktop. Used everywhere on LUGX for game card galleries.

Grid Column Patterns

Common Patterns

grid-cols-1 sm:grid-cols-2 lg:grid-cols-4

1 → 2 → 4 (Game cards, feature icons)

grid-cols-1 md:grid-cols-2 lg:grid-cols-3

1 → 2 → 3 (Blog cards, team members)

grid-cols-2 lg:grid-cols-6

2 → 6 (Small icon grids, tags)

grid-cols-1 lg:grid-cols-2 gap-4 lg:gap-8

Responsive columns AND gap

Raw CSS Equivalent

.game-grid {
  display: grid;
  grid-template-columns:
    1fr; /* mobile: 1 col */
  gap: 1rem;
}
@media (min-width: 640px) {
  .game-grid {
    grid-template-columns:
      repeat(2, 1fr); /* sm: 2 cols */
  }
}
@media (min-width: 1024px) {
  .game-grid {
    grid-template-columns:
      repeat(4, 1fr); /* lg: 4 cols */
  }
}

08

Responsive Images

Control image size, height, and visibility responsively. Use object-cover to fill a container without distortion, and responsive height utilities to make hero images taller on desktop.

Responsive Image Classes

w-full lg:w-1/2

Full width on mobile, half on desktop

width: 100% → 50%

h-48 md:h-64 lg:h-96

Height: 192px → 256px → 384px

object-cover

object-fit: cover (fills container, no squish)

object-center object-top

object-position: center / top

hidden lg:block

Decorative images only on desktop

Raw CSS Equivalent

img {
  width: 100%;
  height: 12rem; /* h-48 */
  object-fit: cover;
  object-position: center;
}
@media (min-width: 768px) {
  img {
    height: 16rem; /* md:h-64 */
  }
}
@media (min-width: 1024px) {
  img {
    width: 50%; /* lg:w-1/2 */
    height: 24rem; /* lg:h-96 */
  }
}

10

Common Mistakes & Quick Reference

Before you build: bookmark these mistakes every beginner makes, then use the cheat sheet while coding.

✗

Thinking Mobile-Last

❌ Wrong thinking:
"I'll add sm: to make it work on mobile"
✓ Right thinking:
"No prefix = mobile. I add lg: to override for desktop"

Tailwind is min-width based. Start mobile, override upward.

✗

Using Max-Width Breakpoints

❌ Trying to do this:
@media (max-width: 768px) { ... }
✓ Tailwind way:
flex-col md:flex-row

Column by default, row at md+. No max-width needed.

✗

Forgetting to hide the hamburger on desktop

❌ Bug:
<button>☰</button>

Hamburger shows on all screens!

✓ Fix:
<button class="lg:hidden">☰</button>
✗

Using hidden without restoring display type

❌ Bug:
hidden lg:block ← but it was flex before!

Using lg:block on a flex container breaks layout

✓ Fix — match the display type:
hidden lg:flex

Restore to flex, not block, if container uses flexbox

✗

Not testing at real breakpoints

Always test at exactly 639px, 640px, 767px, 768px, 1023px, 1024px — right at the boundary.

✓ Use browser DevTools:
F12 → Toggle device toolbar → set exact width
✗

Skipping breakpoints (sm before lg)

❌ Bug:
grid-cols-1 lg:grid-cols-4

Jumps straight from 1→4, awkward at sm/md

✓ Better:
grid-cols-1 sm:grid-cols-2 lg:grid-cols-4
